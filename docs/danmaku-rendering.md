# 弹幕渲染与横竖屏设置

Bilibili XML 弹幕先通过 `BilibiliDanmakuAss` 转成 1920×1080 参考画布的 ASS，滚动弹幕通常持续 8 秒，顶部/底部固定弹幕通常持续 4 秒。转换时有基于文本长度估算的轨道分配；它只适用于导出时的参考尺寸。

播放器的滚动弹幕在 1.0× 下统一以每媒体秒 60 个逻辑像素移动，横竖屏、长短句同速。存活时间为（可显示宽度 + 实测文字宽度）÷ 移动速度；屏幕更宽、句子更长时自然更晚退场。已下载的 ASS 同样生效；固定弹幕保留原时长规则。视频倍速及锁定倍速补偿沿用现有设置。

播放时 `DanmakuOverlay` 在后台解析 ASS，并缓存最近的文档。字体经过实际测量、预绘制后上传到图集，由 `CustomPainter` 按共享的播放位置时钟绘制；每帧更新横向位置，无须重建整棵界面。暂停、跳转和倍速沿用播放器时钟；“以锁定倍速为弹幕速度基准”开启时会抵消已锁定的播放倍速。

旧实现沿用 ASS 的纵向轨道，按当前字号重映射轨道高度，但没有在播放时检查实际字宽和整个运动过程；调整字号、速度或换到手机屏幕后，可能出现同轨追尾，以及固定弹幕与滚动弹幕相撞。原有的 640/320/200 条活动弹幕上限用于性能保护，无法替代阅读密度控制。

## 密度和防重叠

- 密度可以在 10%–100% 间调整，横竖屏分别保存。它对文件内的弹幕作确定性抽样；相同设置不会因为帧率、预加载批次或跳转改变抽样结果。抽样发生在活动数量限制和图集预加载前。
- 滚动、顶部、底部各自使用独立的轨道组，允许不同类型互相叠加。描边、阴影和相邻行少量文字边缘重叠不再互相排斥；只有同类型、文字主体占据同一行时才检查横向拥挤。
- 只检查当前及之后约 0.5 秒媒体时间的拥挤，不再因为数秒之后可能追尾而提前删掉整条弹幕。这是入场防挤策略，不承诺播放全程零重叠。
- 将 ASS 的源轨道重新分配到当前显示区域的可用行，源轨道较低不会再被直接裁掉。优先使用映射后的轨道，拥挤时在入场尝试其他空闲行；入场后轨道固定，不会因图集上传而跳行，也不延迟发送。
- 同类型的所有可用行均拥挤时才跳过弹幕，直到本次过期都不会在中途补入。跳转或主动改变布局参数时重新计算。
- 100% 表示不额外抽样，仍保留上述同类型短时防挤和性能保护。下载转 ASS 时已被过滤掉的弹幕不会凭空恢复；源文件不会被密度设置修改。

## 两套播放页参数

播放页显式选择配置，不根据视频宽高比或临时窗口方向猜测。打开弹幕设置时默认选中当前播放页，也可以通过“竖屏播放页 / 横屏播放页”切换调整。

| 参数 | 竖屏默认 | 横屏行为 |
| --- | --- | --- |
| 字号 | 100%；按逻辑屏幕短边温和适配，普通手机约 14–16 逻辑像素，较大设备最高 20 | 保留历史字号及推荐字号开关 |
| 显示区域 | 弹幕画布上方 25% | 保留历史设置 |
| 滚动速度 | 新默认 1.0×，每秒 60 逻辑像素 | 新默认同为 1.0×；两套已保存倍率继续保留 |
| 密度 | 50% | 100% |

竖屏字号不随视频区域高度、侧栏或设备像素比改变。滚动速度不随画布宽度改变，窄画布更早退场，宽画布更晚退场。显示区域百分比相对于弹幕实际画布；启用“弹幕仅在视频区域内展示”后，画布为视频区域。

不透明度、视频区域限制、倍速基准、自动更新以及字体/字重/描边等外观设置仍共用。新默认字体为思源黑体（`Noto Sans SC`），字重 700；已明确保存的字体和字重继续保留。“恢复弹幕默认设置”重置两套参数及共用外观。

历史 `bilibiliDanmakuDisplayArea/FontScale/Speed` 键继续作为横屏配置使用，升级不会覆盖已有手动值；新增 `bilibiliDanmakuPortrait*` 键保存竖屏配置。配置均通过现有设置注册、持久化和导出流程管理。

## 验证

`flutter test --no-pub test/danmaku_density_collision_test.dart test/danmaku_collision_overlay_test.dart test/danmaku_presentation_profiles_test.dart test/danmaku_settings_dialog_test.dart test/danmaku_settings_responsive_test.dart` 覆盖密度抽样、不同类型允许叠加、同类型入场防挤、真实思源黑体绘制、暂停时改参数、跳转、设置兼容和小屏布局。实际绘制测试包含 320/390/430 逻辑像素宽手机，在上方 25% 区域以 100% 密度播放连续弹幕，验证较低源轨道可重排、各可用行得到利用，以及可见弹幕数量不会退化为零星几条。原有渲染缓存、活动集和帧率测试继续适用。Flutter 测试不等价于 Android/iOS 真机帧率或视觉验收。
