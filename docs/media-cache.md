# 统一媒体缓存

入口为媒体库的「缓存管理」（桌面快捷键 M）。旧批量媒体/字幕导入页面及服务仍保留，但不再从媒体库展示。入口只显示正在解析、传输、保存或合并的任务数，使用蓝灰数字；排队、重试、等待、暂停和失败不计入。

## 操作

- B 站、百度和夸克媒体的菜单可快速缓存；已缓存媒体可继续选择其他画质或删除所有缓存。下载不会新增媒体卡片。
- 选中模式底栏提供「缓存」及紧邻的设置。默认跳过已有缓存和已入队媒体；全为已缓存媒体时变为「删除所有缓存」。
- 文件夹和网盘目录先递归预览，完整读取分页、过滤非媒体并去重，确认后入队。目录失败会显示错误并允许重读，不会默默下载不完整的选择。
- 播放器画质列表的下载/删除按钮独立于画质切换。允许播放一个画质、同时缓存另一个画质。任务页管理暂停、续传、重试和取消，已缓存按媒体汇总各版本。
- 三个来源分别设置批量画质上限，B 站默认最高可用，百度与夸克默认优先原画。原画被来源明确拒绝时才选择最高完整转码，网络、登录和限流错误保留恢复状态。音频保留原音质。手动指定画质不受批量上限约束。原画或更高分辨率完整发布后默认清理同修订的低画质受管版本；可关闭。

## 卡片与单个媒体的缓存窗口

卡片底部蓝条仅表示正在解析、下载、合并或保存的任务。排队、暂停、等待、失败和完成均不显示；同一媒体有多个任务时，仅汇总实际运行任务的进度。

已缓存由完整、可用、未标记删除的本地版本决定，与任务完成历史无关。封面使用黑白灰下载完成徽标，图标、底板、圆角及间距按封面短边缩放。选择模式在网格中把徽标移到另一侧，避开勾选框。删除最后一个版本、存储清理、文件丢失或存储不可用时撤掉徽标；有租约而延后删除的版本也不再显示为可用缓存。

可见卡片及打开的窗口共享目录监听，外部文件变动触发去抖后的元数据核对；进入页面、返回前台及定期维护提供补充检查。只核对文件类型、存在性及长度，不恢复已取消的整文件摘要/试播。目录暂时不可用时保留索引，恢复后重新核对。

卡片菜单「管理缓存」和缓存徽标打开当前媒体的画质窗口，主导航「缓存管理」仍打开全局任务页。窗口合并本地版本、当前任务和在线画质，支持单画质下载/删除、暂停、继续、重试、取消及删除此媒体全部缓存；操作不切换播放画质。在线列表失败时本地缓存仍可管理。

窗口最大宽度 560、最大内容高度 620 逻辑像素，根据实际可用空间缩小；列表滚动，大字体下操作换行。复用 mini 播放卡片尺寸及底部安全区计算，显隐动态更新；极短横屏允许整个窗口内容滚动。

2026-10-22 本次卡片与单媒体窗口更新的 261 项相关回归测试通过，Windows 调试程序及 Android 调试 APK 构建通过。布局测试覆盖 320×640、640×320、768×1024、1440×900、双倍字体和 mini 播放卡片显隐；另覆盖外部删文件、临时掉盘、租约延迟删除、单媒体操作隔离及离线画质管理。布局测试和构建不替代各平台真机验收。

## 功能下载与缓存复用

### B 站下载视频与在线卡片

B 站下载页产生并导入媒体库的视频统一使用在线来源卡片，下载文件登记为该分 P 的完整画质缓存。旧卡片在启动时先保存缓存索引，再原地转换来源；保留卡片 ID、文件夹位置、排序时间、观看记录、字幕、弹幕和下载任务关联，原文件留在原处。同源已有卡片全部保留并共享 `BV + cid` 缓存；站内入口继续复用卡片，下载页和在线解析列表的显式导入继续创建独立卡片。

完整缓存沿用播放器的本地优先路径，在线画质异步补充；可播放一个画质并缓存另一个画质。缓存菜单、徽标和选择底栏沿用已有行为。下载封存时保存实际流画质，后续选择其他画质或删除下载任务不会丢失这份信息。旧文件缺少可靠画质记录时显示「已有离线版本」。同画质的多份文件逐份登记，画质窗口仍按一个档位汇总；删除缓存保留在线卡片，使用中的文件等待租约释放后删除。

ZIP 可导出已有完整 B 站缓存；FluentPack 带上按现有缓存排序选择的一份完整版本及画质信息，导入后恢复在线卡片与缓存，带缓存的包使用格式版本 5。纯在线卡片保留来源引用，设备同步的媒体规则见下文。导出不主动下载媒体，也不把单独视频轨或音轨当作完整文件。

手动 FluentPack 导出区分下载来源：卡片的 `bilibiliDownloadPath` 指向下载页导入成品，它作为本地内容始终打包；旧版直接使用本地路径的下载卡片也保留此规则。其他在线卡片的完整缓存受「携带哔哩哔哩在线缓存」开关控制，默认开启并记住选择。关闭时在线卡片仍保留来源和选中的字幕、弹幕等附件，但不携带可选媒体缓存。共享同源缓存不会把另一张在线卡片变成下载页卡片；不能仅根据缓存的 `managed` 或 `assetId` 推断下载来源。导出不检查原链接是否仍有效，已有本地副本不会因来源失效而被丢弃。ZIP 始终导出实际媒体；此开关不控制设备同步。

设备同步不携带哔哩哔哩主动缓存；网盘必须已有完整文件才迁移，并在接收端恢复为永久离线媒体。发送所用缓存持有租约，手动删除等待任务释放文件。与其他本地媒体共享相同字节时，网盘离线副本使用独立私有文件，删除该网盘缓存不会删除原本地媒体；额外本地复制前按实际大小检查预留空间。

手动导出网盘媒体时，FluentPack 与 ZIP 都要求完整的本地文件或当前修订的完整缓存；未缓存时提示选择实际可用画质，下载完成后再继续。FluentPack 中网盘缓存使用格式版本 6，导回后登记为接收设备的完整缓存，保留来源与画质，不需要借用原设备路径播放。导出持有缓存租约，跳过单独轨道、失效和待删除版本。多画质只选择一份完整版本；FluentPack 优先关联的 B 站原下载，其余按原画和最高画质排序。播客在手动导出中仅保存卡片与链接，原文件夹同步的下载选择规则保留。

精确框选、OCR、转写和合成下载的原始轨道或完整来源文件，在文件封存后立即登记到同一缓存索引，保留原来的来源、画质、编码和修订，不需要等识别开始。进入卡片或再次播放时也会发现旧素材；登记只读取元数据，不复制大文件或新增整文件校验。OCR 图片、提取后重采样的音频和其他衍生结果不冒充原媒体。

B 站只有视频轨时，原来的 1080P 档位显示「视频轨已缓存」，正常播放网关直接读取相同编码的视频轨，缺少的音轨继续在线获取；不会新增「本地 1080P」档位，也不会在 OCR 开始或合并完成时突然重建播放器。完整缓存会把现有轨道接入断点下载流程，只补齐缺失部分。独立音轨可以供转写和后续完整缓存复用，但不能满足 OCR 或完整离线播放。

百度、夸克的素材文件按实际画质、远端身份及文件修订登记，完整原文件可直接离线复用；渐进式播放的后续相同资源请求也可以读取它。视频播客沿用自己的下载与分片存储，准备好的完整原视频就地登记，保留原文件路径和现有离线状态。完整文件与单独轨道均能在缓存窗口删除，使用中的文件受原功能和统一租约保护；删除后同步各自的索引与存储统计。

完成徽标仍只表示完整可用的媒体缓存。只有视频轨或音轨时，在对应画质行明确显示轨道状态及补齐入口，避免把缺音轨的文件标为完整离线视频。

## 文件与恢复

`MediaCacheService` 是任务与版本索引的唯一所有者。媒体身份为 `bvid + cid` 或已有网盘来源键；版本包括来源修订、画质与编码。`media_cache.json`、`.bak`、`.next` 通过现有原子存储写入。重启核对文件，手动暂停保持暂停，系统中断任务恢复入队。

成品位于 `AppStorageService.downloadFiles`，任务工作目录位于 `downloadTasks/.../cache_<任务 ID>`。B 站沿用既有自定义下载路径；目标不可用时保留任务等待恢复。分片、HTTP 校验信息、HLS 检查点、发布回执、iOS 续传数据均留在受管目录。迁移前停止写入、保存断点，迁移后按路径引用恢复。

URLSession 自行分配的系统暂存文件按后台传输保护并计入扫描；完成回调将下载结果移入受管任务目录。

HTTP 续传核对 Range、长度、资源版本与 ETag；签名失效重新解析。不支持 Range 时回退。HLS 按完整分段续传，主动缓存要求结束的播放列表。B 站试看、网盘不完整来源不会标记完成。按用户选择，主动缓存不再做下载后的整文件摘要、媒体探测或试播，必要合并完成后直接发布并登记索引；发布中断按回执和文件大小恢复暂存成品。网络分段与基本文件大小检查仍保留。

百度缓存会读取播放列表声明的 `backhost`，优先普通 CDN 并轮换失败节点，后续分片继承备用节点；不更改软件网络策略。备用 URL 沿用原签名，Cookies 按目标域名筛选，分片缓存仍记录原始播放资源身份。独立 MP4 分片通过本地 concat 合并时间轴，避免字节拼接只保留首段索引。合并与保存显示独立状态并保留已下载量。

默认 2 个任务、每任务最多 4 连接、全局 8 连接，设置位于网络设置。播放请求优先获得可用连接。播放网关优先读取相同版本已有分片，并校验后拼接所缺网络范围，避免把局部缓存当作整段响应。缓存暂停/取消不会取消播放请求。成品租约用于播放、转写、OCR 和合成，删除等待使用结束。

### B 站持续低速恢复与诊断

每条传输连接先预热 5 秒，再按 12 秒窗口观察新传输字节。平均低于 512 KiB/s、确认可用 Range 续传且剩余超过 1 MiB 时，保留分片和已下载字节，尝试备用地址。每个分片或单连接传输最多主动换源两次，不重复放弃已知慢地址；只有一个地址时只重连一次。备用地址也慢时继续下载，备用地址失效时可以回到原先仍可用的慢地址。短暂波动、临近完成、不支持续传或长度未知时不会强制换源。

单连接跨地址续传校验完整资源长度及精确 Content-Range。备用地址忽略 Range 或返回不一致范围时，不删除原来源的有效断点。并行分片沿用同样的严格范围校验；低速恢复只关闭当前响应，不取消其他分片、任务或播放请求。

iOS 原生 URLSession 的续传数据绑定原始 URL，低速恢复保留系统续传数据并重连同一地址一次；实际请求失败仍可尝试备用地址。暂停写入系统续传数据完成后才重新绑定请求，应用在后台时不因低速主动中断系统任务。此路径的真实设备后台行为仍需 iOS 实测。

调试日志的 `BilibiliTransfer` 项记录匿名传输标识、CDN 主机、来源序号、HTTP 状态、请求连接数、全局活动连接与预算、续传字节、新传输字节及速度。每 5 秒采样，并记录换源、重连、继续慢速、完成、取消和失败事件；不记录完整下载地址、签名参数、Cookie、标题或本地路径。日志中的速度从本次新传输字节计算，已有断点不算进速度，可通过现有调试日志面板复制排查。

存储扫描即使未初始化缓存服务也能读取索引。完整缓存属于保留内容，普通临时缓存清理不会删除；有效断点只有明确「放弃续传」才能清理。按实际文件去重统计，自定义目录仅登记已知文件。缓存页删除、空间清理和外部文件丢失会同步索引与来源卡片，保留字幕和观看记录。临时掉盘保留登记，重新挂载后可恢复；重新使用缓存只检查文件存在与大小，不再因修改时间变化重读摘要。
