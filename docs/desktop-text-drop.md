# 桌面文字与链接拖入

## 输入规则

- B 站下载/在线导入、yt-dlp、抖音主输入与批量输入：按实际换行符定位光标所在行；空白行直接填入，有内容则在该行之后插入。已有的下一行保持原样，下一行为空时复用它。
- 媒体、文件夹、播客和浏览器下载任务的名称：采用同样的分行规则；有选区时替换选区。初次重命名全选旧名称，拖回窗口时不重复全选。
- 普通编辑框保留光标插入/选区替换；网址栏替换整条地址。单行框将拖入文本的换行转为空格。只读、禁用、密码和数字输入不接收文字拖入。
- 链接框优先采用浏览器提供的 URL；名称优先采用纯文字。统一 CRLF/CR，不导入 HTML，不通过剪贴板中转。
- 拖入使用 EditableTextState 的用户编辑入口，保留格式校验、onChanged 和撤销；不触发提交/解析/下载/保存。单次文字接收上限为 1 Mi 个 UTF-16 单元。

## 接入与窗口

`DesktopTextDropHost` 由应用输入焦点宿主安装，通过当前画面的命中测试选择输入框；被弹窗遮挡的输入框不接收。`DesktopTextDropTarget` 为批量链接、重命名和浏览器地址栏设置专用策略，并覆盖完整输入框区域。其他普通文本框通过其实际可编辑区域接收。

浏览器下载队列在桌面端嵌入显示时，将重命名面板放在队列内部，随队列移动和缩放；没有新增覆盖网页的模态遮罩。点击网页保留草稿，保存/取消显式结束编辑；输入框内 Escape 取消草稿。手机和独立队列页面保留原对话框。

普通区域的链接拖入交给应用级链接分流入口，复用同一宿主，不新增原生接收器。
完整输入框区域先于分流判断，包括装饰、禁用和只读输入区；输入拒收时也不弹出链接入口。
全局分流仅在释放后处理链接，保留原有文字编辑、文件导入与移动端输入行为。
主动拖入不受自动剪贴板开关控制；排队、去重及验证记录见[剪贴板链接快捷入口](clipboard-link-shortcuts.md#桌面链接拖入)。

## 平台边界

沿用本地固定版本 `third_party/desktop_drop` 0.7.1 的同一个原生接收器，分开派发文字与文件事件，避免重复注册拖放窗口。Windows 读取 Unicode 和 URL 格式；macOS 读取粘贴板文字/URL，保留文件承诺和书签；Linux 用 GTK 协商 URI 与文字。文字只复制，源文字不被删除。

Windows 的 OLE 坐标只按当前窗口 DPI 换算一次；AppKit/GTK 使用逻辑坐标。Linux 当前浏览器为独立 Chromium，因此是跨窗口拖入。

## 验证

- 自动测试覆盖空行、连续追加、行中光标、选区替换、中文/表情、CRLF、格式校验、撤销、DPI、遮挡、文件事件隔离，以及三种桌面平台下的队列移动/缩放/网页操作与草稿保留。
- 抖音批量页验证实际链接计数和 100 条上限，超过上限保留输入并禁用提交。
- Windows 无界面原生检查：先构建 Debug 应用，再用 CMake 配置 `tool/native_desktop_drop_probe` 并运行生成的程序。它直接测试生产 OLE 接收器及真实 IDataObject，不操作鼠标、键盘或桌面窗口。
- 本次已验证 Windows WebView2 的选中文字拖入队列名称框、连续两次分行追加和保存。后续按用户要求使用自动化测试，停止桌面界面操作。
- macOS、Linux 原生代码已接入，组件测试使用相应平台规则；本机无法完成其原生构建和真实拖放验收。外部浏览器组合与 Linux X11/Wayland 仍需在对应桌面环境验收。

本次新增及相关回归共 183 项通过，Windows 原生检查的 8 类场景通过，Windows Debug 主程序构建成功，项目静态检查通过。全量回归为 7245 项通过、82 项跳过、11 项失败；这 11 项与改动前输入焦点宿主的对照结果完全相同，涉及 AI 面板、网盘布局和媒体库既有测试。日志和本轮变更前的文件快照保存在 `.artifacts/desktop-text-drop-*`，不进入发布包。
