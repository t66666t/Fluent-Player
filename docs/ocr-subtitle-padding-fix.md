# 宽框内固定背景小字过滤（2026-11-02）

## 前次验证纠正

用户为容纳长字幕，手动选择了较宽的字幕区域。这个范围是必要输入，不能把缩窄它当成修复。

前次仅用应用区域预览截图中的 600×32 局部素材验证横向扩边上限。该截图和 Android 独立验证包的对照只证明缩略素材的尾部 `av` 消失，不能证明用户完整框选中的 `Jaylc` 已被过滤。原视频到电脑后，使用完整区域连续重现了 `Jaylc`，因此前次完成结论不成立。原先“组件宽度 25%”扩边确有误带入风险，现有按字高限制余量的修复保留，但它不足以解决此次问题。

## 原视频复现与修复

原视频为 1280×720、30 fps。沿用观察到的手动框选 `x=218,y=595,width=835,height=48`，按现有流程缩为 640×36；没有改变框选宽度。用现有 10 Hz 采样及 `mpdecimate` 参数抽取前 40 秒，实际输出 247 帧，再通过真实 `OcrProcessingWorker` 顺序运行 Small、CPU 两线程。

6.9 秒时，正文识别框为 `(99,11)–(548,32)`，右侧小字框约为 `(574,21)–(617,34)`。小字高度仅为正文约六成，但底边接近。旧规则为保护正常英文小写而放行同基线的小字，随后又把它合并进整句。

10.7 秒的长字幕还暴露了另一个细节：扩边后的正文框和小字框已经水平重叠，扩边前的文字组件仍有明显间隔。只比较扩边后的框，会误把它们视为相邻正常单词。

本次修改限于已有检测框的大小、位置过滤：

- `OcrDetectedBox.contentBounds` 保留检测器已有的扩边前坐标，识别裁片仍使用原来的带余量范围。没有增加图像扫描或模型推理。
- 在合并前比较实际文字组件的字高和横向间隔。组件明显更小（低于正文约 80%），并且与所有当前字幕大小的组件都相隔约一个字高时，按侧边小标签排除。候选参照必须接近当前区域字高，防止又高又窄的背景图形反过来删除正文。
- 紧邻正文的小写单词、横向重叠的第二行、正常大小的右侧长字幕保留；窄小的不确定片段不直接删除。对无法仅凭大小位置确定的片段，沿用原来的合并与识别规则。
- 不按具体文字建立黑名单。主、副字幕保持各自已有的区域参考；模型、抽帧、双帧确认、合并时间、任务和检查点格式不变。新判断在各模型和平台共用的 Dart 检测后处理路径中执行。

## 验证与边界

原视频前 40 秒的相同 247 帧对照中，`Jaylc` 从 12 次降为 0 次。排除空白格式及该背景词后，双方输出的正文没有差异；没有出现旧版本有正文而新版本为空的帧。17 秒延伸至右侧的正常长字幕完整保留。

外部素材不提交仓库。复现及收据位于 `.artifacts/ocr-jaylc-wide-20261102/`：`frames.json`、`before-trace.json`、`trace.json`、`trace-comparison.json`、`wide-cases.json`。`ocr_subtitle_geometry_native_test.dart` 可通过 `OCR_WIDE_FRAME_MANIFEST` 指定原始宽框样本清单；也保留 `OCR_NOISE_FRAME` 单帧入口。合成素材覆盖六种当前组合和五种旧版组合的独立小字、同基线小字及只剩背景字的情况。

本轮检查：

- `python tool/verify_model_integration.py`：111 个文件分析通过、1045 项回归通过、3 项需要外部文件的用例跳过。兼容性基线哈希保持不变。
- 最终大小过滤单元及 Windows CPU 实际推理共 23 项通过；DirectML 的实际单帧、完整宽框样本清单和全部 11 个模型组合检查通过。
- 六种当前模型组合在 Windows CPU、DirectML、Vulkan、OpenCL 的 24 条路线通过文字对照；Small 的原视频 6.9 秒完整宽框在四条路线均保留正文、排除背景词。没有把其他语言模型的英文推理视为它们具备中文字幕识别能力。

Windows Small、CPU 两线程对六张实际宽框样本预热后按 ABBA 顺序测量，每个版本 72 次：均值约 59.45 → 55.24 ms，中位数约 57.95 → 57.60 ms。没有观察到平均耗时增加，不据此宣称稳定提速；额外工作只是少量框坐标比较。这个结果不能外推安卓整片耗时。

仍存在边界：20.8 秒有一个尾部 `v`，已混在正文的同一检测组件及识别裁片内，本次独立框过滤仍会漏过。为保护正常字幕，本次没有扩展到图像擦除、文本删尾或额外 OCR。不能把本次结果解释为所有背景文字均能清除。Android arm64 Release 构建与 APK 签名验证通过，包名、版本和发布签名保持一致，未安装到手机；本次仍需真机重新识别验证；Apple/Linux 未进行实机推理验收。前次窄截图的 Android 性能数字不作为本次修复证据。

更新程序不会自动改写已生成字幕。验证时应新建识别或重新识别出错部分，不能用旧任务已完成的前缀判断新过滤是否生效。
