# 页面快捷键设计与补齐

本轮先检查现有按键表、页面按钮、焦点与输入法处理，再补齐遗漏。保留现有视频播放、媒体库、字幕与 AI 的按键，不套用一套会改变原习惯的新布局。

## 按实际输入设备显示提示

页面能接收快捷键，与当前界面是否展示快捷键提示分开处理。Android / iOS 纯触控时，按钮长按、悬停说明、菜单和导入弹窗保留操作名称，隐藏按键后缀；首页与媒体库设置中的快捷键帮助入口同时隐藏。连接实体键盘后这些内容自动出现，断开后自动隐藏，不需要重新进入页面或重启应用。

| 当前设备 | 操作说明 | 按键标注和快捷键帮助入口 |
| --- | --- | --- |
| Android / iOS，纯触控或仅连接鼠标/触控板 | 保留；长按与鼠标悬停沿用原有规则 | 隐藏 |
| Android / iOS，连接实体键盘（可同时连接鼠标） | 保留 | 显示 |
| Windows / macOS / Linux | 保留 | 默认显示 |

共享的 `KeyboardShortcutHints` 位于应用 Navigator 上方，页面、已打开的设置、菜单和底部弹窗订阅同一份状态。设备变化只更新相关界面，不重建导航、不清除正在输入的内容或设置搜索词；已主动打开的帮助可继续阅读。快捷键事件分发和原有按键绑定保持启用，避免刚接上键盘时首个命令失效。

Android 使用 [InputManager.InputDeviceListener](https://developer.android.com/reference/android/hardware/input/InputManager.InputDeviceListener) 监听设备增加、移除和变化，并从输入设备列表识别启用中的非虚拟字母键盘，排除软键盘、鼠标、耳机与普通媒体遥控器。监听器绑定 Flutter engine 生命周期，兼容缓存引擎下的 Activity 重建。iOS 使用 [GCKeyboard.coalesced](https://developer.apple.com/documentation/gamecontroller/gckeyboard/coalesced) 与键盘连接/断开通知，按仍连接的键盘汇总状态更新。启动与恢复到前台时重新查询；较晚返回的旧查询不能覆盖较新的连接通知。无需轮询、蓝牙权限、持久化开关或用“最近一次按键”猜测连接状态。

`test/keyboard_shortcut_hints_test.dart` 覆盖初始连接、热插拔、恢复前台、查询竞态、原生查询失败、软键盘/鼠标不误触发、长按提示实时更新、已打开菜单与导入弹窗、手机及宽屏首页帮助入口，以及设置搜索状态保留。设备状态通过平台通道模拟；这不等于 Android / iOS 真机插拔实测。

本次在 Windows 主机完成验证：新增 17 项设备状态与界面测试通过；播放器顶栏另外 19 项回归通过；扩展页面回归有 313 项通过、2 项原有性能断言失败。失败项均为 `mobile_keyboard_performance_test.dart` 中 Android / iOS 的 `root Bilibili input retains page widgets through IME frames`，在独立的修改前源码副本中也复现完全相同的 4 次重建，未修改这些断言或扩展处理该既有问题。涉及的 Dart 代码通过静态分析；Android `:app:compileDebugKotlin -x :app:compileFlutterBuildDebug` 通过，尚未执行 iOS 原生编译或真机键盘插拔验证。

## 设计依据

- 同一类操作沿用已有含义：播放器 `P/N/G` 对应上一项、下一项、选集；`S/L/W/Z` 对应播放设置、字幕管理、AI、睡眠定时。
- 页面单字母保持跟手，但只在当前页面没有编辑文字时生效。不同页面可复用同一个字母，按钮提示解释当前含义。
- 新增命令仅在首次按下时执行，长按产生的 repeat 和松键不会重复开窗、解析、入队或扫描；上下方向键滚动页面时支持长按连续滚动。
- 不绕过按钮的加载、忙碌、登录、选中项及可见分页条件。危险操作继续走既有按钮回调；不添加一键清空文件、删除模型、退出账号等命令。
- 文本编辑优先于页面操作，包括文字、空格、方向键、复制、粘贴和全选。中文输入法 composing 期间的 Esc 留给输入法；普通输入态 Esc 只解除输入焦点。
- 弹窗、上层路由及隐藏页阻断底层快捷键。原生网页输入不属于 Flutter 文本框，必须额外按网页可见性或浮窗焦点隔离。

参考成熟软件时保留本软件的既有约定：VLC 使用 Space、P/N、F、M；YouTube 将快捷键显示在按钮提示中，并支持媒体播放键；Spotify 提供快捷键帮助及 Ctrl/Cmd+/ 入口。YouTube 的 J/K/L 在这里已经分别用于移动字幕、锁定、字幕库，因此不改成 YouTube 的快退/暂停/快进。

来源：[VLC 热键](https://docs.videolan.me/vlc-user/desktop/3.0/en/basic/hotkeys.html)、[YouTube 键盘快捷键](https://support.google.com/youtube/answer/7631406?hl=en)、[Spotify 键盘快捷键](https://support.spotify.com/ee-en/article/keyboard-shortcuts/)。

## 本轮补齐

| 页面 | 按键 | 动作与边界 |
| --- | --- | --- |
| 应用内帮助 | F1；Ctrl+/；Cmd+/ | 打开快捷键帮助；编辑文字时不打开；首页工具栏/更多菜单也可打开 |
| 首页、合集 | H | 展开/收起操作按钮；选择模式不执行 |
| 首页、合集 | J | 抖音下载；避免改掉已有 D、Y 等入口 |
| 首页、合集 | W | 浏览器导入 |
| 首页浏览页、合集 | ↑ / ↓ | 向上 / 向下滚动当前可见列表，支持长按连续滚动；输入框、滑块、弹窗和隐藏分页保留自身按键行为 |
| 音乐 | P / N / G | 上一首 / 下一首 / 选集，与视频一致；沿用现有队列和可用条件 |
| 音乐 | S / L / W / Z | 页面设置 / 字幕歌词管理 / AI / 睡眠定时；修复原 Z 分支被白名单挡住的问题 |
| 抖音 | V / X / Enter | 粘贴 / 清空 / 解析；普通 Enter 与数字键盘 Enter 都支持 |
| 抖音 | S / L | 设置 / 登录或账号 |
| 抖音 | A / Q / Space | 手动模式全选资源 / 手动模式加入队列 / 开始待下载队列；按当前可见分页执行 |
| 网页队列 | A；Ctrl+A；Cmd+A | 切换当前筛选列表全选；文本框内仍是文本全选 |
| 网页队列 | Space / P | 有选择时开始/暂停所选，无选择时全部继续/暂停 |
| 网页队列 | T / R / S | 重试失败 / 移除所选 / 队列设置；未选择时 R 不执行 |
| 缓存管理 | S / P | 聚焦搜索 / 缓存设置 |
| 缓存管理 | Space | 暂停或继续当前筛选任务；已缓存分页不执行 |
| 缓存管理 | R | 仅在读取出错时重新读取 |
| 存储管理 | R / C | 重新扫描 / 复制诊断摘要；扫描忙碌时 R 不重复扫描，C 沿用已有摘要的可用条件 |
| B站首页/搜索 | S 或 / | 聚焦搜索框 |
| B站首页/搜索 | H / L / R | 历史 / 账号 / 刷新当前搜索结果；加载时不重复刷新 |
| 设备同步 | R / N | 立即同步 / 发送文件夹；未启用或忙碌时不触发同步 |

抖音显示原生网页时暂停整页单字母命令，避免在网页表单里误触发；打开资源列表或切到队列后恢复。自动模式不执行手动资源的 A/Q 命令。

网页队列通常是浏览器内的浮窗。先点击浮窗或用 Tab 进入其控件后才接收按键；失焦后不从网页抢键盘事件。重命名框保留文字输入。浮窗 Esc 被消费，不会后退浏览器；独立队列页 Esc 沿用返回。

## 全局快捷键建议与实际状态

需要区分两个范围：应用内当前页快捷键，以及切换到其他软件后仍有效的跨应用全局控制。Flutter 的 HardwareKeyboard handler 即使名字里包含 global，也只监听交给本应用的事件，不能视为系统全局热键。

建议保留页面单键；后台播放控制优先使用播放/暂停、上一曲、下一曲这类系统媒体键。它们表达明确，适合键盘、蓝牙耳机、通知和锁屏入口。VLC 也提供独立的后台热键配置能力，但本轮不将普通字母注册到操作系统。

桌面后台控制已增加独立的平台适配，统一调用现有播放服务：Windows 使用 SMTC 和任务栏缩略图工具栏，macOS 使用 Now Playing / Remote Command Center，Linux 使用 MPRIS。Android/iOS 继续复用原有系统媒体会话。

Windows/macOS 可在“媒体库设置 → 桌面媒体控制”开启全局组合键，默认关闭：`Ctrl+Alt+Space` 播放/暂停，`Ctrl+Alt+←` 上一项，`Ctrl+Alt+→` 下一项。也可改用 `Ctrl+Alt+Shift` 组合。这是两套可选预设，不是任意按键录制功能。被占用时显示注册失败；关闭功能、停止会话或退出时释放注册。Linux 的组合键由桌面环境配置，不使用在 Wayland 下无效的 X11 抢键方案。

详细的行为、平台差异和验证边界见 [桌面媒体控制](desktop-media-controls.md)。

## 平台与验证

页面命令沿用 Windows、macOS、Linux、Android、iOS 的共同键盘策略；移动端连接键盘即可走相同 Flutter 路径，不增加桌面专用判断。F/F11 窗口全屏仍仅面向桌面，Android Back/Esc 的原生导航规则保持不变。

共享页面作用域增加 Android 原生补偿监听与双通道去重，并补齐 Enter、数字键盘 Enter、/、方括号及 F 键的桥接解码。原生桥只有汇总的阻挡修饰键信息，Ctrl/Cmd+A 等组合由正常 Flutter 路径处理。帮助入口通过 Flutter Shortcuts；F1 解码测试本身不代表厂商原生补偿专用路径已能打开帮助。

回归测试覆盖新增命令、输入/中文组词、重复事件、按钮不可用状态、弹窗/隐藏页、焦点丢失、浮窗隔离、上下曲、既有播放长按行为和按钮提示。测试在 Windows 主机的 Flutter widget/unit 环境执行；其他平台的策略矩阵通过测试不等于对应设备已实测。Android/iOS 外接键盘、桌面原生输入法及实际浏览器内核仍需设备验证。

验证结果：本轮涉及的生产代码与新增/扩展键盘测试通过 `dart analyze`；相关 Flutter 回归最终通过。包含首页/合集、音乐、抖音、网页队列、B站、缓存/存储、设备同步、现有倍速/音量/AI、输入法、移动键盘策略、网页重命名与布局检查。更新按钮提示后同步修正旧布局测试的提示查找，未改变其布局断言。
