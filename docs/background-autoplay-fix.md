# 手动暂停后后台误续播修复

日期：2026-10-30。

代码中确认了能够造成误续播的缺陷，已完成修复及自动回归。尚未取得用户这次手机事件的日志，不能认定远控、语音输入或某一外部应用是唯一触发源。本轮没有操作手机，也没有把修改安装到正式应用。

## 已确认的问题

1. `SystemMediaSessionService` 收到中断结束事件时，只检查“当前已暂停”和事件类型，没有记录是不是该次中断暂停了原本正在播放的媒体。已经手动暂停的媒体，也可能被一次焦点恢复或迟到的中断结束通知重新启动。
2. 系统媒体暂停命令在取得焦点后的 1200 毫秒内，可能被当作播放器自己的焦点噪声过滤掉。该时间窗口不能判断通知栏暂停是否由用户发出；耳机点击以外的真实暂停也必须生效。
3. 前台恢复发出的原生播放请求可能较晚完成。其间用户已经暂停时，旧请求完成后仍可能让底层播放器开始播放。

Android 的焦点变化与用户主动按下播放是两种不同事件。官方示例用 `resumeOnFocusGain` 等标志判断焦点恢复时能否继续播放，而不是把所有暂停状态都恢复。[Android 音频焦点文档](https://developer.android.com/media/optimize/audio-focus)

项目锁定的 `audio_session 0.2.4` 将 Android `AUDIOFOCUS_GAIN` 映射为中断结束事件；它不保证该事件前一定有应用仍然认可的临时暂停。其他应用使用音频可能引起焦点变化，但单凭“正在远控电脑或语音输入”不足以确认本次触发过程。

## 修复行为

- 临时中断开始时，仅为原本有播放意图的媒体记录恢复资格，包含播放服务实例、媒体 ID、会话代次和该次暂停的序号。
- 手动暂停再次提交、睡眠定时到期、停止播放、媒体/会话更换、永久焦点丢失或耳机断开，使旧恢复资格无效。即使界面本来已经显示暂停，再次暂停的意图也能被区分。
- 中断结束先结算到期定时，再检查恢复资格；资格使用一次后清除。无对应开始事件、重复恢复通知、已结束播放以及失败会话不能因此自动播放。
- Android 临时中断保留原有焦点请求以接收正常恢复；同时发生的 duck 事件不会给原本手动暂停的媒体新增播放资格。允许与其他应用同时播放的设置继续生效。
- 保留 iOS 的事件语义：其开始事件为 unknown，结束事件中的 should-resume 决定能否续播。真实平台尚未验证，相关事件序列已加入行为测试。
- 通知栏和耳机暂停作为明确的传输命令处理；Android 播放器自己产生的焦点噪声仍在真正的焦点事件路径处理。耳机按钮防重复和主动播放功能保留。
- 前台恢复不占住显式暂停的命令队列。迟到请求完成后，仅在同一物理控制器仍被持有且最新意图为暂停时补发暂停；旧控制器不会操作替换后的控制器。

主要修改位于 `lib/services/system_media_session_service.dart` 和 `lib/services/media_playback_service.dart`。恢复资格仅存在于内存，没有新增会话持久化格式、默认设置、播放器后端或媒体库操作。

## 验证

新增 `test/audio_interruption_resume_test.dart`，包含 18 个行为场景。通过实际播放服务与同一中断处理入口执行，播放器平台由测试替身控制；不是源码文本匹配检查。修复前已复现手动暂停被恢复、通知暂停被忽略、迟到前台播放盖过暂停等失败。

覆盖手动暂停后单独收到 gain、已暂停时收到完整中断序列、中断期间再次暂停、重复开始/结束、临时中断正常恢复、媒体重建、永久丢失、耳机移除、并发播放设置、过期睡眠定时、停止、iOS 事件映射、duck 事件及原生播放迟到。未返回的前台恢复请求不能阻塞用户暂停。

最终相关回归：**14 个测试文件，358 项通过**。包含媒体按键、通知封面、桌面媒体会话、播放竞争、在线启动、传输同步、定时、播放页及原生暂停修复逻辑。修改相关 Dart 分析无问题。

工作区日志在 `build/background-autoplay-audit/`：

- `red.log`：修复前的行为失败。
- `final-focus.log`：中断、并发播放策略、媒体按键的针对性回归。
- `regression-final.log`：最终 358 项回归。
- `analyze-final.log`：Dart 分析。
- `baseline/`、`review/`：本轮开始时的相关文件快照及变化，避免混入工作区已有修改。

针对性复跑：

```powershell
flutter test --no-pub test/audio_interruption_resume_test.dart test/concurrent_playback_policy_test.dart test/system_media_session_controls_test.dart
dart analyze lib/services/system_media_session_service.dart lib/services/media_playback_service.dart test/audio_interruption_resume_test.dart test/concurrent_playback_policy_test.dart
```

以上通过证明这些代码路径的行为，不等于已复现并修复此次安卓设备上的所有触发方式。Android 17 真机还需在更新后检查“手动暂停—切后台—使用远控/语音—结束使用—保持暂停”，并与真实临时中断的正常续播对照。通知或耳机主动发出的播放命令仍然可用；如后续还有误播，需进一步区分焦点恢复与外部播放命令。
