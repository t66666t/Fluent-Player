## 对话上下文压缩（2026-10-15）

现已支持应用内的自动和手动聊天历史摘要，默认开启自动压缩。点击顶部“上下文使用量 → 压缩与摘要”，或“更多 → 压缩上下文”，可以填写保留重点、立即压缩、停止压缩及展开查看摘要。摘要使用当前选定的模型、地址和凭据，不另选服务；可能产生额外模型用量。自动开关会持久保存，关闭后仍可手动压缩。

发送前先计算未裁剪的完整活动历史；常规压力阈值为有效输入预算的 80%，目标约为 60%。省 token 模式保留 32k 软预算；已有历史分配将要裁掉完整轮次时，也先尝试摘要。固定全文资料占比高时，以保持资料完整、请求能发送及确有缩减为准，不为了达到目标百分比替换字幕原文。默认保留最新两个完整轮次，窗口较小时可减少保留轮次；当前用户问题始终完整。摘要只合并上一检查点与新进入旧段的完整轮次，不采用失败或中断的回答，不存思考过程。

原始聊天消息继续完整保存。摘要检查点单独记录覆盖范围、前缀校验、字幕来源标识及上下文哈希、模型与用量。旧存档无需迁移即可读取。编辑、撤回、重新生成和分支时根据实际前缀判定有效性；模型、协议、播放位置或检索意图变化不会直接清掉通用文字摘要，但必须重建相应请求前缀并重新估算。预览只做本地计算，不调用模型。

压缩直接使用现有 Chat Completions、Anthropic Messages、Gemini GenerateContent、Codex app-server/exec 或 OpenCode run 通道；当前不接入原生加密压缩状态，也不改变 CLI 会话隔离策略。摘要请求自行预检、按需分块合并，每次整理最多八次摘要调用；空内容、输出截断、取消、失败或无缩减均不覆盖已有摘要。同一失败历史范围不反复自动调用，手动可重试。运行与取消绑定原对话，切换对话不串写。

输入超窗现在单独分类：只有明确的 context overflow 且尚未输出正文时，才允许压缩后重试一次；第二次仍超窗则结束。限流、鉴权、一般参数错误、普通 413 和输出长度结束不触发压缩。摘要及已知超窗尝试用量单列并计入回答总消耗，缺失的用量标为未知。上下文估算不使用累计计费输入作校准；前缀复用只接受已知单次输入的测量值。模型目录区分独立输入/输出上限和共享窗口，未知服务保持保守估算。

验证记录见 `.artifacts/ai-chat/context-compaction-regression.log`、`context-compaction-analyze.log`、`build-windows-context-compaction.log`；界面截图为 `context-compaction-preview.png`。验证采用本地 HTTP 和模拟 CLI/模型，未调用用户真实模型账号。

## 生成上限与百炼模型预算（2026-10-14）

API 正文达到上限时，保留原始问题、资料、历史前缀和已有正文，最多自动补写一次，在同一条回答中显示。补写不重新进行问题规划、字幕处理或标题生成；可关闭思考的模型在补写时关闭，必须思考的模型使用最低已声明等级。只有思考、没有正文时，单独请求补齐正文，不把未完成的思考伪装成历史回答。每次请求受单次生成设置、模型输出限制、输入限制和剩余窗口共同约束；两次仍未结束时显示“继续生成”。保存的 8k/64k 偏好不自动提高；8k 是每次生成额度，两次生成最多各使用 8k，输入会再次计费。断网恢复属于传输层的有界重试，另遵循下面的网络恢复流程。

用量累计所有已返回的生成统计，缺失字段保持未知；不把累计思考/缓存明细覆盖成最后一次的数字。多次请求的输入账单与当前上下文大小分开：下一轮和补写预算使用原始请求的实测输入，经过断线重试而无法分离的合计输入仅用于账单，预算退回保守本地估算。长回答的历史节选同时保留开头和中断处，帮助后续理解续写、纠正和困惑。

## 本轮意图与资料选择

### 2026-10-13 长字幕处理优化

采用 [LlamaIndex 的窗口装包](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/indices/prompt_helper.py)与[异步分段、逐层合并](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/response_synthesizers/tree_summarize.py)的思路，并参考 [DeepSeek Harness 的本地估算与实际用量区分](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/token-meter/README.md)。实现仍使用原有 Dart 传输与本地缓存，无新增运行依赖。

流程是：判断本轮任务 → 能放入时直接发完整原文 → 放不入时全量建立主题索引／问题证据 → 按最终剩余空间自适应合并 → 搭配需要的原文回答。API 至多两段同时处理，普通索引不逐句复述全文。正文截断优先续写，继续失败才拆小；完整记录持久化，取消与失败不把残稿写成完成结果。合并预算分配给每组，后续轮次进一步收紧，避免固定长度合并一直无法放入最终窗口。最终回答的思考偏好保留。

实测中首次发现高密度数学文稿的合并仍会超长，自动预算正确停止了请求；随后按最终窗口调整合并策略，保留并复用已完成的分段记录，不重新支付原文处理。新记录使用独立版本缓存，首次可能需要重建，旧文件不删除。下面的 2026-10-12 记录属于旧恢复策略，现行参数以“上下文逻辑”和“用量与缓存”为准。

换话题、纠正、困惑或资料范围变化时重新构建活动上下文，不再为了缓存而重放旧播放状态与旧检索资料。明确的连续追问可以继续复用相同资料范围的请求前缀。失败或中断回答不进入权威历史；早期原文摘录只加入查询相关的文字。上一答过长时保留标明省略的最近轮次摘录，帮助理解反馈。原始本地聊天记录保留。

## AI 阅读位置与进入规则（2026-10-14）

## 屏幕与布局

生成回答时，设置、视频资料、开发者模式、历史、新建、重命名、导出和消息操作保持可用。每轮在发送时固定配置、所选资料、播放快照及原对话 ID；意图判断、全文处理、正文和标题均使用该轮配置。设置窗口保存成功后才关闭，改动从下一次发送生效；修改资料也只影响下一轮。设置会同步给其他已经打开的视频对话，其正在生成的回答仍使用原快照。

切换、新建或分支保留源对话的后台生成，新对话可以独立发送。生成状态、请求预览、阶段、取消对象与标题任务按对话隔离；停止只取消当前查看的回答。复制可以包含已经生成的正文。从正在生成的回答创建分支时，分支保留当时的文字并标记为未完成，源回答继续生成。编辑、重新生成、撤回、删除会先停止并保存对应回答，再修改记录；不会因为迟到的流式片段复活删除的对话或覆盖修改后的消息。磁盘修改期间仍短暂防止重复提交。

AI 入口默认在字幕边栏内部打开：竖屏位于视频下方，横屏位于视频旁，横屏宽度与字幕文稿共用，保留视频画面。顶栏的“全屏对话”可展开为完整聊天窗口；全屏与面板共用对话控制器和输入草稿，流式生成不中断，退出全屏或系统返回后回到原播放器面板。竖屏中按可用高度限制视频并逐渐收起外部工具条，横屏仅将聊天面板抬到键盘上方。聊天顶栏始终直接显示历史和新建图标，开发者模式和源对话位于更多菜单，视频资料和模型使用一行摘要；输入框默认一行，随输入增长。提示与用量通过信息按钮查看。短横屏和键盘弹出时，资料入口收进菜单并限制输入框高度。桌面保留 Enter 发送，手机用发送按钮、键盘回车换行。

快捷提问仅填入草稿，光标放在文字末尾，不主动聚焦输入框或发送；已聚焦时会收起键盘。输入文字和占位文字采用相同字号、行高及对称留白，发送按钮与单行输入垂直居中。输入框只更新自己的文字与发送按钮，避免每次打字重建消息 Markdown。

竖屏、横屏和全屏共用 `AiKeyboardViewport`，播放器关闭自动缩放，由该组件统一处理键盘高度，并扣除已预留的底部安全区，避免重复避让。系统逐帧上报键盘高度时直接跟随；仅一次上报最终高度时使用 220ms 曲线过渡，收起或中途反向都从当前显示位置继续。无动画偏好会立即更新。动画使用固定子树，聊天布局仅在响应式断点变化时重新构建，减少 Markdown 重复解析与播放器重绘。模拟回归覆盖了逐帧跟随、展开/收起、中断反向、底部安全区、极短横屏和全屏键盘；未连接手机，实际移动设备帧率尚未做性能采样。

展开或收起思考会暂停自动滚动，手动向上滚动也会立即暂停，流式输出继续更新但不会抢走阅读位置。点击“回到最新”，或手动向下滚动到末尾，可恢复追随；发送新提问也会恢复。自动滚动回调在执行前再次核对阅读状态，避免先前排队的回调覆盖用户操作。

视频资料页使用主、副字幕优先的紧凑勾选列表，视频信息默认折叠；点击文稿行或预览图标查看内容，不会改变勾选。小屏逐页预览，宽屏左侧选资料、右侧直接预览文稿。关键词搜索始终可用，时间筛选按需展开；筛选工具与长文稿分别滚动。设置页在小屏使用单栏，宽屏将连接与模型、响应与预算分成两栏。历史、文稿预览、模型选择、编辑和开发者页面共用适应安全区与键盘的弹层；窄屏使用完整可用区域，宽屏限制窗口尺寸。

视觉使用现有 AppTokens 的中性灰、蓝色强调色和应用字体，减少装饰卡片、彩色图标和大段常驻说明。回归用例覆盖竖屏/横屏面板切换全屏与草稿保留、流式思考展开/收起及手动上滑、快捷提问、输入框对齐、短横屏键盘、较大字体、宽屏资料预览及设置分栏。

## 对话与分支

每个视频有独立的本地历史，每次“新建对话”产生独立记录。完成第一轮后先保留提问生成的本地标题，API 后端再用一次小请求概括标题；概括失败保留本地标题。手动重命名优先于自动标题。开发者模式可以编辑标题提示词，清空它则禁用该额外请求。

编辑、撤回和重新生成默认在当前对话内操作，保留对话 ID，不自动增加历史记录。撤回将该提问放回输入框，并移除该提问及其后的消息；编辑从该提问处重新发送修改后的内容；重新生成从对应提问处重新回答。修改较早的轮次时，后续依赖旧内容的消息会被移除，并清理旧请求前缀，避免将已撤回内容继续传给 AI。只有点击“从这里创建分支”才创建独立记录：从助手回答分支会复制到该回答；从用户提问分支则把提问放回草稿，避免形成未回答的历史轮次。分支记录保存源对话与源消息 ID，可以返回源对话。上下文预算裁剪不会删除本地历史。

历史支持搜索、重命名、删除和复制为 Markdown。每条对话独立保存为 JSON，写入有临时文件和上一版备份，启动时可以恢复受损文件的上一版；上次未结束的回答恢复为已中断状态。流式过程每秒保存一次，结束、失败、停止时再保存一次。编辑、删除与设置保存期间锁定会话操作；过期的消息编辑不会发送到其他对话。服务中断、内容过滤与不支持的工具调用保留部分回答并明确显示失败。

## 上下文逻辑

### 文稿处理方式与速度

在“AI 设置 → 文稿处理方式”选择模式；“快速总结”可以独立关闭。常规预算为平时的输入/输出总预算；自动全文扩展和全文直读的实际请求预算在上下文指示器和答复详情中单独列出。输入上限提高不代表填充到上限，实际输入仍只有来源资料、提问与必要历史。

AI 设置中可选择四种方式：自动按问题控制资料量（默认）、全文直读、省 token 片段检索、分段整理。自动的细节问答优先检索约 6k token 原文；全片与播放位置问题先尝试一次发送全部已选文字字幕。智能节省开启且常规预算至少 64k 时，必要时可临时尝试 96k；只有能容纳全文并免去多次分段请求时才采用，不降低用户已配置的更大预算。智能节省开启时较小的手动预算不自动扩展；关闭时依次尝试 96k、128k 和至多 256k，采用能容纳全文的最小档位并受已知模型窗口约束。模型窗口未知时不擅自扩展；实在放不下才进行全文分段。全文直读使用模型声明的窗口，放不下明确报错。实际发送预算随答复保存，并与配置预算分开显示。

省 token 模式将视频片段限制在约 6k 本地估算 token，精简历史，不发起分段摘要请求；代价是全面概括可能遗漏，因此界面和请求预览明确说明。分段整理模式在全片问题中主动预生成记录，即使原文能直接放入窗口也遵从用户选择；首次有额外处理时间和费用，完成记录可复用。“快速总结”默认关闭，最终回答沿用用户的思考设置；显式开启时，基础总结在能力已知且可关闭思考时关闭，必须思考时使用最低等级。中间资料整理独立采用快速处理策略。

请求去除 SRT 序号和不必要的格式，保留全部字幕文字和时间锚点；一小时以内的锚点采用 MM:SS，长视频保留 HH:MM:SS，减少重复时间格式。全文静态资料仍在动态播放位置及提问之前，以利供应商缓存复用。

用户提供的 58 分钟 `ai.srt` 实测为 129,015 字节、1,937 条可读字幕、20,211 个正文字符。逐条检查确认默认模式把全部字幕放进一个请求；完整输入本地保守估算约 48,465 token，省 token 模式约 5,384 token 且明确为非完整覆盖。本地组装时间约 24ms（单次样本，包含默认预算尝试和全文扩展，不包含首次索引建立和网络/模型生成时间）。测量文件为 `.artifacts/ai-chat/fulltext-example-measurement.json`；未调用真实 API，也未修改用户字幕。

本次全部 AI 与播放器回归以及用户实际字幕测试共 247 项通过、2 项真实 CLI 测试未启用；AI 模块与全部 AI 测试静态分析无问题。记录为 `.artifacts/ai-chat/fulltext-speed-regression.log` 和 `.artifacts/ai-chat/fulltext-speed-analyze.log`。Windows Debug 和 Release 构建成功，记录为 `.artifacts/ai-chat/build-windows-fulltext-speed.log` 和 `.artifacts/ai-chat/build-windows-fulltext-speed-release.log`；Release 构建后核对用户字幕 SHA-256，文件保持不变。模式选择、偏好保存、240/320px 窄屏设置和当前播放器布局通过回归；未测试真实 DeepSeek 的整次响应时长。

字幕来源包括播放器已加载的字幕、视频绑定的主副字幕、下载附带的字幕、托管字幕资产、其他关联文稿、同目录匹配的字幕，以及现有 B 站字幕服务可获取的在线轨道。在线轨道复用现有登录与字幕服务，读取字幕 JSON，不下载整段视频。

默认优先选择有文字的主字幕和副字幕；没有指定主、副字幕时，按完整度、语言、绑定关系和人工文稿优先级推荐一条可用来源。自动推荐跟随播放器主、副字幕变化；手动选择后保留选择，也保留明确的“仅元信息”。对话分支继承选择模式，历史记录不会被自动改为全部字幕。点击“自动选择”可恢复自动模式。

字幕名称优先使用语言、来源和用户命名，清理缓存名、UUID、哈希以及常见乱码；相似名称会补充区分。每条资料显示主/副/其他角色、来源、片段数量、时间范围和开头摘要。**预览文稿**支持关键词、起止时间、当前位置附近筛选、时间戳跳转和复制；长文稿按段懒加载。完整文件路径不进入 AI 上下文。视频元信息也可预览。

在线字幕保存到本地后保持轨道身份，并迁移旧文件 ID 的选择。在线列表与内容共用 15 秒等待预算，最多 4 轨并发；成功内容缓存，失败自动重试间隔 30 秒。上下文窗口的“重新读取资料”可以立即重试。当前片段定位与引用跳转会计入播放器的字幕延迟。

字幕以时间片段建立缓存的词语、中文二元词索引。具体问题优先检索相关原文及邻近片段；当前片段或带时间的问题覆盖对应位置。简短的连续追问结合最近提问补充检索线索。能放入预算时直接发送完整字幕。

长字幕的全片总结采用全文分段处理：全部已选文字字幕建立紧凑主题记录与时间索引，覆盖主题、关键结论和相互联系，避免逐句重写或展开完整教学推导。按可用窗口装包，普通主题整理每次输入至多约 24k 本地估算 token，全面核查至多 12k，另预留提示词、输出及余量；保留每条文字和时间锚点，字幕标签与范围只在段首提供。API 每轮最多两段并发，CLI 串行；结果始终按来源顺序排列。记录仍过长时分组、逐层合并。超长单条字幕按 Unicode 码点完整拆分。

普通主题索引通常预留 1,536 token 输出，必须思考模型预留 3,072；全面核查分别为 4,096/6,144，均受模型输出上限和剩余窗口约束。正文截断先带着未完成记录续写一次，不从零重写同一段，也不单纯增加上限；仍截断则立即拆成更小的四段，完整成功后保存父段结果。只返回思考时单独增加正文空间。每个原始段最多 8 次请求、拆分最多 2 层；过滤等非截断错误直接停止。

缓存按原文片段、供应商/模型、提示词、输入/输出配置与核查问题隔离，带完整性校验。新主题记录使用 v4 缓存，旧缓存文件保留，首次需要重建新记录。停止、失败、截断的输出不会写成完成缓存；完成的独立分段仍可复用。修改字幕只重新处理受影响的分段，重开后复用已完成记录。失败会取消、等待其他在途处理结束，不再启动新段，不退回抽样总结。

“列出所有”“有没有提过”等全面核查问题会按问题逐段检查原文，不复用普通概括替代核查；相同问题的完成结果可复用。全文处理进度表示每段均经过处理或复用了该段记录，不代表摘要保留了每一项细节。语义摘要仍可能省略内容，原文保持完整，细节提问继续回查原文。

请求预算先扣除最大回答长度和额外余量，再分配系统提示词、当前问题、近期完整对话轮次、较早对话的有界原文摘录和视频资料。本地按文字类型保守估算，不再直接把 UTF-8 字节数当 token 数；这不是供应商的精确分词结果，实际消耗以服务商返回为准。过长的当前问题或提示词明确报错并保留草稿，不截断用户问题。

长期历史摘录是原文摘录，并非模型生成的语义摘要。失败或中断的助手回答不会作为完整助手轮次发送；思考过程不发送到下一轮。较早历史和长字幕被裁剪时显示说明，完整记录仍保存在本地。

**范围说明：**普通细节检索使用本地词语和中文二元词索引，不需要额外的 embedding API，纯语义关联和罕见同义表达仍可能检索不足。全文分段摘要与核查覆盖所有已选可读字幕，但无法承诺模型从不遗漏事实。模型分析提供的元信息与文稿，当前不会识别视频画面。

## 用量与缓存

用量按答复当时的连接方式、协议、域名和模型分别展示。Codex/OpenCode 不套用 DeepSeek 的缓存命中率，详情仅显示 CLI 实际返回的已复用输入等字段；API 仅展示实际返回的缓存、写入、思考分项。没有字段不显示为零。少量缓存命中不再取整成 0%，极小值显示 `<0.1%`。DeepSeek 明确返回零时标为“本次未命中缓存”；没有缓存字段则说明无法判断。详情包含命中及未命中的输入 token，并提供与上一请求的本地前缀比较（字符比较不是服务端缓存匹配或精确 token）。历史记录缺少接口来源时使用中性标签，不根据当前模型猜测旧记录来源。前缀诊断不保存或显示 API Key，也不通过额外请求人为预热缓存。

API 智能节省模式保存实际发给模型的消息。下一轮沿用完整的上次请求，追加完成的回答、尚未注入的资料、当前位置和新问题；相同字幕摘录不重复注入，不发送上一轮思考过程。视频元信息去掉动态 `positionMs` 并固定字段顺序，播放进度和字段重排不会破坏前缀。历史分支、来源、模型、服务或提示词变化时重新建立上下文；重开软件仍可复用保存的请求。此策略参考 [DeepSeek Harness Session](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/core/session)，提高前缀复用机会，不保证供应商命中，也不发额外付费请求预热。

活动上下文达到约 32k token 或模型/配置输入预算时才重整历史。完整字幕已在固定前缀中且仍可容纳时，保留该字幕前缀，仅重整对话尾部；其他情况保留最近完整轮次及较早原文摘录。全文直读以及固定全文前缀本身已超过 32k 本地估算的会话使用模型/配置预算作为阈值。可见历史及字幕原文不会删除；较早原文摘录不是语义摘要，仍有信息损失，详情明确显示重整原因。参考 [DeepSeek Harness Token Meter](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/llm/token-meter)，连续请求以服务报告的输入量加新增内容的本地估算预测下一轮占用；校验与占用界面共用该预测，未返回用量时回退保守估算。这些预测不是账单。

全文预处理除每段恢复上限外，全局最多 `max(4, 原始分段数 × 6 + 2)` 次实际请求，预计输入总量最多 `max(20,000, 原始分段预计输入 × 4)`，允许一次续写后的四段恢复及必要汇总。预算在启动请求时预留，包括并发中的请求。达到任一上限立即停止，已完成分段继续保留；不继续无限收费，不退回抽样回答。预算、实际调用数、已知消耗、并发峰值、各次结束原因与耗时进入答复详情。本地记录复用不触发 API 请求，也不计作服务端缓存命中。

资料栏右侧显示下一次请求的预计输入占模型窗口比例，点击查看配置预算、回答预留和上次实际输入。模型窗口未知时显示占配置预算的比例，不将配置预算冒充模型上限。输入后的估算延迟合并刷新，不重建消息 Markdown。

DeepSeek 使用服务自动提供的前缀缓存；静态字幕/摘要位于动态播放位置、聊天历史与本次问题之前，提高重复前缀的复用机会，实际命中以 `prompt_cache_hit_tokens` 等字段为准，不保证命中。Claude 官方原生接口对足够长的静态资料块标记缓存边界，自定义代理不添加这类专用参数。Gemini、OpenAI 兼容 API、Codex 与 OpenCode 分别归一化其用量字段。全文分段提示词在开发者模式中可编辑，修改后相关缓存重新生成。

来源资料、标题、元信息和历史摘录在请求中有明确的数据边界；提示词要求区分资料与指令，并区分事实、推断与未知内容。开发者预览展示实际发送的消息顺序及节选，便于检查这些规则。

## Markdown 与桌面后端

思考框、展开/收起标题的点击反馈和展开后的外轮廓共用 10 逻辑像素圆角，并在 Material 层裁剪点击效果。展开和收起显式指定无描边形状，去掉 ExpansionTile 默认的上下分隔线，避免展开后顶部出现横向细线。本轮 29 项对话面板回归通过，静态检查无问题；展开和收起按下状态截图为 `.artifacts/ai-chat/reasoning-expanded-pressed.png` 与 `reasoning-collapsed-pressed.png`，验证记录为 `reasoning-shape-tests.log` 和 `reasoning-shape-analyze.log`。

Markdown 使用维护中的 `flutter_markdown_plus` 与 Dart `markdown` 的 GFM 解析，支持标题、列表、引用、表格、任务列表、链接、可选择文字与代码块复制。流式消息更新节流，对话列表懒构建，消息独立重绘。思考内容单独折叠展示；连接测试和标题请求在允许时关闭思考，不能关闭的模型保留必要输出空间并采用较低等级。时间戳链接用于跳转当前视频；网页链接限 HTTP(S)，生成的 HTML 或代码不执行，图片显示文字占位。

聊天链接采用主题蓝色文字，不加下划线；时间引用如 `[00:37:29]–[00:42:49]` 显示为 `00:37:29 – 00:42:49`，两端均可点击跳转。时间戳与两侧文字之间缺少空格时补充一个空格，已有空白保留。该处理发生在 Markdown 语法解析中，保留消息原文、代码示例、无效时间和正常 Markdown 链接的语义；标题内的时间沿用标题字号及粗细。

链接点击识别器由消息的 Markdown 状态持有，流式重新排版继续复用同一目标的识别器，解决指针按下与松开之间到达新内容导致点击取消的问题。每次实际解析后回收已移除链接，消息卸载时释放全部识别器。回复尚未结束即可跳转时间戳。聊天加载、文稿准备、模型连接/等待/思考和模型目录读取、连接测试均采用静态文字或静态图标，不使用持续旋转的加载圈或不定进度条；上下文占用比例仍显示静态定量指示。

流式交互修复验证：67 项公式、原生选择及聊天相关回归通过；新增覆盖在指针按下和松开之间更新回复的真实点击，以及 Codex 模拟流在连接、准备、等待、思考、正文生成等阶段的静态提示与未完成回复的时间跳转。改动文件静态分析无问题。

桌面端可以选择已安装并登录的 Codex 或 OpenCode，指定可执行文件路径和模型，或使用 CLI 默认模型。Codex 默认通过 App Server 的 stdio JSON-RPC 连接，实时接收正文增量与模型提供的可读思考摘要；不同模型、问题或等级可能不返回摘要，应用不伪造思考内容。初始化后的进程在连续请求中复用，空闲十五分钟后关闭；空闲聊天的设置页借用同一连接，关闭设置页不会销毁测试成功的聊天连接。具体取舍与实测见 [Codex 连接复用](codex-connection-reuse.md)。每条有界请求使用独立 ephemeral 线程，不带入隐藏的上一条 CLI 会话历史；停止时立即停止界面输出并请求中断，未及时响应则终止进程。启动与等待模型阶段在回答区域显示。

Codex 聊天进程使用临时目录与只读沙箱，关闭此通道不需要的 apps、shell_tool、shell_snapshot，并将项目指导文件读取预算设为零；这些只作用于本应用启动的子进程。OpenCode 继续使用 JSON 输出和禁止工具权限的独立聊天 agent。两者复用本机 CLI 的登录与供应商设置，提问经 stdin 传递，不拼入 shell 参数。Codex `exec --json` 的旧适配器仍作为兼容性测试路径保留，默认聊天使用 App Server。

CLI 路径可以填写可执行文件、`bin` 文件夹或安装文件夹，也可以留空；应用会查找 PATH 和常见桌面安装目录，包括 `%LOCALAPPDATA%/Programs/OpenAI/Codex/bin`，并兼容 Windows npm 的 `.cmd` 启动脚本。设置中的“自动检测安装与登录”显示工具版本和 Codex 登录状态；“刷新 CLI 模型目录”读取 Codex 的 `debug models` 或 OpenCode 的 `models --verbose --refresh`，支持搜索模型、显示窗口和思考选项。目录不代表每个型号都获账号授权，测试连接会发送简短消息验证所选模型。

API、Codex 和 OpenCode 分别保留自己的模型和思考选项；两个 CLI 还分别保存路径与模型目录。模型未选择时刷新会选目录首项，也可手动选择或点击“使用工具默认模型”。如果工具默认配置指向账号不支持的型号，也会返回模型权限错误，而不会误报为未安装。安装路径、登录、账号模型和代理网络失败分别显示明确提示。

AI 设置中的有效改动统一自动保存，文字输入短暂停顿后写入；模型选择、工具默认模型、连接配置和响应偏好遵循同一规则，无需点击保存。顶部显示自动保存状态，底部使用“关闭”，不再以“取消”暗示撤销。关闭按钮、窗口外点击和返回操作会先处理待保存改动；输入无效或保存失败时明确提示，可修正、重试，或明确放弃未保存更改后关闭。选择模型前后主动释放输入焦点，返回聊天后保持键盘收起；成功保存不弹底部通知。已成功检测的 CLI 版本与登录状态短暂复用，避免检测后立即测试连接时重复启动检查程序。

CLI 模式依赖用户本机版本、登录及模型配置；不能凭本地模拟测试确认用户账号可用。Codex 的只读沙箱用于限制写入，仍应结合本机 CLI 权限、插件和配置理解其能力边界。

开发者模式保存应用传入 CLI 的准确提问文本和 API 请求参数快照，展示协议、实际使用的思考及长度参数；API 密钥不在快照中。Codex 还显示应用设置的 threadOptions 与 turnOptions，包括基础提示、开发者提示及摘要选项；运行中的管理消息和 CLI 自身内部提示不属于该文本快照。原生 API 将系统提示提取到对应字段，并合并连续同角色消息。OpenCode 的独立 agent 使用可编辑的 CLI 提示词。CLI 预算计入 JSON 转义与应用附加内容，但 CLI 自身提示和工具定义的全部开销无法事前精确估算；实际统计以返回值为准。Windows 终止会清理本次子进程树。

## 2026-10-12 数学公式渲染

聊天正文、思考过程与带公式的用户提问接入 [flutter_math_fork](https://github.com/simpleclub/flutter_math)（Apache-2.0）。它使用 KaTeX 风格的 TeX 解析及 Flutter 原生排版；没有 WebView、JavaScript、网络公式服务或系统 LaTeX 依赖，五种原生平台共用相同实现。Markdown 接入参考了 [flutter_markdown_plus_latex](https://github.com/foresightmobile/flutter_markdown_plus_latex) 的语法与 element-builder 扩展方式，本项目自行实现边界识别、缓存和回退。

- 支持 `$…$`、`\(…\)` 行内公式，`$$…$$`、`\[…\]` 独立公式，以及 `math` / `latex` / `tex` 围栏。支持常见分数、根号、上下标、积分、极限、求和、矩阵、分段函数与 AMS 多行推导。
- 公式在 Markdown AST 中识别，代码、转义美元符号及普通价格不会被全局替换。表格、列表和引用里的行内公式也可使用。
- 独立公式靠左对齐，只留适量上下间距，没有“公式”标题、底色、边框或常驻按钮；数学代码围栏也采用相同样式。正文、行内与独立公式共享 Flutter `SelectionArea` 原生选区：鼠标拖选、触屏长按及选区手柄、系统复制菜单、Ctrl/Cmd+C 与全选均可使用。公式作为完整结构选中并高亮，复制返回原始 LaTeX（保留原始分隔符、环境与换行），可与前后文字连续选择；不复制内部字形顺序或占位符。宽公式保持清晰字号并横向滚动，系统字体放大仍生效，窗口缩放不会重新解析已有公式。
- KaTeX 字体没有中文字形，中文注释节点使用已随应用打包的思源黑体，并保持分数、下标等位置的 TeX 字号。这个小型 AST 适配器集中在 `ai_math_fonts.dart`；升级渲染器时需复跑中文字体测试。
- 未闭合的流式公式先显示接收状态与原文，闭合后才解析；数学代码围栏在本次回复完成后排版。非法、不支持或过度复杂的公式显示说明并保留可复制原文，不把解析异常直接抛进聊天界面。
- 解析树采用 LRU 缓存，最多 128 项及 65,536 个源文本字符，成功和失败结果均缓存。单个公式限定 4,096 字符、1,024 个非空白字符、32 层括号与 32 个换行，宏展开最多 100 次；这些限制用于保护低配置设备。使用较轻的 `Math` 而不是整式选择编辑器，公式有独立重绘边界。

## 2026-10-13 块状公式自动换行

Markdown 通过宽度作用域传递当前消息区域的宽度，即使复用已解析的组件，侧栏缩放仍会更新公式宽度。块状公式进一步读取所在列表、引用等容器的实际约束，避免使用无限宽或旧宽度而越过页面右侧。

参考 [flutter_math_fork 的 TeX 断行文档](https://github.com/vurilo/flutter_math_fork/blob/master/doc/line_breaking.md)，独立公式和数学围栏在顶层关系符、二元运算符及允许断行的位置分段，再按可用宽度排列；同一行按数学基线对齐，保留运算符间距及系统字体缩放。分数内部、矩阵、配对定界符和禁止断行的结构保持完整；过宽的不可拆结构由公式内部横向滚动显示。选区仍把整式视为一个单位，复制保留原始 LaTeX。宽度变化仅重新排版，不重新解析源文。

## 2026-10-14 优化公式断点与续行

针对断点生硬、续行不清楚的问题，块状公式改为在顶层关系符或二元运算符之前分段，运算符与其后的项一起进入续行，避免行尾悬挂加号或等号。断点识别区分二元运算与一元正负号，保护普通括号、可伸缩定界符、矩阵、分数及显式多行推导，并遵守相邻空白中的禁止断行标记。

排版先保证尽量少的行数，再用动态规划比较关系符、加减号及乘除类断点和各行留白，减少短尾行。续行使用随字体缩放的悬挂缩进和行间距，同一行保持数学基线对齐；单个宽项若仅因缩进而超宽，会取消该行缩进。不可拆的超宽结构仍能横向滚动。

分段继续使用原始 AST；每个叶节点保留原来的透明字体/颜色样式，避免上游范围裁剪在同一个样式包装内重复内容。不可见的前文原子保留二元运算符的 TeX 间距，不改变复制得到的 LaTeX 源文。窗口缩放仍复用解析缓存。
