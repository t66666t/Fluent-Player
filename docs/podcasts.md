# 社区版播客

社区版恢复完整版的播客页面和核心逻辑，复用已有播放器、媒体库、字幕、转录、学习、导出与同步。应用身份和数据目录仍与完整版独立，不读取私有项目文件。

## 入口与页面

- 首页“播客”：订阅、最新更新、继续收听、收藏、下载和队列。
- 导入菜单“订阅或导入播客”：搜索频道或粘贴 RSS/Apple 分享链接，预览后订阅。
- 频道页：简介、搜索、筛选、分季、手动排序、多选、批量下载及频道设置。窄屏上下布局，宽屏左右分栏。
- 播客设置：更新、通知、播放、缓存、离线下载、搜索与备份；频道支持继承全局或单独覆盖。
- 音频使用共享音乐播放器，视频使用普通播放器，共用会话、字幕与播放队列。节目简介、选集、收藏、下载、倍速、睡眠定时和学习沿用现有入口。

订阅可以分组到可嵌套的播客合集，频道卡片也可放入媒体库文件夹。支持多选、拖动、重命名和隐藏文件夹里的频道卡片；隐藏卡片保留订阅和原位置。取消订阅保留已有下载和收听记录。

## 搜索与来源

默认搜索 Apple Podcasts，可选择地区；Podcast Index 需要配置自己的凭据。支持 RSS 2.0、Atom、Apple Podcasts 分享链接，以及网页明确提供的 RSS/Atom 链接。搜索预览不自动创建订阅或收听记录。

媒体必须来自已解析订阅源提供的 enclosure。小宇宙等网页只有隐藏 JSON 或 og:audio/og:video 时不提取音视频；不绕过登录、付费或 DRM，不恢复发布者已撤下的节目。旧缺少 RSS 证据的记录保留本地文件与进度，联网前需刷新有效订阅源。

网盘、视频网站、内置浏览器、网页媒体提取及网站剪贴板监听继续停用。普通远程 URL 不能借用播客身份进入播放或处理队列。

公开 RSS 不等于允许任意再分发。离线保存、媒体导出、转录和分享仍应遵守内容许可及适用规则；代码的 GPL 许可不替节目内容授权。

## 播放与收听记录

从频道或筛选结果播放时保存当时的队列快照，后续浏览和排序不会收缩正在播放的队列；切集、失败重试和恢复启动沿用保存的队列。已听标记与续播位置分别记录。连续播放、倍速和频道覆盖沿用完整版逻辑。

音频与视频使用原生播放时钟；首次加载、缓冲和跳转等待时字幕不自行前进。已有官方 SRT/VTT/Podcasting 2.0 JSON 文字稿和章节可通过原有字幕入口使用。

## 缓存、下载和后台刷新

在线播放按实际读取的数据建立缓存，默认上限 1 GB、保留 7 天。完整离线下载单独管理，默认并发 2、容量 5 GB；支持暂停、继续、取消、重试、批量和频道自动下载。播放、下载和转录准备共用媒体缓存，续传验证来源版本及字节范围。

清理临时缓存保留完整下载、未完成任务和正在使用的资源；删除下载不删除收听进度。HTTP 音视频文件支持完整离线下载；HLS 可在线播放，不会把清单误标为完整节目，DASH 需选择对应文件版本。

后台刷新、自动下载、通知、全局暂停与保留规则按用户设置执行。Android/iOS 仍受系统后台调度和通知权限约束。

## 字幕生成与学习

没有官方文字稿时，在播放器打开原有 AI 字幕面板，确认后开始。先准备完整本地资源，再按原流程切片并使用所选本地模型或在线识别服务；在线服务会上传识别所需音频。关闭面板不会取消已确认的任务，结果回存对应节目。任务暂停、取消、重试和字幕输出继续使用既有流程。

未修改模型清单、模型默认项、兼容性基线或本地推理运行时。网盘、网站媒体和未确认来源不能通过转录任务重新获取。

## 备份与导出

OPML 导入导出保存订阅源；JSON 和 FluentPack 可保留频道、进度、收藏与设置，FluentPack 不包含播客节目音视频。ZIP 的频道导出使用 OPML/引用，同一文件夹中的普通本地文件仍按文件导出。已有本地媒体保留原本打包行为。

引用或 OPML 备份不包含节目媒体，也不代表再分发音频的授权。导入旧数据保留历史身份、收听记录与用户文件，不自动删除缺少 RSS 证据的记录。

## 快捷键与验证

桌面总览支持 S 搜索、I 导入、P 设置、R 刷新、空格播放/暂停；频道支持 S 搜索、P 设置、R 刷新、B 多选、A 切换全选、Ctrl/Command+A 全选。F/F11 全屏，Esc 优先退出输入、搜索或多选。输入框、弹窗及隐藏页面保留自身按键行为。

本次构建、受控 HTTP/缓存/播放会话测试、两小时音频准备和回归结果见 [社区版验证记录](community-verification.md)。构建和模拟平台测试不代表物理设备播放、原生模型推理或后台系统调度已验收。

## 首次在线播放的连接恢复

未缓存节目的元数据探测和媒体 Range 请求在连接中断、响应头超时等暂时故障后，会在同一次播放内重连一次。自动选路需要切换备用线路时，本次请求立即使用新线路；用户指定的统一线路继续保持原选择。播放请求每次连接和等待响应头合用 8 秒，给原生播放器既有的 20 秒初始化期限留出恢复时间。离线下载继续使用原来的较长网络期限。403、404、429 和来源服务器的 502 不触发线路切换或立即重试。

停止过时的播放读取会同时取消尚未收到响应头的探测；取消不会被误判为网络线路故障。转发失败发生在媒体响应发送前时，返回完整的空正文 502，并清除原来的媒体长度和 Content-Range，避免原生播放器一直等候不可能到达的数据。既有缓存分段、下载进度和节目来源校验继续保留。

`test/podcast_playback_recovery_test.dart` 覆盖首次探测/Range 失败、响应头停滞、备用线路重连、有限失败、取消及来源 HTTP 拒绝。它与既有媒体存储、跳转、网络、传输恢复和并行下载测试合计 59 项，在 Windows 上通过。原生检查使用临时数据库、临时缓存和本机生成的 MP3，故意中断第一次连接，验证真实解码器一次播放即可启动，并能暂停和继续：

```powershell
flutter test integration_test/podcast_startup_native_test.dart -d windows --no-pub --dart-define=PODCAST_STARTUP_NATIVE_TEST=true
```

可额外传入 `PODCAST_STARTUP_FEED` 和 `PODCAST_STARTUP_TITLE` 两个 dart-define，使用发布者 RSS 中匹配标题的节目复测；未指定标题时选第 4 集。测试会访问该公开来源，但不使用用户的订阅数据库或已有媒体缓存。其他平台仍需各自的原生设备验证。

设备同步仅在社区版设备之间进行：同步订阅引用和逐集收听进度，不传节目音视频、收藏或本机设置。目标设备没有订阅时会创建订阅引用，不因此下载节目。详见 [设备同步说明](progress-sync.md)。
