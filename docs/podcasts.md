# 播客订阅、播放与离线

桌面播客总览、频道、搜索与导入、节目预览和设置页共用 `F` / `F11` 切换全屏；`Esc` 先退出当前输入、搜索或多选状态，再退出全屏或返回上一页。页面被弹窗或其他页面盖住后不响应按键，切换全屏导致焦点丢失时仍可继续操作。在输入框中，字母和 `Ctrl` / `Command` 组合键保留文字编辑行为。

总览支持 `S` 搜索、`I` 导入、`P` 设置、`R` 检查更新和空格播放/暂停当前会话；频道支持 `S` 搜索节目、`P` 频道设置、`R` 刷新、`B` 多选、`A` 切换全选，以及 `Ctrl/Command+A` 全选当前筛选结果。搜索与导入页使用 `S` 聚焦在线搜索、`I` 聚焦链接导入、`P` 打开播客设置，输入框中的回车执行搜索或解析。单集预览使用空格试听/暂停，左右方向键跳转 5 秒。

总览的「订阅」支持长按或右键进入多选、勾选滑动连选，以及 `B` 多选、`A` 切换全选、`Ctrl/Command+A` 全选当前文件夹；`Esc` 和返回键先退出多选，再返回上一级。新建合集使用首页原有的可展开操作按钮、实验布局侧栏入口和 `N` 快捷键，根据当前页面保存到播客根目录或正在浏览的播客合集；播客页不再增加独立的新建按钮。可以重命名、嵌套和解散播客合集。在合集内搜索或导入的新订阅会在返回总览时放入当前播客合集。分组和排序保存在本机播客数据库，独立于媒体库文件夹中频道卡片的位置，也不改变节目顺序或播放队列。

订阅卡片复用文件夹页的拖动门槛、长按时间、边缘自动滚动、投放高亮和震动开关。多选直接接入首页原有的顶部投放区和底部工具栏，包括相同的尺寸、颜色、圆角和退出动画；频道的取消订阅、合集的解散都使用红色危险操作，底部保留加入播放列表、导出和单项重命名，不再增加「移动到」按钮。选中时 `N` 重命名，`R` 移除，`E` 导出，`U` 移回上一级。拖动已选卡片移动整个选区，拖动未选卡片只移动该项；直接放到卡片上调整顺序，在合集上停留约 300 毫秒后松手则移入合集。下级合集的顶部提供返回上一级的投放区。解散合集只把内容移回上一级，取消订阅需要单独确认，保留下载和收听进度。刷新新增的订阅不会自动加入已有选区。加入播放列表会展开所选频道和合集中的节目，复用统一的去重与可取消追加流程，不开始播放，也不把整份节目目录写入媒体库。

播客封面、连播和频道浏览与媒体库共用一套能力。封面原始文件只下载一次，不同尺寸只影响解码；连续播放和默认倍速在没有单独设置时跟随软件，显式关闭或数值会保留。频道内节目的选择、手动顺序和刷新不会改写正在播放的队列，也不会为了浏览而把整频道写进主媒体库。

启动时，本地频道信息和封面缓存与媒体库并行准备，卡片无需等待播放会话、通知或后台刷新服务完成初始化。已有本地封面在首次构建时直接使用，不额外等待淡入动画；缓存过期时仍先显示旧图，再检查更新。

连续播放在确认本集结束后，按当前播放队列顺序切换到下一集。频道独立设置优先于播客全局和软件设置；队列没有下一集且未开启列表循环，或睡眠定时器要求停止时，会停在本集。2026-10-25 修复了底层先暂停、后发布结束位置时漏掉结束事件的问题，避免连播开启后仍停住。

“已听”在确认播放结束时自动设置，也可以手动标记；续播位置独立记录本次听到哪里。重新播放已听节目会从头开始，之后的几秒进度、切换节目和重新进入应用均保留已听标记。手动标为未听或同步明确的未听更改可以取消标记。修复了切集时把上一集写成未听，以及重播达到继续收听门槛后清除媒体库完成状态的问题。

滑动超过单集行的点击容差后，松手不再触发打开节目，避免短促上滑被误认为点击而用播放页覆盖迷你卡片。

频道页现有的单集和侧栏滚动条在有可滚动内容时常驻显示，统一使用 10 个逻辑像素宽、至少 56 个逻辑像素长的滑块。安卓、iOS 和桌面均可直接拖动，无需长按；触摸沿用扩大的命中范围，并关闭桌面自动叠加的重复滚动条。

导出包含新的顺序和显式设置时使用 FluentPack 格式 4。旧的格式 2、格式 3 仍可导入。旧版本软件会拒绝格式 4，而不是悄悄丢掉顺序和继承关系。频道内「手动顺序」保存在播客数据库，刷新只把新节目插到前面。总览里的订阅顺序不移动文件夹里的卡片。

媒体库的「播客」入口提供订阅、最新更新、继续收听、收藏、下载和队列。导入菜单也可以进入「订阅或导入播客」。每个频道对应一张可放入文件夹的播客卡片；频道内部由播客页管理，不能导入普通文件或创建文件夹。

首页、文件夹和播客订阅页的频道卡片显示作者名，没有作者时显示「播客频道」，不显示项目数或未听集数。文件夹中的卡片菜单可选「不在此页面显示」，保留订阅、原来的文件夹位置和收听记录；隐藏状态会保存。播客订阅页的卡片右下角提供「更新」和「删除」，仅已隐藏的卡片显示「添加到文件夹页面」，可恢复原来的位置。「删除」取消订阅并把卡片移入回收站，保留已有下载。

频道详情按窗口形状调整布局：手机使用紧凑封面信息区，平板和大屏竖屏使用横向头图，宽屏横屏使用频道信息与节目列表的左右分栏。两栏可独立滚动，窗口缩窄后保留搜索和筛选。节目列表采用标题、摘要与时长的文字布局，不重复堆放频道封面。搜索输入大约每 200 毫秒查询一次，清空会立刻生效。下载字节进度只刷新对应节目的进度，不重新扫描整份目录。

正在播放的队列以播放列表为准。从频道或筛选结果开始播放时，按当时的节目顺序建立一份快照；在这份快照里切集、暂停后继续或失败后重试，只改目标，不把队列收成一集。只有明确的单集播放才会换成一集。总览里的队列展示同一份播放列表中的播客节目，重排时保留夹在中间的本地文件。下次启动会按保存的条目恢复这份队列；某一集已经不在目录里时跳过它，而不是清空其余节目。封面调度按播放中、可见、取色、预取的顺序执行，滑出屏幕的请求会取消，单集图还没到时先显示已经缓存的频道图。

设置页采用分组导航，适合宽屏的侧边栏和窄屏的横向分类；单项仍可恢复继承。频道与节目菜单在窄屏呈现为底部操作面板，在宽屏呈现为分组菜单，下载、收听与取消订阅使用清晰的操作分组。

音频播客直接复用 Music Player Screen，共享布局、封面背景、字幕阅读和控制栏；后续音乐播放页的调整会自动应用到播客。控制栏的「选集」打开现有播放器的选集面板，并定位当前节目。横屏左上角使用透明、无边框的图标按钮，使用独立的上、左边距，不随进度条宽度移动，按钮按关闭、全屏（桌面）、更多、定时、简介排序；所有按钮等高并沿同一中心线排列；其中「节目简介」按钮提供简介入口，收起时不显示正文；展开后在整组按钮下方、沿按钮组左边缘展开圆角模糊背景浮层，间距为 4，按内容自然增高，超过屏幕可用高度时正文在窗口内滚动，顶部收起按钮固定；支持收起按钮、点击外部和 Esc 关闭，没有整页遮罩。横屏简介不参与文字稿的布局计算，展开、收起均保留原有滚动空间和位置。竖屏保留原有标题、右侧按钮与简介布局。收藏、下载、倍速和学习入口收在节目操作中。播放页覆盖媒体库和迷你播放器，返回后恢复迷你卡片。

选集面板与迷你播放器的队列直接读取统一封面仓库，优先显示单集图，缺失或加载失败时回退到频道图。已经缓存的频道图会立刻显示，单集图成功后再换上。轻量队列记录即使没有本地封面路径也可以显示图片；可见条目按需加载，与频道页共用原图和磁盘缓存，不逐集复制频道封面。打开选集时按当前节目定位，手指或指针拖动后不再把列表拉回去。

横屏标题区域使用面板的可用宽度，优先换行；过长的标题与作者信息缓慢往返滚动，也可手动滑动查看。减少动画模式下关闭自动滚动。

视频播客默认进入普通播放器；音频也可以通过节目操作切换到普通播放器，保持同一播放会话。播放页面选择集中在 `PodcastPlayerPage`，无需维护独立的播客播放界面。

播客进度、逐字高亮和字幕跟随以原生播放时钟为准。首次加载、缓冲和跳转等待期间停止推进；缓冲结束标记本身不会启动字幕，必须等真实播放位置继续变化。未收到缓冲事件时也只允许短时间插值，避免网络等待累积成字幕偏移；恢复后重新对齐实际音频位置。普通媒体沿用原有平滑时间轴。

## 导入与搜索

- 默认搜索 Apple Podcasts，可选择地区；在“播客设置 → 搜索与备份 → Podcast Index 搜索凭据”中可配置自己的凭据。
- 支持 RSS 2.0、Atom、Apple Podcasts 分享链接、网页公开 RSS 发现，以及 OPML 导入导出。
- 小宇宙等网页如果只公开一集的媒体地址，会明确显示「导入这一集」；只有确认持续更新的订阅源才显示「订阅整个频道」。
- OPML 导入部分失败时保留已成功的频道，并列出失败地址。JSON 备份和 FluentPack 可以保留进度、收藏与设置。
- 支持源提供的季数、集数、章节 JSON，以及 SRT/VTT/Podcasting 2.0 JSON 时间轴文字稿；字幕与 AI 学习复用现有播放会话。没有文字稿时可使用原有转录功能。

搜索结果的预览加载会对临时连接中断和临时服务器错误最多重试两次，整次加载（含网络检测、跳转和重试）最多等待 20 秒；明确未联网时直接提示连接网络，不反复请求。失败后可以直接重新加载当前播客或返回原搜索结果。403、404、无效订阅源和证书错误不会自动重试，来源要求的 Retry-After 等待不会被缩短。离开预览、取消或切换频道会中止这次加载，迟到的响应不能覆盖新的页面。

本次运行中最近成功的预览有独立的内存缓存，最多 6 个地址、合计约 8 MiB 文本、有效期 6 小时；不存音视频文件，不创建订阅或播放记录。再次进入时先显示缓存并检查更新，刷新失败仍可阅读旧内容并显示提示；应用重新启动后不保留这些预览缓存。

频道只显示来源公开提供的节目与历史分页，不恢复已被发行方撤下的内容，也不解析需要平台付费或登录的封闭内容。

频道菜单的「频道链接」提供频道主页和 RSS；节目菜单与播放器操作中的链接入口还会显示单集原始网页和音视频地址。链接可以查看、选择、复制或在浏览器打开，复制结果直接显示在按钮上。

## 缓存和下载

「在线播放缓存」保存实际请求的数据，默认上限 1 GB、最长保留 7 天。部分缓存明确区别于完整离线下载。播放器和下载任务共用同一份媒体分段，续传会检查范围、长度与来源版本；不支持 Range 的服务器会采用兼容读取方式。

在线播放按目标位置发送 HTTP Range，接收到数据就交给播放器，无需等满 1 MB 缓存块。跳转时在播放器发出新位置请求后停止旧位置读取，后台下载不会占住整个节目的读取锁。元数据只探测一个字节；已解析的最终媒体地址在本机短期复用，地址失效或返回错误范围时重新解析原始链接。

音频播客使用较短的预读窗口，并启用 MP3 的 Xing/VBRI/码率快速定位，避免为了精确建立索引而扫描前面几十分钟。来源缺少定位索引时位置可能存在少量误差；来源完全不支持 Range 时仍受其读取能力限制。这些策略只作用于播客播放。

「下载完整节目」支持音频和视频、暂停、继续、取消、重试、批量下载及频道自动下载。直接使用当前可用网络，包括手机流量、Wi-Fi 和有线网络；并发为 2，离线容量为 5 GB。调度在有空闲名额时立刻补位，不会等整批慢任务结束。同一节目的播放、手动下载和 AI 准备共用一条任务；取消最后一个 AI 准备会暂停这次补齐，不会取消用户已经保留的下载。来源提供独立音频与视频版本时，可以分别选择；正在下载的版本不会被静默换成另一个。

播放与下载使用独立的 HTTP 连接池，下载先验证一个最多 4 MiB 的窗口；确认 Range、总长度和版本校验信息后，每集最多同时下载两个 16 MiB 连续窗口。全局最多 4 条下载连接，同一下载域名最多 3 条；SQLite 租约让前后台任务共用上限。磁盘仍按 1 MiB 分段保存，已缓存或正在被播放读取的分段不会重复下载。不支持 Range 的来源直接保存第一次响应，不先读完丢弃再重下。播放器暂停读取不会拖住共享下载。取消能中断等待名额、连接和响应头、正文读取及退避，保留已验证分段。进度合并并行窗口的有效字节，避免倒退或重复计数；最近几秒的速度归零后不继续显示旧 ETA。5 秒没有数据会显示等待原因，正文连续 30 秒无响应后自动重试缺少的部分。

播放缓存、未完成下载、完整下载分别统计。清理临时缓存不会删除完整下载、未完成的下载任务、当前使用中的文件或明确保留的文件。删除下载不删除收听进度。桌面导出直接复制文件，手机使用系统分享文件，避免将大视频一次读进内存。

当前完整离线下载针对 HTTP 音视频文件。HLS 可以通过统一网络入口在线播放，但分段清单不会被误标成已完整下载；DASH 清单需要选择对应音频文件或 MP4 版本。

导出和转录需要完整文件时，合并结果会取代已有分段，后续播放直接读取该文件，避免长期占用两份空间；转录过程中会保护所用媒体。

## AI 字幕生成

播客先准备整集本地资源，再在本地切分并上传识别。没有官方文字稿时，播放页可以直接打开现有 AI 字幕面板，开始按钮仍由用户确认，不会一进入就下载整集。关闭面板后，当前节目生成完成仍会加载字幕；其他节目的结果只入库。下载阶段的等待不会被说成识别超时。已有完整下载或完整播放缓存直接复用；部分缓存只补齐缺少的分段。准备音频与普通离线下载共用同一条持久化任务，展示已复用大小、已下载/总大小、近期速度和预计剩余时间，不增加悬浮通知。全局暂停和下载容量仍按播客设置执行。

订阅更新、在线播放、手动下载、自动下载和字幕生成均使用当前可用网络，不提供按 Wi-Fi 或手机流量限制连接的设置。以实际音频请求判断连接是否可用，VPN、未知网络或系统网络检测异常不会单独挡住下载。旧版本保存的网络类型限制不再生效，已有等待网络的任务会重新进入普通下载队列。

为字幕生成补齐的媒体默认登记为完整下载，播放、下一次转录、导出都复用它；不会在转录结束时删除。完整缓存若已存在但离线下载预算已满，仍可以直接用于转录，并明确按缓存规则保留。合并文件取代分段，只保留一份媒体，临时清理不会误删正在转录的资源。

连续播放自动进入的节目可能只有播放队列中的轻量条目，尚未登记到媒体库。字幕任务现在直接保存所选媒体的来源快照，包含播客、B 站或网盘的原始来源标识；切集或重启不会把任务改到下一集，也不要求先返回频道重新打开。转录准备时只登记实际使用的那一集，字幕和译文继续按原规则保存，不会将整个播放队列写进媒体库。旧播客任务缺少来源时可从目录补回，旧失败任务也能在当前媒体上直接重试。

音轨检查区分在线音频尚未准备、本地文件不存在、空文件与确实没有音轨。探测失败、空流信息、未知流或仅返回封面图片时，会让现有的有界音频解码流程进一步确认，避免仅因元数据缺失就误报“没有音轨”。直接 HTTP 音频按在线输入处理，不按本地文件是否存在判断音轨。

播客与普通媒体统一按约 60 分钟分段，段间保留 2 秒重叠，短尾段按统一规则合并，单段可到约 70 分钟。旧的已完成 15 分钟片段仍可继续复用。下载临时断网会重试缺少的分段，上传临时断网优先重试失败的上传块。每个已提交的识别任务编号随源文件和时间段保存，暂停、进程中断或结果查询失败后继续查询原任务；服务端明确说明任务过期时才重新提交本地音频。已完成的字幕片段不重复识别。

每轮获取识别结果最多等待 5 分钟，包含请求、网络重试和退避。没有明确原因的 HTTP 412 / 业务码 -412 显示“请求被拒绝，原因尚未确认”，只等待 3 秒后重查一次；不会仅凭 412 就认定访问过于频繁。429 或明确的频率限制、服务器报告的安全拦截分别提示，默认按 15、30、60、90 秒退避；服务端提供 Retry-After 时遵守其最短等待时间，超过本轮时限则保留任务供稍后重试。正常查询仍从约 2 秒间隔开始，外层不会重新开启已耗尽的查询重试。

错误提示保留 HTTP 状态、业务码和经过脱敏的服务器错误摘要，最近一次查询错误随任务检查点保存。语音识别的直连请求使用原生直连并复用连接，网络设置变化时新请求更换连接，旧请求尽量读完；系统代理和自定义代理仍按用户设置选路。请求携带明确的 JSON Accept 与 Cache-Control: no-cache。上述调整用于修正错误判断和减少连接开销，不能据此断言某次 412 的实际原因。

HTTP 状态码含义见 [HTTP 412 标准定义](https://www.rfc-editor.org/rfc/rfc9110.html#name-412-precondition-failed)。

恢复焦点、收起控制中心和最小化恢复不会主动断开下载。真正切换网络后，已建立的连接尽量完成，新连接按播客自动连接策略选路；短暂失败按 1、2、4、8、15、30 秒退避续取缺少的缓存。手机真正后台期间不耗尽重试次数，返回前台后继续；主动暂停或取消仍立即生效。播放中的可验证片段也能从缺失字节续接，不把不同版本的媒体拼在一起。

## 数据和设备迁移

目录、状态、设置和任务保存在数据目录下的 `podcasts/podcasts.sqlite`，媒体保存在 `podcasts/media`；播放时才按需要建立现有媒体库的兼容记录。

手动导出 FluentPack 或 ZIP 时，播客只迁移频道或单集卡片及来源链接，不携带已下载节目，即使以前开启过「打包时包含完整下载」也不会在手动导出时复制节目媒体。单独选择一集不会打包其他集的下载。FluentPack 保留订阅、进度、收藏和可共享设置；ZIP 提供订阅链接及卡片引用清单，可重新导入，导回时不会覆盖已有播客设置和收听进度。

含播客状态的 FluentPack 使用格式 4，携带哔哩哔哩完整缓存时使用格式 5，携带网盘缓存或逐词字幕时间文件时使用格式 6；旧包继续可导入。现有文件夹传输及加密设备同步保留原规则，主动开启「打包时包含完整下载」可用于原文件夹传输；它与手动导出卡片分开处理。路径、网络权限、存储预算和搜索凭据不在设备之间复制。

Windows x64 Profile 的 2,000 集场景实际运行了 1,800 次连续往返拖动更新，记录 3,561 帧，屏幕报告 120 Hz。UI 帧耗时 p50 / p95 / p99 为 4.917 / 9.178 / 11.602 ms；超过 16.667 ms 的帧为 1 / 3,561（0.028%）。超过 120 Hz 的 8.333 ms 预算仍有 296 帧（8.31%），因此不宣称所有帧达到 120 fps。当前测试环境返回的 raster 时间接近零，不能据此判断实际 GPU 栅格耗时。原始记录为 `windows-profile-final.json`，CPU 栈为 `cpu-samples.json.gz` / `cpu-hotspots.txt`，均在上述 artifacts 目录。
