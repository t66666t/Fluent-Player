# 本地字幕流式工作流

范围为当前四种本地 ASR、所有已有增强/加速路径，以及 Hy-MT2、Qwen3、AI API 和普通字幕翻译服务。这里的“流式”指完成一个稳定字幕批次便追加显示，并非将所有离线模型改造成逐词在线识别器。新任务使用 30 秒音频块、2 秒重叠，旧断点保留已记录的块长度。

## 云端转录与本地翻译

云端 ASR 配合本地字幕翻译也使用同一套流式发布、恢复和播放接口。原文识别完成后直接作为完整主字幕；第一批译文提交后自动选为副字幕，后续只追加译文快照，不重载整份 SRT、不缩短主字幕、不移动播放时间。第一批译文尚未就绪时保留原有副字幕。`primaryComplete` 标记使日志存储保留原文文件及词级时间，恢复时只补写译文。

发布窗口默认最多 8 条字幕，并同时限制为 800 个 Unicode 字符、30 秒字幕时间跨度；条数沿用任务冻结的本地翻译设置（1–12 条）。单条超长字幕保持完整，由既有翻译器分片处理。原生请求仍受设备资源预算、格式校验与补译机制约束。整个翻译流复用同一个 `LocalTranslationSession`；发布、进度刷新与模型生命周期分离，内存允许时不因下一批发布而重新加载权重，资源紧张时沿用现有释放策略。

每批原文与译文的编号和时间对应，译文先落盘再发更新。失败或停止保留已提交译文及中断批次中已校验的结果，继续生成复用云端原文，只处理缺失条目；任务配置和发布边界保持冻结。用户在识别、翻译或暂停期间更改主副字幕、交换顺序或清空字幕，会保存该代次的选择保护，继续生成及重启后均不自动抢回选择；仍被选中的生成轨道继续追加。横竖屏自动恢复与手动选择使用不同调用标记，另一个媒体的字幕选择不会阻止原媒体的生成结果。

播放器完成通知只提示完成，不再通过面板回调重新加载流式文件。列表、分段文章、连续文章支持完整原文不变而译文增长的更新；选文期间冻结当前显示和复制内容，退出选文后补齐译文。连续文章重排期间保留上一份画面，再按可见句子中的文字位置恢复阅读视角。尾部提示显示“正在翻译”。

Windows CPU 的真实 Hy-MT2 验证使用六条英文、每批两条，在 8 GiB 总内存 / 4 GiB 可用内存的准入测试条件下分别提交 2、4、6 条译文；主字幕字节保持不变。首次提交为 5,280 毫秒，总计 9,540 毫秒，模型加载 1 次、复用 2 次。该结果是本机样本，记录见 `.artifacts/model-center/cloud-local-translation-native-results.json` 与同名前缀的原生测试日志。对应测试入口为 `cloud_local_translation_native_test.dart`，通过 `CLOUD_LOCAL_NATIVE=true` 开启；Windows Flutter 原生测试使用下文相同的 `LLAMADART_NATIVE_LIB_DIR` 设置。

本轮 190 项相关回归通过，补充词级时间保留后 10 项云端与本地组合测试再次通过，17 个相关文件的静态分析无问题。覆盖首次挂载、保留旧副字幕到首批完成、识别期间手选、仅更换主字幕、清空字幕、停止续传、进程重启、日志尾部修复、完成通知、三种文稿模式的阅读与选文，以及既有本地流式和音乐文稿回归。记录为 `.artifacts/model-center/cloud-local-translation-{final-regression,targeted,analysis}.log`。未使用真实收费云端识别接口，云端识别由测试输入替代；本地翻译另有上述真实 CPU 验证。

## 处理与提交

`ModelTranscriptionRunner.run` 的可等待 `onStableBatch` 携带固定字幕编号、绝对时间、音频处理位置和推理预约，原有完整返回值仍可使用。`StreamingSubtitleAssembler` 仅保留重叠区及可能延续的末尾组，处理跨块去重后复用既有自然分句；已发布部分不再重组。文件末尾统一收尾。

`LocalTranscriptionStream` 按顺序翻译并提交。自动翻译方向在首个稳定批次确定并写入日志；后续批次沿用，已发布前文进入上下文。AI API 继续使用原批量、并发、反思、术语、格式修复与限流机制；普通服务继续使用原接口与节流。严格模式不把失败原文当译文，失败前已校验的译文保留，续传只补缺失项。失败批次之后的内容不能越过它发布。

“生成字幕的标点”是首页独立设置，默认去掉语末句号和逗号，也可单独选择只去掉语末句号。已有全局选择与已冻结任务保留原规则。任务冻结其输出规则，在翻译之后对本批原文和译文统一清理，再保存并成对发布；内部识别、分句及待补译断点仍保留原始标点。日志每批额外保留最多两条原始前文，恢复后翻译继续使用完整上下文。在线转录路径也清理实际输出，在任务内部保留原始翻译输入；翻译服务在首次写入结果前应用输出规则，完成通知和导出读取同一结果。规则不加入识别指纹，不导致原生识别断点失效；旧冻结任务没有该字段时保留全部标点，重新生成才切换规则。清理仅处理新增字幕，无逐帧处理或全文重复扫描。

后续性能优化将语末查找改为逆向字素遍历，删除区间用于词级时间映射，译文直接清理字符串；没有新增模型调度锁、逐段完整性扫描或全文比较。在线整份结果的解析、清理、SRT 与伴随时间编码采用大小阈值决定是否进入后台，字幕对象按 128 条交接并等待确认。后台纯计算结束后，由原任务再次检查取消，再写入与通知；停止时不会因后台完成而发出迟到的成功通知。原始翻译输入、配置冻结、流式成对提交与旧断点保持原规则。具体阈值、Windows AOT 测量及适用范围见[模型中心](model-center.md)。

本地翻译借用 ASR 的有效推理预约，在识别/增强边界交接，避免回调再次排队造成死锁。识别和增强可在不同原生工作线程并行；翻译等待当前原生调用结束，独占本批推理时间，再放行后续识别与增强。按设备可用内存决定流水线及模型复用；不足时沿用原生释放策略。网络翻译可以与后续识别重叠，待发布块最多积压两个；原生双阶段流水线已有两块上限时直接等待发布，避免叠加两套缓冲。

源字幕与译文先追加、刷新到磁盘，再记录同一个批次提交及两个字节偏移，最后发布一次成对更新。停止会立即进入“正在停止”、取消网络和预取，并等待不可抢占的原生调用及文件写入结束。已提交结果保留，未提交内容从已保存识别/翻译断点补做。只有整项任务完成后才发送完成通知、自动移除或执行外部视频字幕内嵌。

日志记录也维护已确认的字节位置。写入半条记录或刷新磁盘时报错时，回退到该位置；同进程续传先修复日志和输出文件，再继续追加，避免错误记录混入后续提交。

## 断点与字幕文件

- `model_streams/<代次>.jsonl` 保存冻结任务、源媒体标识、固定输出路径、翻译方向、成功译文、成对字幕及词级时间、处理位置、提交字节数和状态。已有任务目录、B 站分 P 共享目录、外部输出目录规则继续使用。
- `model_jobs/asr-<摘要>.json.appendlog` 追加识别/增强块的变化，同时兼容旧 `.json` 检查点。运行时不反复写整份断点，不扫描整份字幕哈希或读取完整备份。
- 重启后在后台 isolate 解码日志一次，恢复已提交字幕并修复未提交的文件尾部；已识别/增强块不重新推理，已成功译文不重新翻译。重选部分字幕时直接使用内存快照。
- SRT 按批增长；最终一次生成现有 `.wordtiming.json` 伴随文件。生成中导出使用已提交快照，编辑保留既有另存副本方式；删除先停止并等待写入关闭。
- 生成中的任务保留恢复数据；完成后管理器只保留紧凑元数据，选中字幕的播放器持有自己的快照，避免批量任务长期占用所有已完成文稿的内存。

## 增量界面

文稿列表、分段文章、连续文章，以及音乐页横竖屏歌词的末尾提供轻量生成提示，例如“正在转录并翻译 · 03:24 / 12:00”。提示仅对应当前媒体、当前选中且实际显示的生成中字幕；主副字幕显示模式也参与判断。切换到普通字幕、停止、暂停、出错或完成时立即隐藏，切回生成中的字幕时恢复。完成状态通过管理器及文件状态通知更新，不依赖再次追加字幕。

`SubtitleGenerationFooter` 单独订阅状态，按秒级显示值去重，只重建自己的文字。尾部提示区保持固定留白，避免完成时改变阅读锚点或选区；它不参与字幕编号、文章分句、歌词高亮或复制文本。音乐桌面列表把提示放在独立 sliver 中，不修改歌词高度缓存；移动列表和文章将尾部提示与正文索引区分。歌词选文使用独立的提示位，保留已冻结文稿及其选区。

短文稿在列表、分段文章和连续文章中均从顶部开始显示，实际内容（含尾部提示与内边距）超出视口后才使用滚动定位。连续文章复用已有行高，最多检查一屏内容；没有滚动范围时，播放跟随、手动定位和阅读位置恢复不重新锚定当前句，避免索引列表将收缩后的高度与外部视口高度混用而产生大块留白。视口变大、文稿重新能完整显示时恢复首行顶对齐；字幕追加超出视口时沿用原列表状态。

短文稿修复新增 21 项回归，覆盖跟随开关、定位比例两端、手动定位、视口扩大、字幕从不足一屏增长到超出视口，以及已挂载可选文字节点的保留。共 277 项相关文稿、选字、滚动、生成提示与流式更新测试通过，针对修改文件的静态分析无问题；日志为 `.artifacts/model-center/short-transcript-{targeted,regression,analysis}.log`。验证使用本机 Flutter 控件环境，未进行用户平板的真机复测。

此提示的 25 项新增验证涵盖五个平台的 Flutter 控件配置、音乐横竖屏、三个文稿模式、切轨/切媒体、终止状态、选文和追加锚点。连同既有文稿与音乐交互共 334 项相关回归通过，1 项按现有条件跳过；这些是本机控件与状态测试，不替代五个平台的真机运行。横竖屏预览保存在 `.artifacts/model-center/generation-footer-{portrait,landscape}.png`，验证日志为 `generation-footer-{tests,regression,analysis}.log`。

本地流水线的总体进度固定为单行“已完成 03:24 / 12:00”，使用已提交字幕的音频处理位置；开启翻译时，等待原文和译文成对提交后推进。超过一小时的媒体从一开始使用“00:03:24 / 01:12:00”格式，数字等宽并预留固定位置，窄屏按可用宽度缩放，不换行。播放器面板和任务列表使用同一显示组件，流水线各阶段详情保留。对应总体进度条也使用相同的已提交比例，原有任务调度与阶段进度保持独立。

## 2026-10-20 调度与重叠区修复

本地翻译不再强制关闭识别/增强流水线。`AsrExecutionPlan.withLocalTranslation` 以可用内存决定阶段并行和驻留：串行路径中识别与 CTC 精校交替加载，按两者工作集的最大值计算；精校只计可能驻留的最大语言包，轻量增强另计。内存允许时保留翻译会话，避免每 30 秒重载 GGUF；内存有限或用户选择节省内存时继续按阶段释放。默认增强、分句和加速偏好保留，不通过关闭精校或强制 GPU 提速。

`ModelStageBarrier` 在本地翻译期间拦住新的识别、增强和降噪原生调用，并等待已开始的调用结束，避免多个模型同时抢占 CPU。翻译结束或抛错后均放行后续调用，停止仍等待当前不可抢占的原生调用结束。翻译指标新增实际 `modelLoads` / `modelReuses`；复用会话时的进度文案也区分于重新加载。

新一代字幕保留识别块的重叠头部，在未发布尾部按“上一块后缀 / 下一块前缀”合并重复文本，保留后续新内容、词级时间偏移和复核信息；不同识别假设造成的同一说话人时间交叠在发布前修整。相隔的真实重复语句和已知不同说话人不会按重复文本删除。不会扫描或改写已发布全文。

字幕组装版本随任务保存。旧的冻结任务续传使用原组装规则，避免字幕编号与已完成译文错配；选择“重新生成”才采用新版边界处理，并保留旧字幕文件。

真实 Windows CPU 测试使用 SenseVoice、默认增强与 Hy-MT2，模拟移动设备的 8 GiB 总内存 / 4 GiB 可用内存准入条件，对比强制每批释放和新的阶段驻留策略。相同 65 秒稀疏语音、相同原文结果及三次成对提交中，总耗时为 19,671 / 11,809 毫秒，首次成对发布为 6,885 / 6,178 毫秒；翻译模型加载由 3 次降为 1 次，复用 2 次。记录为 `.artifacts/model-center/streaming-native-results.json` 的 `mobileAdmissionComparisonOnWindows`。这是 Windows 上的实模型对照，不是小米平板、Android 真机或持续语音吞吐测试。

本次 386 项相关回归通过，9 项按现有在线测试条件跳过；另有 7 项真实原生模型测试通过，覆盖四种 ASR、两种本地翻译和驻留对照。回归包括并行阶段交接、旧任务组装版本迁移、停止续传、边界文本与词级时间、播放器增量以及现有翻译和增强行为。13 个相关文件的针对性静态分析无问题，记录见 `.artifacts/model-center/streaming-scheduling-{regression,native,analysis}.log`。

## 2026-10-21 音频窗口归属修复

上一版文本去重无法处理“同一段声音被识别为不同文字”。而且 V2 时间整理在冲突时把前句结束时间缩至后句起点，会让仍在说的前句被后句抢先显示。新任务使用 V3 窗口归属规则，不再用这个时间整理方法消除跨块冲突。

前后两侧都有可用词级时间、且前句完整时，按声音所占时间保留前句并移除下一块的重复词，即使重复词被识别为完全不同的文字也适用。只在两侧词级时间证明没有语音时修整 VAD 留白，保留真实的新词与实际重复说话，不用字数比例或同音字相似度推算切点。

粗糙时间、跨切点的原子词、冲突的时间范围及被块尾截断的语句，会提取两侧完整上下文音频，用当前模型重新识别一次该交界范围，替换尚未发布的两份假设。沿用当前 CPU / GPU、声道、降噪、VAD、热词、精校、补标点、静音修整和自然分句配置。增强前的原始 VAD 块尾、进入重叠区的语音起点及下一块重叠头部的语音信息单独传入组装器，避免精校移动时间后误把半句当成完整句发布，或因残词时间漂到重叠区之外而漏检；必要时连下一块没有识别文字的情况也重新取音频收尾。

该流程位于四种本地 ASR 共用的发布入口，在任何字幕翻译服务接收文字之前完成。没有交界语音冲突时不增加推理；有歧义时增加一次局部音频识别，以避免残词污染后续翻译。交界原始结果和增强结果沿用追加检查点保存，继续生成时复用，取消或失败不提交这批字幕。

流水线在交界识别期间等待识别、增强和预降噪原生调用交接，防止同一模型所有者重入。识别返回、可选调优与 PCM 交付归入同一个共享阶段，避免交界修复覆盖下一块尚未取走的音频。音频提取使用原入口单独准备，不消耗普通块的预取序列；临时文件在成功、出错和停止时均关闭并清理。

版本 1 / 2 的已冻结任务仍按原规则重放，防止已提交字幕的编号与译文错配；重新生成才采用 V3，旧字幕保留。此前生成的错误文本不会被后台改写。

本轮边界与关联回归共 82 项通过，记录为 `.artifacts/model-center/asr-boundary-ownership-final-{regression,handoff}.log`。覆盖“咱还能谈谈吗？”/“看忙，接着说。”两份冲突假设、前句结束时间与播放高亮、增强前后时间漂移、真实重复话语、翻译前处理及成对发布、串行/并行原生交接、停止和续传。交界识别返回空结果时暂停且不缓存空断点，重试可重新识别；不会因空结果断点而永久失败。串行交接测试显式使用节省内存模式，避免依赖另一个正在调整的自动调度策略。

Windows CPU 原生测试 11 项通过，其中包含四种 ASR 的真实连续语音交界、两种本地翻译的成对文件提交及模型驻留对照。补充原始 VAD 信息后，四种连续语音交界用例再次全部通过；这四项属于上述 11 项的复测，不另计数量。音频把强语音帧放在 30 秒切点，检查局部重识别、时间轴无重叠、断点重放不重复解码。SenseVoice、Dolphin、Parakeet 的样本文字与完整音频基准相同；Zipformer tiny 会随 VAD/降噪上下文改变部分识别文字，其测试验证同一话语没有拼接两份假设，并保存两份实际文字，不能据此声称识别准确率不变。原视频未提供，中文例句通过可控时间与假设重现，真实模型测试使用工程内的中英文语音样本。

## 2026-10-21 在线翻译等待与原生模型交接

原生双阶段流水线此前把整个字幕发布回调包在模型独占区内，AI API 翻译等待网络时也会拦住下一块识别。现在只转录或使用在线翻译时，仅交界重识别及其增强进入独占区；分句、文件追加和在线翻译等待均在区外执行。交界重新识别仍先等所有已开始的原生调用结束，借用当前推理预约完成，保留 PCM 交付、原始 VAD 归属、断点和取消规则。使用本地翻译时继续独占整次交接，不嵌套获取同一交接锁。
