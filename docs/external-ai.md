# 外部 AI 连接与完整对话导出

桌面播放器默认提供只读的本机 MCP 服务。用户另外开启权限后，外部 Agent 也能管理转录任务，分别选择软件或 Agent 优化、翻译新生成或已有的字幕，并按需加载副字幕。同时启用时先优化，再翻译优化后的版本。问答、总结及 Agent 执行的字幕处理由用户选择的 Agent 完成；MCP 始终不提供媒体文件。

## 用户操作

1. 点击媒体库顶栏的 **连接外部 AI**（窄窗口显示连接图标）。媒体库设置中也保留入口。
2. 开启 **允许外部 AI 读取资料**，选择整个媒体库或一个文件夹。文件夹授权包含其子文件夹；回收站和隐藏目录不会开放。
3. 选择 Agent，页面会自动准备连接提示词。检查预览后点击 **复制连接提示词**，把这段话发给对应 Agent。它会读取播放器生成的本机连接说明文件，为自己的客户端添加连接。
4. Agent 如果可以编辑自身 MCP 配置，会备份后合并连接。随后还需完成该客户端的加载、信任、启用和当前任务工具选择；提示词不能代替客户端要求的用户确认，也不保证现有会话立即加载新工具。各客户端的连接步骤默认完整显示。没有配置能力的客户端可直接使用 **其他连接方式** 中的 **添加连接** 或 **复制配置** 按钮。
5. 按[逐客户端连接步骤](external-ai-client-setup.md)完成接入，再让目标 Agent 实际调用 `player_overview` 和 `library_browse`。两次真实调用成功后，即可直接提出媒体库与文稿问题。正在运行其他任务时，保留等待加载状态，按客户端要求稍后处理，不强制重启应用。

需要处理字幕时，再开启 **允许管理转录任务** 和 **允许优化、翻译和加载字幕**。页面可分别记住两个步骤的默认执行方式，也可直接在对话中指定。API 密钥只在播放器内填写。

例如：“把这几个视频的现有字幕先优化，再翻成英文：优化由你完成，翻译用软件，完成后加载译文为副字幕。”

连接提示词默认预览开头五行。点击 **展开全文** 可查看并选择全部文字，全文随整页滚动；点击 **收起** 恢复简短预览。**复制连接提示词** 始终复制当前预览对应的完整内容，收起状态也不会只复制开头。预览和复制使用同一份已准备好的提示词；切换 Agent 或调整授权后，页面会重新准备预览。

连接提示词按客户端分别生成，引用本机说明文件的绝对路径；令牌不直接出现在提示词中。说明文件包含连接所需的凭据，仅供用户授权的本机 Agent 使用。提示词要求保留其他配置、不回显凭据、不安装模型或运行时，并在真实查询成功后才能报告连接验证通过。

例如，用户复制给 Codex 的提示词会要求它读取本机说明文件、合并当前 Codex 的 MCP 配置，然后调用 `player_overview` 和 `library_browse`。给 WorkBuddy 的提示词会指向 WorkBuddy 自己的配置入口。用户无需手写地址和配置内容。

需要保持播放器运行。关闭读取开关后服务停止；授权设置会在每次请求时检查。历史 AI 对话有独立的授权开关，默认不开放。

**检测播放器连接**验证播放器自己的服务是否可访问，不能代替外部 Agent 的真实连接验证。页面请求数包含本机检测；配置文件、工具缓存和工具列表也不能代替当前任务中的真实调用。

外部 Agent 成功调用播放器工具后，顶栏图标会变绿，连接页显示 **已收到 Agent 调用** 和最近调用时间。仅保存配置、握手、列出工具、失败的调用和播放器自身检测不会触发此状态。记录只保留在本次服务运行期间；关闭读取、更改授权或重启服务会重置。该状态表示已成功读取过资料，不代表 Agent 持续在线，也不根据当前选中的客户端推断调用者身份。

## 日常处理与真实队列（MCP 1.5）

新 Agent 应先读取 `player_overview` 或 `player_guide`。概况直接给出软件实际选中的转录服务、语言、优化接口/要求和翻译模式，不依据已安装模型猜测默认值。当前选公益或云端接口时，不需要先选择、下载本地转录模型。用户没有另行指定时，沿用当前设置及已保存的执行偏好；没有偏好默认软件处理。只为真正的目录、多字幕版本或授权歧义询问。

- **整目录混合任务**：`subtitle_plan` 传 `folderId` 或 `targets`，`source=auto`；未指定目录时只用明确可用的 `activeLibraryContext`，不能把正在播放视频的目录当当前浏览目录。可显式选择整个授权库，最多1000项，超限明确拒绝而不静默截断。先按需发现现有字幕，再给出已有、确认缺少、失败/未检查和多版本待选的分类；失败不等于无字幕。已有主字幕优先当前选中，其他多版本汇总选择一次。
- **开始**：用 `subtitle_process` 提交 `planId`、`requestId`。有可用字幕的媒体直接优化/翻译，确认缺少的才转录；同时开启时先优化，再翻译本批优化版本。明确要求优化会开启本批步骤，不受全局优化开关当前关闭的影响。可为本批覆盖 `transcriptionServiceId`、`sourceLanguage`、优化连接、翻译提供商或语言规则，不必先改全局默认。规划版本、字幕版本或配置改变时，旧确认不能套用到新内容。
- **软件或 Agent**：两步分别选 `app`/`agent`。软件执行只需开始及 `subtitle_jobs` 查稳定状态，不解析进度文案或自己编排内部分批。Agent 优化按当前提示纠错、保持原语言/原意和时间轴；Agent 智能互译使用实际 `SmartSubtitleTranslator` 路由提供的 `translationParts`（每段有目标语）。按 `parts` 回传并用 `preserveCueIds` 保留无需翻译的条目，软件重组标记与保留片段。单向模式使用指定目标语；显式目标语言覆盖智能模式。旧草稿的 `contract=1` 继续使用返回的旧 `entries` 协议。
- **真实队列**：`transcription_queue` 查询软件已有任务，包括手工创建的；按返回的 `taskId` 和 `availableActions` 调用 `transcription_queue_control` 开始、暂停、继续、取消或重试。取消不删除媒体或已发布字幕。失败重试与完成后重新生成是不同操作，重新生成需要单独确认。句柄绑定任务代次和媒体身份，不能误控换源后或重新生成的新任务。
- **协作批次**：`subtitle_jobs`/`subtitle_job_control` 管理统一作业、单媒体步骤和 Agent 草稿；可以按媒体暂停、继续、取消、重试。后台失败给出安全分类及恢复工具。已完成识别/软件处理结果可恢复发布，丢失完成缓存时拒绝自动重算，避免盲目重复消耗接口额度。旧 `transcription_start`、`tasks_read/control` 和 `translation_*` 入口保留兼容，其中旧任务查询仍只覆盖旧 MCP 批次，不能据此声称软件真实队列为空。

例如：“把当前文件夹所有视频的字幕优化，缺字幕的先用当前服务转录；翻译按我的智能互译设置，由你处理。”Agent 应先规划并汇总需要选择的版本，再执行确认后的批次；默认保留原稿并应用推荐主副字幕，明确要求只保存时才传 `loadSubtitles=false`。API Key 始终仅在播放器原生窗口填写，MCP 不提供媒体文件、路径、播放地址或密钥。

### 主副字幕与稿本名称（MCP 1.5.1）

| 本批处理 | 默认主字幕 | 默认副字幕 |
| --- | --- | --- |
| 只优化 | 本批精校稿 | 保留原副字幕 |
| 只翻译 | 本批使用的源稿 | 本批译稿 |
| 优化并翻译 | 本批精校稿 | 根据该精校稿生成的译稿 |

规划、开始及作业结果都会返回字幕方案。Agent 完成后应说明实际主稿、副稿的名称；`subtitleSelection.applied=true` 代表选择已保存，`loadedForCurrentMedia` 只代表是否刷新当前播放，不代表选择成功与否。未播放的媒体也会保存各自选择，软件不会为此打开媒体。处理期间用户自行更改选择时保留用户选择并说明结果，新稿仍在字幕管理区。

用户指定“译稿做主字幕”“交换主副”“关掉副字幕”时优先按要求，可先只保存，再用 `subtitle_select` 同时指定 `primaryDocumentId`、`secondaryDocumentId` 或 `clearSecondary`。省略的一边保留；同一版本不能同时放两边。ID 来自产物或 `documents_list` 的 `documentId`（兼容原 `id`），不能传名称或路径。

软件和 Agent 的新稿统一用“内容名＋版本”，例如 `人工智能入门 · 听写稿`、`人工智能入门 · 精校稿`、`人工智能入门 · 英文译稿`，智能互译为 `人工智能入门 · 互译稿`。重做后用 `v2`、`v3` 区分。内部文件名、任务 ID 与模型名称不拼进稿名，原文件、自定义名及版本关联保持。可识别的旧自动名称只改善显示，不迁移字幕文件。

## 能读取的资料

| 工具 | 内容 |
| --- | --- |
| `player_overview` | 软件名称、当前媒体及授权范围概况 |
| `playback_read` | 与迷你播放卡片一致的实际当前媒体、暂停/播放意图、实时进度及按显示顺序分页的播放列表 |
| `folder_info` | 文件夹或来源卡片详情；完整版播客频道包含简介、主播及本机已缓存单集的分类数量 |
| `library_documents` | 批量列出整个授权库、文件夹或所选媒体的本地文稿及可用情况，可筛选有/无文稿的媒体 |
| `library_document_search` | 跨媒体搜索文稿原文关键词，按媒体返回标题、文稿 ID、时间戳片段 |
| `documents_read_batch` | 批量读取多个媒体的文稿，自动选择首份可用文稿或指定版本，共享正文预算并支持完整续读 |
| `library_browse` | 普通目录按软件顺序浏览；完整版播客频道默认按日期倒序只返回最新 10 期，可按收听/收藏状态筛选并继续翻页 |
| `library_search` | 授权范围内媒体、文件夹和完整版播客单集的标题/简介搜索，可按来源筛选 |
| `media_info` | 标题、类型、来源、时长、编码、章节、目录位置及已有简介/发布日期；可读取当前播放或队列中的临时媒体 |
| `documents_list` | 单个媒体已关联或可自动匹配的本地字幕、转录文稿 |
| `document_read` | 带时间戳的文稿正文、读取偏移、版本与下一页位置 |
| `document_search` | 单个媒体已有文稿中的关键词片段；跨媒体应使用批量搜索 |
| `conversations_read` | 单独授权后读取此媒体已经保存的问答和分支关系 |

目录、媒体和文稿使用软件内部 ID 定位，不接受任意磁盘路径、URL 或查询语句。普通文稿读取只使用已有资料；缺少时，Agent 可单独调用 documents_prepare，批量准备现有字幕。该步骤不转录、不调用生成模型，不下载整个远程媒体。unchecked/failed 不等于已确认没有字幕。

### 跨视频查询与批量总结

保留 12 项基础资料读取工具，增加 3 项按需文稿准备工具；独立授权历史对话后再增加 1 项。原有单媒体工具保留兼容；批量任务应优先走下面的入口，避免 Agent 为每个视频反复调用工具。

- “哪些视频有字幕？”：调用 `library_documents({"hasDocuments":true})`，同时返回媒体和可用文稿 ID，不读取已关联文稿的正文。可以附加 `folderId`（默认包含子文件夹）、`mediaIds` 或 `titleQuery`。
- “哪些视频讲过光圈？”：调用 `library_document_search({"query":"光圈"})`，搜索授权范围内文稿的原文关键词，不限媒体标题。每个匹配媒体最多给出 3 个片段；这是关键词搜索，不是语义检索或全文阅读。
- “总结这几个视频”：直接调用 `documents_read_batch({"mediaIds":["媒体ID1","媒体ID2"]})`，不必先逐个调用 `documents_list`。默认每个媒体只选择首份现存的关联文稿；需要其他语言或版本时通过 `requests` 指定 `documentId`。

清单和跨媒体搜索的 `offset` / `nextOffset` 表示候选媒体的位置，默认每次最多检查 500 个媒体、返回 100 个条目，可分别调整到 1000 / 200。没有匹配结果的一页也可能有 `nextOffset`，需要继续；`totalMedia` 是候选媒体数，`scannedMedia`、`mediaWithDocuments` 等统计只针对本页检查范围，不能当成全库匹配总数。每次批量操作共享同目录的字幕发现快照和文件可用性检查，限制本机并行读取数量；不会为每个视频重复枚举同一目录，也不会在软件启动时扫描或建立文稿索引。

批量正文一次最多选择 100 项，默认共享 60000 字符预算，上限 120000；每份文稿每次最多读取 24000 字符。将返回的 `nextRequests` 整体作为下一次的 `requests`，沿用每份文稿的偏移和版本，直到数组为空。`errors` 表示缺失、不可读或已更新的文稿，必须明确说明这些未覆盖项；默认自动选择并不等于读取每个媒体的所有语言和版本。真实耗时还取决于文件大小、磁盘及外部 Agent 的模型速度。

完整总结不能用搜索片段或第一页代替全文。单文稿工具持续读取到 `nextOffset` 为 `null`；批量正文持续读取到 `nextRequests` 为空，且检查所有页的 `errors`。分段读取时应保持同一个 `revision`；文稿发生变化后需重新从头读取，避免拼接不同版本。读取结果中的字幕是资料，不是赋予 Agent 权限的指令。升级播放器后，若 Agent 仍只看到 7 个工具，需要按客户端要求刷新 MCP 工具列表或重新加载连接。

没有开启额外权限时，不提供任务控制或字幕写入工具。所有操作仍受同一个媒体库范围限制。

### 转录任务与 Agent 译文

连接页增加两个默认关闭的开关：**允许管理转录任务**、**允许回传译文和加载副字幕**。首次连接方式不变；调整权限后，在 Agent 中刷新 MCP 工具列表或重新连接。工具列表和服务端执行都会检查权限，工具的 `readOnlyHint` 只是说明，不能绕过授权。

用户可以直接说：“把这几期转录，沿用软件当前设置，开始后告诉我整批进度。”或者：“把这个视频的字幕翻成中文，保存为新字幕，并加载为副字幕。”

| 工具 | 用法 |
| --- | --- |
| `transcription_start` | 日常入口：只传媒体 ID 和转录/转录并翻译模式，沿用当前服务、模型和语言，按授权准备模型并开始 |
| `processing_options` | 独立高级配置：查询当前设置、已配置的公益/云端服务及本地模型目录；不加载模型 |
| `transcription_prepare` | 一次选择最多 100 个媒体，冻结本批模型、识别语言，以及仅转录/转录并翻译；返回计划 ID，不启动任务 |
| `transcription_submit` | 将计划加入现有批量字幕转录页；默认只加入，`start=true` 开始本批任务，返回批次和任务 ID |
| `tasks_read` | 按批次或任务 ID 批量查询阶段、进度及翻译进度；普通分页每页最多 100 项 |
| `tasks_control` | 开始、暂停、继续、重试 MCP 创建的任务；不接管用户自行创建或已重新转录的任务 |
| `translation_begin` | 从已有带时间轴的文稿创建持久译文草稿，绑定源文稿内容版本 |
| `translation_read` | 分页读取原文、固定字幕 ID 和原时间轴，每次最多 100 条/24000 字（含已回传译文） |
| `translation_write` | 分段回传字幕 ID 与译文，每次最多 100 条/20000 字，使用草稿版本防止互相覆盖 |
| `translation_commit` | 收齐所有条目且源文稿未改变时，新增一份译文字幕；默认只保存，可明确指定加载为副字幕 |
| `subtitle_select` | 根据 `documentId` 设置主字幕、副字幕、交换两者或关闭副字幕；为该媒体保存，不开始播放。旧 `assetId` 选译文副字幕参数仍兼容 |

转录使用播放器已有的单一队列、模型所有者和资源调度。日常调用 `transcription_start`，只指定媒体与 `transcribe` / `transcribe_translate`，沿用当前设置；公益接口和其他已配置云端服务都不需要安装本地转录模型。本地模型缺失时披露固定模型及组件的下载大小，确认后由原队列准备并继续。云端音频由播放器直接提交已配置服务，Agent 不接触媒体文件、媒体路径、播放地址或密钥。临时本地媒体需先由用户加入媒体库；社区版只处理本地媒体，但可按用户授权使用公益/云端 ASR 与模型下载。

`processing_options`、`models_prepare`、`models_status` 和 `settings_update` 是独立的高级配置能力，不是日常转录必经步骤。`settings_update` 可选已有服务/本地模型、媒体语言、本地翻译模型、翻译方式和目标语言，修改后续任务的默认值，不改已排队任务；不接受自定义地址或密钥。高级 `transcription_prepare` / `transcription_submit` 保留兼容，适用于只准备计划或本批覆盖设置。

默认在连接页「待确认」批准具体一批操作，模型下载大小、使用的服务、上传音频/发送字幕及语言同时展示。批准绑定该计划、媒体来源、配置和连接范围，24 小时失效；Agent 只能查询 `approvals_read`，不能调用工具替用户批准。用户可在「自动代办授权」分别开启本批转录、模型下载、在线处理，开启的类别无需重复确认；全局默认设置变更始终逐次确认。关闭权限或改变授权范围后，正在准备的 MCP 操作在下一边界停止，已确认提交的原生任务仍由批量转录页管理。

计划重复提交返回同一批次。写操作使用 `requestId`，网络重试必须沿用同一 ID 和相同参数。队列中的原生任务另外保存不透明的外部任务 ID，防止在中断恢复后重复创建或误控用户任务。任务和译文草稿保存于本版本自己的应用数据目录；播放页是否打开不影响队列。关闭 MCP 连接只撤销后续操作权限，已经开始的转录仍由播放器执行，可在批量转录页暂停。Agent 结束对话后能否继续自动查询取决于客户端，本服务不承诺自动唤醒；有任务时建议每 3–10 秒查询整批状态。

回传译文只能修改文字，不能修改原时间轴、跨媒体引用字幕或覆盖原文件。缺失、重复、过期的字幕条目或源文件变化会阻止发布，已收到的内容保留为草稿。发布使用应用生成的独立文件名，并登记为机器生成的翻译字幕；重复提交不增加第二份。`documents_list` 会提供已有管理字幕的 `assetId`、类型和语言。只有当前媒体匹配时才刷新实时副字幕，异步期间改变媒体、字幕选择或权限会阻止迟到结果覆盖新的选择。

MCP 只返回元信息、文稿文字、ID、任务状态和进度，不提供媒体资源端点、音视频片段、Base64、真实磁盘路径、播放或签名下载地址。字幕读取会排除媒体路径、媒体格式、位图字幕和常见媒体文件头，未解析的二进制资料不会作为文稿回传。若 Agent 自身另有整个磁盘的权限，那属于 Agent/操作系统的权限范围，不能由播放器的 MCP 限制代替。

### 播客、来源卡片和实际播放会话

完整版通过独立的只读适配器合并已经加载的播客本机目录；没有播放过、尚未创建媒体库记录的单集也可浏览。普通频道查询只返回最新 10 期，附带标题、原始标题、发布日期、最多 240 字符的简介摘要和 `listenStatus`，不会自动把几百集或完整文稿交给 Agent。需要旧期才沿 `nextOffset` 翻页并保留 `revision`；目录成员或顺序改变时会要求重新读取，避免新集插入导致漏集或重复。只返回结果页中的简介，频道尚未加载时明确报告等待状态，不初始化播客运行时或自动刷新 RSS。

`library_browse({"folderId":"频道卡片ID","podcastFilter":"inProgress"})` 查询进行中；筛选还支持 `played`（已听）、`favorite`（收藏）、`unplayed`（从未开始）和 `all`。收藏是独立标志，一集可以同时已听且收藏。状态使用软件已有的播放进度、完成标志和收藏记录；`folder_info` 返回该本机目录的分类数量，不代表远端 RSS 的所有历史内容。只搜索几个主题或总结最新几期时，不要求先遍历全部历史。完整简介通过 `media_info` 或 `folder_info` 分页读取 `descriptionNextOffset`。

来源以 `source.kind` 区分 `local`、`podcast`、`cloudDrive`、`bilibili`、`url`，网盘卡片附提供商 ID，哔哩哔哩卡片附已有 BV/分 P 信息。只返回白名单描述字段；不导出账号 ID、原始来源地址、签名播放地址或登录凭据。网盘只涵盖已导入的媒体库卡片及已在实际播放队列中的条目，不会借 MCP 枚举整个网盘、登录、获取新播放地址或下载资料。

`playback_read` 读取实时会话，不依赖播放页是否打开。`currentMedia` 是实际选中的媒体，`state`、`isPlaying`、`transportPlaying` 及实时进度共同描述播放状态；`previewMedia` 仅表示队列预览，不能称为正在播放。`queue.items` 按迷你播放器的实际显示顺序返回，每页默认 50 条，支持 `nextOffset` 和队列 `revision`。返回的媒体 ID 可直接用于详情和批量文稿读取，不需要把临时条目写入媒体库。

整个媒体库授权包含这些当前会话和队列中的可见媒体；指定文件夹授权仍只返回该范围内的内容。原有隐藏目录、回收站和未授权媒体不会因为进入播放队列而获得读取权限。社区版仅接入本地播放会话/队列及本地文件夹，不安装完整版播客目录适配器，也不增加网盘或网站浏览入口。升级后应重新加载客户端工具列表，确认出现 `playback_read` 和 `folder_info`。

### 按需准备现有文稿

- `documents_prepare(mediaIds, requestId)`：每批最多 100 个媒体，立即返回 `jobId`。不需要进入播放页；同一媒体的并发请求串行复用结果。
- `documents_prepare_status(jobId)`：分页查看整批进度和 `ready` / `candidate` / `unchecked` / `confirmed_none` / `failed` / `login_required` / `unsupported` 等结果，准备好后用 `documents_read_batch` 批量读取。
- `documents_prepare_cancel(jobId)`：取消本批，终止自己的字幕提取进程，保留已准备结果。

先复用字幕管理区及媒体专属任务目录中的文本，即使没有选为主/副字幕也能找到；随后使用原有文件名/时长匹配器检查同目录字幕，不自动关联模糊匹配。缺少资料时，只提取内嵌文字软字幕，跳过 PGS/DVD 等图片字幕；本轮不做 OCR。新提取文件按媒体身份/大小/修改时间区分，媒体变化后不复用旧缓存，临时文件不进入文稿列表。首次探测/提取会随容器大小耗时，后台批量执行，每个原生探测/提取均有限时，Agent 无需逐视频反复调用工具。

社区版仅提供本地媒体的字幕发现、文字软字幕提取、模型/已配置 ASR 服务控制和确认机制。公益或其他云端 ASR 是播放器按授权上传本地音频的处理服务，不提供网盘、网站或播客媒体接入。MCP 始终不提供媒体文件、媒体路径、密钥或任意网络地址。

## 对话导出

AI 对话的“更多”菜单提供 **复制完整对话** 和 **导出完整对话…**。历史会话也可从条目菜单导出。

- 支持 Markdown、纯文本和 JSON，便于复制、保存或交给另一个 AI。
- 默认包括当前会话从第一轮到最后一轮的问答正文；可以选择此媒体的全部会话，保留分支关系。
- 可选附带导出时当前可用的所选字幕文稿；它不代表历史每轮都使用了同一份资料。
- 已返回的思考内容可以单独选择，默认不导出。
- 不导出草稿、AI 连接设置、访问令牌、原始请求封包或本地文件路径。正文中用户自己写入的内容仍按原文保留。

导出是正常资料文档，不承诺恢复供应商未公开的内部思考或旧对话未保存的逐轮请求历史。

## 字幕优化、翻译与 Agent 协作

`subtitle_processing_options` 提供当前设置、确实支持优化/翻译的接口、软件/Agent执行方式及操作说明。`subtitle_process` 是统一开始入口，`subtitle_jobs` 一次查看整批，`subtitle_job_control` 暂停/取消/继续；无需Agent理解软件内部分批、模型调用、进度文案或额外处理步骤。应用适配边界在 `external_ai_subtitle_backend.dart`，实际开始操作复用转录队列与 `SubtitleTranslationService.processSubtitleFile`；应用调整内部流程时保留这个开始/状态/结果契约即可，不要求Agent重新编排内部步骤。

- `targets` 每批1–100个已授权媒体，可逐项指定 `documentId`；未指定时批量按需准备已有字幕，优先当前字幕。`source=existing` 不重新识别；用户明确要求重新转录时才传 `source=transcribe`，并读取这次任务的实际新文稿，不能用旧字幕冒充。
- `optimize` 和 `translate` 分别选择 `off`、`app`、`agent` 或 `ask`。用户没有指定执行方时沿用已保存偏好，没有偏好则用软件；只有偏好为 `ask` 才询问整批一次。软件连接页面可以分别记住两个默认执行方式。日常任务无需先修改模型。每批可独立选择已保存的优化、翻译AI连接，省略则沿用各自当前设置；不会修改全局模型或影响已经排队的任务。
- 两个步骤都选择软件时，复用软件一次完整处理调用。混用时，协调器只衔接已保存的字幕版本。翻译的输入固定为本任务完成的优化版本；优化未完成时，翻译步骤不可读、不可提交。
- Agent处理用 `subtitle_work_read` 按需读取少量条目与背景，按稳定 `cueId` 调用 `subtitle_work_write`。后者要求 `expectedRevision`，每次最多100条/20000字；最后一批 `complete=true`，收齐后另存字幕，再开始下一步。优化保持原语言、原意、句级时间轴与条数，不扩写/总结/翻译；仅发送文字和有限背景。字幕或媒体身份变化时保留旧结果并要求重新建立任务。
- 原字幕不覆盖。精校稿和译稿分别进入字幕管理区，译稿关联精校稿的版本；默认完成后应用推荐主副字幕，`loadSubtitles=false` 明确只保存。用户字幕选择已变化时保留新选择；切换播放媒体不会阻止原媒体保存自己的选择，也不会把结果加载到错误媒体。
- 软件工作进度来自应用服务，不解析中文文案来判定成功。Agent步骤按已持久化条数显示，退出Agent不会假装继续生成；重连后读取原任务继续，重复请求沿用 `requestId`。暂停仅停止本任务的请求和等待，不接管其他任务或共享下载。

`subtitle_service_configure` 是独立高级能力，只准备接口名称、HTTPS（或本机HTTP）地址、模型。软件的“待配置字幕接口”卡片打开现有原生接口编辑器，由用户填写密钥、检查连接并保存。每次新增独立连接且初始密钥为空，不继承其他地址的凭据；Agent只能取得配置状态与 `connectionId`，不能接收/查询/提交API Key。接口地址不可嵌入凭据或查询参数。凭据继续使用原有安全存储，不写入MCP任务、普通设置或对话；冻结任务也不能把旧密钥发送到新地址。

读取和任务控制、字幕写入均需在播放器授权；自动执行、模型下载和在线服务沿用现有独立授权。Agent自身的模型、额度及字幕数据政策由该Agent负责，不承诺免费或离线。三个桌面系统共用实现；MCP始终不提供媒体文件、媒体路径或播放地址。社区版仅适用已有本地媒体，不因此恢复在线媒体入口。

## 版本身份隔离（2026-11-06）

Fluent Player Pro 使用应用标识 `cn.teezy.fluentplayer.pro`、MCP连接名 `fluent_player_pro`、默认端口38461；Fluent Player开源版使用 `cn.teezy.fluentplayer.standard`、`fluent_player`、38462。服务握手的title与player_overview中的applicationName显示当前版本。凭据和连接说明按应用ID分别保存，不读取另一版凭据，也不会覆盖客户端中的另一版连接。已有同名配置发生冲突时仍须用户确认；不自动改写用户客户端设置。用户保存的自定义端口继续沿用；手工把两版设成同一端口时第二个服务会明确报端口占用，不会自动连到另一版。
