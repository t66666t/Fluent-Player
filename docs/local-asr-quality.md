# 本地转录字幕质量调研与可选处理

更新日期：2026-10-20。目标平台：Android、iOS、macOS、Windows、Linux。已接入可关闭的默认增强流程，直接使用现有五端原生运行库和纯 Dart 后处理；没有在客户端安装 Python 或 PyTorch。下面区分实际接入能力、上游参考与尚需真机验证的范围。

## 转录吞吐与流水线

选择本地模型后的默认流程是：复用或获取媒体 → 准备所需模型 → 声道混合与 16 kHz 单声道 PCM → GTCRN 降噪 → VAD 检测语音 → 按实际语音选择可用计算后端并识别、保留原生时间 → 按需 CTC 精校 → 中英标点 → 静音边界修整 → 重叠去重与自然分句 → 已开启的字幕翻译 → 保存。说话人识别不在流程内。没有可靠时间的语言仍遵循既有安全回退，精校不自动改写原文。

第一版只在流水线准入成功时复用模型。很多移动设备和低核数桌面回退为顺序执行后，仍每块释放和重载主模型；默认短样本的收益也不能代表整段播客。现在将“模型复用”和“阶段并行”分开：SenseVoice、Dolphin、Parakeet、Zipformer 及五端共用同一策略。

默认“自动流水线”在资源足够时创建两个独立工作实例：识别实例执行 VAD → ASR，辅助实例交替执行下一块 GTCRN 降噪及上一块按需 CTC → 标点 → 静音修整。识别第 n 块时，第 n+1 块已经可以降噪；同一块的识别仍依赖降噪结果，增强仍依赖识别原文。较短的增强与降噪共用一个原生实例队列，同一模型始终只有一个调用，不为第三阶段再开一组计算线程。没有启用降噪时沿用识别与增强的双阶段重叠。原始识别在增强前保存，最终按时间顺序归并并自然分句。

最多两片音频处于识别/等待增强/增强中，积压时识别等待；另外只允许提前读取和降噪一片 PCM，并可提前准备一个后续 WAV 文件。队列不会随音频长度增长。降噪 PCM 经可转移缓冲交给识别，再交给增强，后续阶段不重复读文件或降噪。退出、失败或取消后等待正在运行的调用结束，并清理全部未领取的音频。在线模型服务同样可以提前准备下一片音频，不额外并发提交付费任务。

顺序模式也在余量允许时复用主模型、VAD、降噪和标点。只有实际需要 CTC 时才先释放主模型与 GPU 会话；下一块确实需要重新识别时，先释放旧 CTC，再加载主模型，避免低内存设备同时驻留两组大权重。纯后处理恢复可以继续复用 CTC。降噪与后处理都未启用时不创建第二个推理实例；仅开启降噪也可以重叠。任务结束释放所有资源；翻译和 OCR 与整条转录流水线继续共用重型推理预约，防止同时额外驻留一个数 GB 的大语言模型。

调度依据 CPU、物理内存、当前可用内存及模型大小。线程总预算为逻辑处理器一半，移动端上限 4、桌面上限 6；识别受用户 1–4 线程配置限制，辅助实例最多 2 线程。设置已从容易误解的“本地转录 CPU 线程预算”更名为“本地识别 CPU 线程上限”：控制单个识别模型内部的计算线程，并非并发音频数量；实际可按资源下调，辅助线程另由调度器分配。流水线最低预算为 3，可分成 2 个识别线程与 1 个降噪/增强线程。并行工作集按主模型文件两倍 + 最大单个语言 CTC 三倍 + 轻量增强三倍 + 0.5 GiB 估算，当前可用内存须再留 1 GiB，物理内存至少 4 GiB 且大于工作集加 1 GiB。不再将两个不会同时常驻的语言 CTC 全部累加。

顺序复用另按主模型两倍 + 轻量增强三倍 + 1 GiB 估算，再留 0.5 GiB；物理内存至少 2 GiB。移动端未知可用内存时保留回退，桌面未知可用内存时分别要求 16 GiB 才并行、8 GiB 才顺序复用。用户选择“节省内存”始终按阶段释放。这些是调度估算，不是测得的最低内存保证。Windows 读取可用物理内存，Linux 读取 `MemAvailable`，Android 读取 `ActivityManager`，iOS 读取当前应用可分配余量；余量会动态改变，见 [os_proc_available_memory](https://developer.apple.com/documentation/os/os_proc_available_memory)。

新建任务的流水线和顺序复用都使用约 60 秒准备窗口，减少 30 秒小块带来的 FFmpeg、重叠和写盘开销；顺序释放模式仍约 2 分钟，VAD 的语音识别窗仍最长约 12 秒。旧检查点保存或推断自己的窗口，不因切换调度丢失进度。调度不进入原始 ASR 身份键。模型、语言、音频前处理与版本约束保持有效。

声学精校默认只补齐不完整或过粗的原生时间：需要全文覆盖、单调且有效的字素/词块范围，并排除过长时间块、含多个完整英文词的原子块等。已有可用原生时间时跳过 CTC；“每条字幕都做声学精校”可强制运行，原生粗粒度边界与 CTC 细粒度边界存在精度取舍。增强依赖仍提前准备，自动跳过不等于卸载已下载权重。ORT 环境改为惰性复用，修复反复 `init()` 覆盖句柄遗留的引用；CTC 的空闲线程不自旋。线程争用的依据见 [ONNX Runtime 线程管理](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)。

音频切片、降噪、CTC 和流式识别减少了重复 float 数组复制；VAD 只读取语音坐标，不再把同一段语音复制到另一组 Dart 缓冲。VAD 模型按块重置与复用，但严格保留 512 点输入节奏，原生对照验证检测坐标一致；扩大当前固定运行库的调用窗口会改变检测结果，没有采用。ORT 环境惰性复用，CTC 空闲线程不自旋，依据见 [ONNX Runtime 线程管理](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)。

完整进度面板分别展示降噪/识别/增强的音频覆盖量、当前步骤、片段编号、实际计算后端、调度方式、本地已用时间与断点复用数；队列保留紧凑的识别/增强两行，可点开实时三阶段详情。各阶段状态互不覆盖，加载阶段不伪造百分比。整体进度也计入降噪，不会在第一块降噪期间一直停在原始起点；百分比是音频工作量分配，不是剩余时间估计。增强的 CTC 计数只计算确实需要精校的片段，分句完成后才报告本地处理 100%。

此前尚未拆出降噪时，Windows 上每个模型同一输入连续四块，CPU 2 线程、默认增强与自然标点上下文，包含模型加载，测得：

| Dolphin Base INT8 | 10.695 秒 | 8.950 秒 | 6.690 秒 |

## Parakeet 忽长忽短与说话人功能调整

Parakeet TDT 可在同一音频帧输出多个词块，个别词块的原生 `duration` 为零。旧代码丢弃这些词块的时间后，分句器无法确认整句的文字覆盖，便安全回退成整条原始字幕；能完整匹配的其他字幕又按旧的英语 40 字符目标切分，导致长段和短碎片混杂。真实 JFK 样本中，38 个词块有一个零时长的 `y`，旧代码仅保留 37 个，修复后保留 38 个。零时长词块使用同组的下一不同起点作为界限，不单独切开同帧组或英文单词。

默认改为“自然分句”：先衔接通常间隔不超过 900 ms 的语音续句；不超过 3 词且不足 1.8 秒的短片段可跨不超过 1.4 秒的停顿继续衔接。随后在可靠时间轴上综合比较句末、从句、停顿、时长和显示长度，惩罚短碎片、孤立尾词及冠词/介词/助动词之后的断点。目标为 6 秒、中文约 20 字、英语等约 80 字符，可在目标附近选择较完整的边界。这是纯 Dart 规则，不新增模型或下载，也不是完整的语法分析。没有可靠时间时，仅合并能整体放入目标的相邻短段；估算分句仍默认关闭。

默认增强链路还发现，单独给 VAD 切出的 `Ask not` 补标点会产生错误的终止感，精校后仅显示约 0.77 秒。自然分句开启时，补标点前也衔接语音续句，避免将片段当成整句；这一步随任务冻结，关闭自然分句时不启用。中英标点模型的中文标点类别在英语输出中转换为英文样式。真实默认流程最终得到 3 条字幕，时长约 1.75 / 4.01 / 2.05 秒，未改写识别词。证据：`.artifacts/model-center/parakeet-default-pipeline-native.json`。完整音频直接识别的 38 词块复现数据另见 `parakeet-segmentation-{before,native}.json`。

旧推荐的 4 秒/40 字符设置迁移到新预设；自定义、关闭分句及新版显式选择的短句设置保留。已冻结任务沿用自身的显示配置。Parakeet 原始识别断点增加时间轴版本，避免重新读入缺少词块的旧时间数据；其他模型与付费平台的远端任务断点不受此变化影响。

当前播放器不需要说话人识别，因此已移除开关、Pyannote/CAM++ 清单、自动下载、推理和派生状态；旧任务中这两个依赖被忽略，iOS 的旧后台下载会暂停。已有权重文件和历史字幕的说话人元数据保留。此前的匿名编号只在元数据与辅助断句中使用，没有写进 SRT 正文，不能作为当前播放器必需的增强。

## 这次长字幕的原因与修复

原来的 `local_asr_worker.dart` 把每个 Silero VAD 语音段作为一条字幕。VAD 的最长语音段约 12 秒，用来限制识别的音频长度；一段连续讲话内可能有数句话，因此字幕显得很长。缩短这个音频上限会改变模型获得的上下文，不能用它代替字幕分句。

本次已增加独立的纯 Dart 分句处理，接在原始识别结果去重、拼接之后：

```mermaid
flowchart LR
  A[声道选择与 PCM 准备] --> N[可选 GTCRN 降噪]
  N --> B[VAD 与边缘补音]
  B --> C[本地 ASR]
  C --> D[原文与原生 token 时间断点]
  D --> H[可选 CTC 精校与声学复核]
  H --> P[可选标点恢复]
  P --> S[可选静音边界修整]
  S --> I[派生结果断点]
  I --> E[重叠片段去重与时间偏移]
  E --> F[可选字幕分句]
  F --> G[字幕保存与现有翻译链路]
```

入口是“模型中心 → 本地转录设置 → 字幕分句”。新任务默认自然分句，可选择短句、标准、保留原始语音段或调整参数：

| 方案 | 每条时长目标 | 每条长度目标 | 用途 |
| --- | --- | --- | --- |
| 自然分句 | 6 秒 | 中文约 20 字 / 英文等约 80 字符 | 结合句末、从句和停顿；默认 |
| 短句 | 4 秒 | 中文约 20 字 / 英文约 40 字符 | 小屏、较短显示；可手动选用 |
| 标准 | 6 秒 | 中文约 28 字 / 英文约 56 字符 | 较完整的语义单位 |
| 保留原始语音段 | 沿用模型输入段 | 不限制 | 希望自行编辑或保留旧行为 |
| 自定义 | 2–12 秒范围内的选项 | 多档显示长度 | 按内容调整 |

这些数值是本项目的起点，不是所有语言和字幕平台的统一规范。长度按近似显示宽度计算，全角文字约占两个英文字符宽度。这里限制的是一条字幕的总量，播放器仍按实际字体和屏幕宽度换行。

分句保留模型识别的文字，优先句末标点，达到长度限制时尽量选择逗号或完整单词边界；保护 Unicode 字素、组合字符、emoji 和模型原子词块。自然分句综合比较相邻边界，尽量减少不足一秒或一两个词的碎片；原生极短句、最后一小段或不可拆词块仍可能偏离目标。它不承担完整词法分析，中文无标点长句仍可能切在复合词中间，泰语等无空格语言也可能保留较长字幕；要进一步改善语义边界，需要标点恢复或相应语言的分词规则。

可靠原生 token 时间能与最终文本完整对应时，用它确定切分位置并保留、重定位词级元数据。只有起点的模型使用下一个 token 的起点作为前一个 token 的结束边界；这不是测得的真实词尾。固定 sherpa_onnx 1.12.12 的公开 Dart 返回值未暴露 TDT 独立词时长，本项目通过该固定版本的 C API JSON 保留可用的 `durations`。额外 CTC 强制对齐与这些原生时间分开标记。

没有可靠对齐时默认保留整条原始字幕。可选“无词级时间时允许估算分句”，按显示宽度比例估计句级时间；可能不同步，不伪造逐词元数据。标记文本、结构化歌词采用保守保留策略。

设置自动保存，任务开始时冻结。已排队或开始的旧任务保留分句配置，已经生成的字幕不会自动改写。原始 ASR 断点不受显示分句设置影响；对同一输入重新创建任务时，可利用尚存的原始识别断点重新分句；此次 Parakeet 时间轴修复会重新识别旧版断点。当前仍会执行模型安装检查和加载；尚未添加“直接重新排版已入库字幕”的编辑入口。长列表分句在独立 isolate 执行。

## 开源项目里值得采用的做法

| 项目 | 核查到的实现或能力 | 对本项目的价值及边界 |
| --- | --- | --- |
| [stable-ts](https://github.com/jianfch/stable-ts#regrouping-words) | 按标点、词间间隔、长度和时长重组；可记录并重放重组规则，另有基于非语音区域的时间修整 | 借鉴处理顺序和可撤销设计。纯文本重组算法适合移植 Dart；其推理工具属于 Python 生态。仓库目前已归档，不作为新的运行依赖 |

## 已实现的默认增强

入口：“模型中心 → 本地转录设置 → 识别增强”。首次使用默认启用所有处理开关；选择本地转录模型后，后台准备相应语言所需的增强权重。每项都可关闭，关闭后的偏好保留，重新选择本地模型不会覆盖手动选择。声道默认混合，热词表默认空。设置按任务冻结，旧任务保持原处理方式。

| 处理 | 已接入实现 | 能力边界与代价 |
| --- | --- | --- |
| VAD 与补音 | Silero，阈值 0.5、静音 350 ms、最短语音 180 ms、最长语音 12 秒、前后留白 160 ms；均可调 | 保持绝对采样坐标，补音不越过相邻语音段中点；字幕显示长度另设 |
| 标点恢复 | CT-Transformer 中英 INT8；仅为缺少句末标点的片段补标点 | 只接受标点、空白变化，保留原文字形/大小写并重映射词级文本范围；已有完整句末标点时跳过。未确认语言的拉丁文字不能直接当作英语，需要已通过的英语声学对齐或中英专用引擎 |
| 静音修整 | 20 ms 音频能量窗、80 ms 缓冲、至少 600 ms 显示 | 不删字，保护已知词首及 CTC 对齐词尾；静音片段或不可靠边界保持原样 |
| 时间精校 | 普通话 XLSR-53、英语 Wav2Vec2 CTC + Dart Viterbi；有安全时间边界时拆为约 6 秒窗口 | 对齐匹配均值至少 0.25，贪心声学复核与原文相似度至少 0.55。词表缺字、数字未覆盖、过长、不匹配或新边界引入相邻字幕重叠时保留原轴。明确的其他语言不套用中英模型；自动且没有语言标签时按文字尝试，仍必须通过声学核对 |
| 轻量降噪 | GTCRN，4 秒窗口、160 ms 重叠淡化、尾部补齐 STFT 帧后裁回精确原长度 | 保持 16 kHz 原始采样时间轴；干净语音可能受损，可关闭。不承诺所有噪声下准确率提升 |
| 声道选择 | 五端现有 FFmpeg 链路，混合/左/右 | 单声道使用原声道；不覆盖源媒体 |
| 热词 | 新增中英 Zipformer Tiny，原生 `cjkchar+bpe` 与 `modified_beam_search`；最多 100 条 | 此权重使用有状态流式编码器，文件转录也经流式接口执行。原生编码源短语，不能把已切分 BPE 词块再次输入。其他引擎不支持时保留词表并提示，不强行改写原文 |
| 声学复核 | 对齐失败或参考文字差异较大时，字幕列表与编辑页逐条提供复核入口 | “声学匹配度”不等于 ASR 准确率。保留原文、失败原因和参考文字，不自动用第二次声学输出覆盖字幕 |

VAD 补音、重叠等能力可参考 [Silero](https://github.com/snakers4/silero-vad) 与 [whisper.cpp VAD](https://github.com/ggml-org/whisper.cpp#voice-activity-detection-vad)。热词限制见 [sherpa 官方文档](https://k2-fsa.github.io/sherpa/onnx/hotwords/index.html)。这些是实现路径判断，仍需要在项目固定运行库、真实设备和样本集上验证。

## 调度、进度与验证方式

沿用应用级队列、模型租约和取消机制，按“模型准备 → 音频准备/降噪 → VAD/识别 → 时间精校 → 标点 → 静音修整 → 分句 → 保存”报告阶段。下载等待发生在共享推理锁之外；处理时持有主模型及依赖租约。识别器先释放，再依次加载对齐、标点模型。主识别预算仍为 1–4 CPU 线程，额外模型最多 2 线程。五端保留 CPU 路径；主识别可选的硬件加速、实测选择与故障隔离见[本地转录硬件加速](asr-acceleration.md)，本页增强模型继续使用 CPU。

识别进度按实际处理的音频位置，对齐按已完成片段或字符，文本处理按条数；加载阶段显示加载状态。不能把某一阶段的 100% 当作总任务已完成，也不要在尚未测量吞吐时给出精确剩余时间。预估速度使用实际运行的 RTF（处理耗时 / 音频时长），分开记录加载时间、峰值内存和处理时间。

原始 ASR 在增强前即落盘；原始断点与派生结果分开存储。降噪、声道、VAD、补音、热词变化使原始缓存失效；只变标点、对齐、静音修整时复用原始识别。此次派生管线版本变化不会复用包含旧说话人断句的派生缓存。仅变字幕长度可复用派生结果；切换自然分句也会切换标点的续句上下文，这时重做后处理并复用原始识别。取消或增强失败后仍保留完成的原始识别。已入库字幕不会被自动重写。

原生资源通过 `finally` 释放；分段之间允许取消。CTC 文件加载在 Windows 使用 UTF-16，其他平台用 UTF-8，避免含中文路径失败；不通过复制数百 MiB 的模型缓冲加载权重。

验证样本应覆盖连续中文、粤语/日语/英语、混语、长单词与数字、快速和慢速讲话、音乐静音、嘈杂录音、切片边缘和多人重叠语音。识别用 CER/WER，时间对齐用人工边界偏差与覆盖率，字幕展示检查长度分布、闪烁、重叠、首尾时间和文字是否丢失。中文无标点的词内切分另行人工评估。每个可选增强需做开/关对比，不能只用能输出文字的样本检查代替质量评测。

本次分句代码不新增原生库，五端共享实现。Windows 上已使用现有三个本地 ASR 模型做真实输出检查；五个系统的真机表现不能由单个平台推断。Apple/Linux 构建与移动端长音频、后台中断、内存/温升等仍需对应设备验证。

2026-10-19 增强实现的 Windows 实测已覆盖中英文默认完整链路、原始断点复用、时间精校阶段取消、Zipformer 热词、真实标点恢复、中文模型路径及与现有 OCR ONNX Runtime 共存。新实现直接复用固定的 `sherpa_onnx 1.12.12` 和现有 ONNX Runtime，不能单独升级 sherpa 平台包破坏 ABI。Android/iOS/macOS/Linux 的端侧质量、时延和温升仍须对应设备实测；本机测试不是多语言准确率基准。
