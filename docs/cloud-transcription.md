# 云端转录

文档核对日期：2026-10-31。用户使用自己的账号及 API Key，音频直接从软件上传，费用由所选厂家收取。无需自行准备对象存储、公开链接或回调服务器。五家的在线账号转录尚未实测；已执行的验证及其边界见[验证记录](cloud-transcription-tests.md)。

## 使用方法

1. 打开“媒体库设置 → 模型中心 → 服务管理”，选择 ElevenLabs、Soniox、AssemblyAI、Deepgram 或 Google Gemini。
2. 填写自己的 Key，确认模型及识别语言后保存。默认自动识别语言，保留词级时间信息；说话人、热词等附加选项默认关闭。
3. 在原有“转录方式”中选择保存的服务，使用“转录”或“转录并翻译”。保存服务不会自动更换当前默认服务。

Key 需要具备文件转录和文件管理权限。例如 Soniox 需要 Async 与 Files 的读写权限，查询模型还需要独立的 Model listing 权限；缺少模型查询权限时仍可保留内置型号，通过手动样本核对转录能力。权限说明见 [Soniox 官方文档](https://docs.soniox.com/guides/api-key-permissions)。

模型按能力显示语言、字符时间轴、说话人和术语选项。Google 使用 `verbatim` 与词级时间戳，不提供与其互斥的 Smart 或热词选项。AssemblyAI Pro 的语言列表不包含韩语，不会暗中换用另一模型。语言提示不保证把音频翻译为指定语言，翻译继续使用单独选择的翻译服务。

高级设置可以填写尚未出现在列表中的模型 ID，也可以修改服务根地址。新型号默认关闭尚未确认的附加能力；接口若只返回全文而没有有效时间轴，会保留原响应并明确报错。软件不会均摊句子时间来伪造词级时间。

服务管理中的“样本检查”由用户手动触发，上传现有英语短样本，可能产生少量用量。模型列表刷新只查询元数据，不代表账号已经完成过转录验证。

## 已适配的接口

| 厂家 / 初始模型 | 上传、提交和查询 | 字幕解析 |
| --- | --- | --- |
| ElevenLabs / `scribe_v2` | `xi-api-key`；`POST /v1/speech-to-text` 文件表单直传 | 读取 `words`、可选 `characters`，单位秒；保留文字和空格，忽略声音事件；存在 `transcription_id` 时在保存后删除远端 transcript |
| Soniox / `stt-async-v5` | Bearer Key；`POST /v1/files` → `POST /v1/transcriptions` → 查询原任务及 `/transcript` | `tokens` 的 `start_ms/end_ms`，合并子词并保留 Unicode 字素边界；保存后先删除任务、再删除文件 |
| AssemblyAI / `universal-3-5-pro` | 原始 Key 鉴权；`POST /v2/upload` 上传二进制，再提交 `/v2/transcript` | 使用 `speech_models` 数组；读取 `words` 的毫秒时间及 `speech_model_used`；保存后删除 transcript 及其关联数据 |
| Deepgram / `nova-3` | Token Key；`POST /v1/listen` 上传二进制；自动模式使用 `language=multi` | 读取通道内的真实词时间（秒）、带标点单词及模型版本；默认不启用 Smart Formatting |
| Google / `gemini-3.5-transcribe` | `x-goog-api-key`；Files API 可恢复上传，再调用 `/v1beta/interactions` | 读取 `steps[].content[].annotations[]` 内的 `word_info`；严格解析如 `0.100s` 的 Duration；有 Interaction ID 时恢复查询原任务，保存后清理 Interaction 和文件 |

AssemblyAI 的上传 URL、Google 的文件 URI 均由软件自身上传获得，无需用户提供链接。Google 的上传会话地址必须与配置的服务地址同源，禁止把 Key 随重定向发到其他地址。

## 模型更新

服务编辑页先读取缓存；缓存超过 24 小时才在后台刷新，也可以手动刷新。启动应用和捕获转录任务不查询模型列表。

- Soniox 根据 `transcription_mode=async` 过滤；Deepgram 根据 `batch=true` 过滤，并合并模型返回的语言元数据。
- Google 遍历 Models API 分页，只收录文件转录型号，排除 Live / Realtime；该接口可能没有列出全部专用转录型号。
- ElevenLabs 尝试 Models API 中的 Scribe 文件型号。未提供完整转录枚举的响应保留内置清单。
- AssemblyAI 使用已核对的内置清单及手动模型 ID，不通过收费样本推测模型是否存在。

刷新不会改变所选模型，不会删除未在新响应中出现的旧配置。失败或关键结构变化时保留旧缓存。缓存按厂家、服务地址及 Key 隔离，文件名使用不可逆摘要，文件内容没有 Key。语言元数据缺失时不宣称支持所有语言，未确认的新型号默认不启用附加功能。

新型号沿用已适配协议时，可以直接使用已有上传和解析实现。厂商新增响应字段不会破坏解析；鉴权、必要字段、时间单位或任务状态发生不兼容变化时仍需更新适配器。已捕获任务冻结模型 ID、语言、选项、能力及协议版本；厂家自己的模型别名是否指向新权重由厂家控制，不能据此保证远端权重永远不变。

Deepgram 的未知型号不会被假定支持 `multi`：元数据仅有一种语言时使用该语言，否则保留服务默认语言并在界面明确标注。可从已发现的语言列表手动选择。没有使用会自动回退到其他型号的 `detect_language` 来冒充原模型的语言能力；已确认的 Nova-3 默认仍使用多语识别。

## 上传限制与音频准备

软件默认每段最多 10 分钟、文件最多 20,000,000 字节，重叠内容计入限制；同时取当前模型与功能组合的更严格上限。

| 厂家 | 官方限制及软件处理 |
| --- | --- |
| ElevenLabs | 标准模式最长 10 小时，最短 100 ms；说明页 3 GB 与参数页 5 GB 存在差异，软件采用更小值 |
| Soniox | 最长 300 分钟；未确认独立的单文件字节上限，软件仍使用 20 MB 上限 |
| AssemblyAI | 上传接口约 2.2 GB，文件转录最长 10 小时；不套用 URL 导入接口的更大大小限制 |
| Deepgram | 文件上限 2 GB；文档中的 10 分钟为处理超时，软件采用自己的 10 分钟分段策略 |
| Google | Files API 上限 2 GB；词级时间戳或说话人功能将单次音频限制为 30 分钟，不能采用普通转录的一小时上限 |

优先直接使用符合条件的原音频，或复制支持的音轨。需要转码时使用 16 kHz、单声道、64 kbps MP3；音轨复制失败会尝试该兼容预设。只准备当前需要的片段，第一段就绪即可上传，并预取下一段。

上传前检查实际文件长度、已知格式和时长。复用源探测信息和生成过程记录，不增加音频全文件哈希、启动扫描或对转码输出的完整复查。确实超限时进一步分段；明确的格式拒绝才尝试一次兼容转码，收费提交结果未知时不会盲目重传。

相邻段保留短重叠，以真实词边界分配归属、避免整句被误删；同时保留静音和原媒体时间偏移。分段即使乱序完成，也先保存结果，再按连续顺序发布。原字幕、词级信息和译文复用现有增量保存、播放和翻译流程。

音轨晚于画面开始时，按已有音轨时钟保留开头静音；完全处于音轨开始前的片段不生成文件、不调用收费接口。说话人编号由厂家按每段音频分配，不承诺跨段人物身份一致。

热词还有请求长度限制：ElevenLabs 按数量、字符和词数检查，AssemblyAI 每条最多 6 个单词；Deepgram 有总计 500-token 限制，Soniox 上下文有总 token 限制。后两家未公开对应分词器，软件采用保守的字节预算（分别 450 和 7,500 字节），这属于软件限制，不是精确的厂商 token 计数。

## 网络与恢复

“网络设置 → 云端转录”默认跟随设备网络，涵盖模型查询、上传、提交、轮询、下载结果和清理。整体网络方式仍优先；公益接口继续使用原有“语音识别”策略。系统代理、PAC 和 HTTP / HTTPS / SOCKS5 自定义代理沿用统一网络层。代理失败不会偷偷改为直连，TLS 证书继续验证。

每个服务会话复用 HTTP 和 TLS 连接，包括代理隧道；网络变化后新请求使用新线路，在途上传保留原线路。同一厂家、地址及 Key 共用两段识别、一条上传的预算；不同 Key 无法仅凭密钥内容确定是否属于同一个计费账号。遇到明确限流则降为单段并遵守 `Retry-After`，有界重试会重新构造被明确拒绝的请求，不重放结果未知的收费提交。

连接超时 20 秒；模型、提交控制和状态查询 30 秒；同步识别响应最长等待 15 分钟。上传不设置短的固定发送总期限，90 秒没有发送进展才中断；排队与限流等待不计入这 90 秒，发送完毕后停止上传看门狗，进入处理等待。

异步任务立即查询，未完成时按 1、2、3 秒间隔查询；排队超过一分钟使用 5 秒，状态推进后恢复短间隔。服务返回更长的 `Retry-After` 时采用更长等待。

任务断点保存文件引用、任务 ID、原响应和完成段。先保存字幕断点，再清理远端资源；清理失败保留待清理标记。暂停后继续查询原 ID，完成段不再次准备音频或识别。公益接口任务失败后，单项重试、开始失败任务和批量开始都会清除旧远端 ID，只重新提交未完成片段；重试意图也随队列保存。

付费异步接口确认远端任务失败、取消，或查询任务、结果、上传资源返回 404 / 410 时，会持久化作废相应引用，下次重试重新提交该片段；旧格式备份不能恢复已作废的 ID。暂时断网、鉴权失败和未知状态保留原任务。若收费提交已发出但没有收到确定结果，软件停止自动重提；应先在厂家控制台核对，必要时重新创建任务。

Key 沿用现有安全存储，不进入服务普通配置、任务 JSON 或日志。本地模型、公益接口、默认服务及旧任务保持兼容；腾讯、阿里只从新增菜单撤下，已有配置和任务继续读取与维护。

## 维护入口

`cloud_asr_types.dart` 定义能力与冻结选项；`cloud_asr_catalog.dart` 负责模型缓存；五个适配器位于 `cloud_asr_adapters.dart`；协议解析、网络预算、分段分别位于 `cloud_asr_parser.dart`、`cloud_asr_transport.dart`、`cloud_asr_pipeline.dart`。设置页在 `cloud_asr_editor.dart`，运行入口仍为 `ModelTranscriptionRunner` 和 `TranscriptionManager`。

契约、缓存、网络、设置、长媒体与恢复测试已纳入 `python tool/verify_model_integration.py`。不要修改 `test/fixtures/local_model_compatibility.json` 来接受回归；新增字段仅用于新的云端服务任务。

官方依据及逐项验证记录见[云端转录验证记录](cloud-transcription-tests.md)。
