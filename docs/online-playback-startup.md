# 在线媒体续播起播修复与验证（2026-10-28）

本轮将起播保护从 B 站扩展到共用播放服务中的网盘 HLS、网盘原画、音频播客和视频播客，处理页面进入、上下集、通知队列选择及后台播放入口。修复的代码缺陷可以造成“封面和正在打开一直保留，点一次进度条才开始”的症状；不能据此判定用户某次故障一定由代理或某个 CDN 引起。

## 原有保护、替代机制与回归风险

| 原机制及目的 | 本轮处理 | 需要保护的行为及验证 |
| --- | --- | --- |
| B 站前台等待目标画面，防止片头闪现 | 提取 `PlaybackStartupContext`，区分可挂载、目标已准备、播放时钟已启动。所有在线来源适用；后台验证目标位置与音频，不依赖页面纹理 | 暂停打开仍能准备；前台不提前发声；后台不用等页面。Windows 原生直接读取 `time-pos`、`pause`、`seeking` 和解码输出参数 |
| 后台短暂等待后降级为成功，避免纹理永远不出现 | 统一在线起播不再用超时或 `isPlaying` 标志授权成功；必须观察实际时钟前进。暂停意图则以完成目标准备为准 | 防止“按钮已播放，内核没动”；保留本地媒体原有定位和回退逻辑 |
| 精确校正初始位置，避免错误续播 | 初始位置校正、停住的目标画面恢复、停住的时钟恢复各自最多一次。后两者等待 750ms 后才触发；人工跳转优先；已有进展还需新样本确认仍在前进，才能跳过恢复 | 不让初始定位用掉唯一解卡机会；快速起播无额外 seek；不中断健康声音；从零开始同样可恢复 |
| B 站 EDL 一次装载分轨，避免 `audio-add` 破坏续播位置 | 后台明确关闭视频轨时也使用一次 EDL 装载和 `Media.start`，保留真正纯音频的分支 | 背景仅音频、前台加入画面和画质交接继续使用原控制器、轨道政策和精确定位检查 |
| 1.5 秒音频兜底防止未知视频被误判为音频 | 明确的纯音频、延后纹理或主动关闭视频轨，可在时长就绪后以零尺寸完成初始化；仍单独验证音频与目标位置。未知普通视频保留原兜底与运动视频判断 | 不再等待一个明确不会出现的尺寸事件；不能让慢解码的视频冒充音频。几何规则及原生后台仅音频、Mini 加入验证覆盖 |
| 两秒进度保护避免初始化零值覆盖书签 | 在线会话准备和时钟确认期间一直保持可信展示时间线；封面保护复用相同会话。网盘及视频播客页面也复用 300ms 提示与 120ms 封面淡出 | 横竖屏和 Mini 不出现非预期的书签→0→书签；失败保留封面、目标和重试；播放中的短缓冲继续保留当前画面 |
| 页面与通知可能同时宣布播放，保护控制器归属 | 在第一次同步通知前发布可合并的起播 Future；同媒体同代次加入原任务。取消且未完成准备的控制器不能当成健康会话复用 | 防止重复初始化、旧定位返回后覆盖新媒体；定位的每个异步边界检查控制器、请求、seek 代次和目标 |
| 串行媒体通知命令，防止上下集重入 | 上下集仍串行且保留设备重复回调抑制；停止、seek、明确队列选择及时进入服务。队列选择先取消旧起播，再经现有切换锁提交 | 不必等旧起播超时才停止或换集；重复通知不多跳一集；迟到画面、读取和恢复计时器不能抢回旧媒体 |
| 暂停与播放意图在异步初始化后提交 | 统一流程覆盖暂停打开后的继续播放；等待失败重试时也记录最新暂停意图，并传给下一次尝试 | 暂停、通知 seek、重复进入、同项重新选择和自动重试均有行为测试，不用界面状态冒充成功 |
| B 站 30 秒起播预算、网盘分阶段上限，防止层层重试 | 地址、初始化、定位和恢复共用剩余预算；整集重试及网络配置变更继承原单调时钟。保留网盘解析/初始化阶段上限及播客 12 秒时钟确认上限 | 不允许每次重试重新得到 30 秒；网盘解析绑定取消令牌，迟到返回的 lease 必须释放；B 站地址最多强刷一次的状态随重试继承 |
| 网络变更后旧连接和回调失效 | B 站、网盘和播客加载中继续当前预算并隔离旧会话。成功播放仍沿用既有网关重连策略 | 不改变用户的直连/代理选择，不升级播放器依赖，不改持久化格式；Range、缓存完整性、背压、断流恢复继续由原网关负责 |

参考了 [PiliPlus 当前播放器实现](https://github.com/bggRGjQaUbCoE/PiliPlus/blob/main/lib/plugin/pl_player/controller.dart) 中将分轨地址作为 EDL、在一次 `open` 中携带续播位置的做法。本项目保留自身的网关、轨道恢复、尺寸和会话所有权保护，没有引入该项目的依赖或整套播放器。

## 受控修改前后对比

使用同一套假平台、媒体书签、解析结果和故障：第二个控制器确认初始化与播放，但实际时钟冻结；只有一次新的定位才能使它恢复。修改前代码来自本轮编辑前的备份，放入隔离目录运行；为兼容工作区并行新增的音质菜单，仅加入了本测试不会调用的空 UI 接口，未改起播行为。

| 来源 | 修改前 | 修改后 |
| --- | --- | --- |
| B 站 | 返回后 100ms 内进度前进 0ms，只定位一次，没有自动恢复 | 919ms 内确认恢复，采样前进 101ms，总计两次定位 |
| 网盘 HLS | 进度前进 0ms，没有自动恢复 | 899ms 内确认恢复，采样前进 101ms |
| 网盘原画 | 进度前进 0ms，没有自动恢复 | 909ms 内确认恢复，采样前进 106ms |
| 音频播客 | 超过 3 秒仍未完成起播 | 916ms 内确认恢复，采样前进 105ms |
| 视频播客 | 超过 3 秒仍未完成起播 | 921ms 内确认恢复，采样前进 108ms |

这是可重复的故障注入比较，计时包含 100ms 验证采样，不是公网 CDN、代理性能或所有媒体的速度保证。记录：`build/online-startup-benchmark-before.jsonl`、`build/online-startup-benchmark-after.jsonl`。生成的比较用例保存在 `build/online-startup-benchmark-generated-test.dart`，永久回归用例在 `test/online_media_startup_test.dart`。

## Android 离线回前台与缓存起播补修（2026-10-29）

用户确认新的永久“正在打开”发生在 Android：完整下载的 B 站视频，其原视频已下架，返回桌面后再回到播放页，声音和进度继续，封面不消失。这是上一轮按逻辑来源设置封面保护遗漏的本地文件分支。

保留文件仍有 `bilibiliStream` 来源标识，但实际已经持有本地文件 lease，Android 交给本地平台播放器。原来的前台恢复根据来源标识创建在线分轨画面等待；本地文件没有在线分轨启用回调，等待无法完成。现在按实际播放资源区分本地文件与网关，只让真正使用网关及对应内核的会话进入该等待。没有通过超时直接撤封面掩盖尚未准备好的在线画面。

同时确认了缓存启动的额外等待：已有索引且完整的文件，在取得播放 lease 前还会先扫描物化目录并发布索引。另有媒体库未挂接、记住历史音质选择两条路径会绕过完整文件，进入在线地址解析。当前播放会话重新进入页面时，也可能先查缓存而延后复用。

| 原保护及目的 | 替代机制 | 潜在回归与验证 |
| --- | --- | --- |
| 回前台时为 B 站设置封面，防止加入视频轨时闪出片头 | 检查实际网关 lease 与播放器归属。本地保留文件不创建无人完成的在线分轨等待；真正在线仍保留原保护 | 已下架本地文件在播放/暂停状态下分别连续前后台三次，控制器和播放意图保持；在线 Mini、丢首帧恢复及慢 CDN 原生场景继续通过 |
| 先扫描目录补齐缓存注册，再取得文件，保证完整性 | 优先调用原有完整文件 acquisition；命中返回已验证 lease。未命中仍扫描、发布、重新 acquisition，再走原物化后备 | 扫描永不返回时，已索引文件仍可取得；未索引完整文件仍可发现；未完成缓存不会被当成完整文件；明确请求的清晰度不能被其他文件替代 |
| 依赖媒体库挂接，并因文件音轨未知而避开历史音质偏好 | 冷启动先查完整文件；媒体库未挂接时使用同一缓存 runtime 的 acquisition hook。可选音质菜单异步补全，失败不阻塞本地文件 | 媒体库挂接前/后、原视频下架、历史 HiRes 选择均覆盖。用户主动切换音质仍走对应在线音轨，暂停继续后保留这次选择 |
| 同视频再进入时尝试将在线控制器提升为本地缓存 | 正在播放的会话先复用原控制器；暂停会话仍保留原提升机会，但不覆盖主动音质选择 | 模拟缓存查找永久等待，正在播放的同项再进入仍立即复用，无新建控制器、额外 seek 或缓存查找 |
| 网络设置变化时重连准备中的在线会话 | 当前资源为完整本地文件时不重连；真实在线的取消、代次和剩余预算机制不变 | 本地文件准备中切网络政策不重建；共享在线网络切换、请求竞态和旧回调测试继续通过 |

新增行为测试在修复前复现了索引命中等待扫描、媒体库未挂接时绕过缓存，以及播放/暂停两种前台恢复永久封面。原始失败保存在 `build/offline-resume-before-tests.jsonl` 和 `build/offline-resume-before-lifecycle.jsonl`；没有放宽原来的封面或清晰度断言。
