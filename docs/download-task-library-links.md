# 下载任务与媒体卡片

## 下载、入库与队列规则

- B站下载、yt-dlp、抖音和浏览器下载在传输及必要处理成功后固定自动入库。解析、入队是否立即开始下载仍遵循各页原有规则；B站在线解析添加在线卡片，缓存管理仅为已有媒体保存画质版本。
- 下载完成与入库成功分别处理。入库失败保留成品，通过“重试入库”恢复，不重新下载；文件丢失明确提示重新下载。
- 批次首次开始时冻结有效任务的逻辑队列顺序，合集、播放列表和分P保留源内顺序。完成项立即入库，后来完成的前项归回原位；失败项不阻塞其他成员，之后插队不改变已冻结的入库排列。
- 下载批次、成员顺序和操作标识同时持久化在任务与媒体库中。重复完成通知和保存失败重试复用同一媒体卡片，队列记录清除后仍能维持批次顺序。媒体库手动排序优先于后续自动排列。
- 各媒体导入队列独立设置“成功入库后移除队列记录”，默认关闭。只有卡片、关联文件及排列确认保存成功后才能清理记录，正式媒体和其他分P、画质保留。B站在线卡片后台补充附加信息不依赖解析记录继续存在。
- 队列操作默认作用当前筛选列表，选中后作用所选项目，按钮显示可执行数量；全局操作在更多菜单中明确标为“所有任务”。切换筛选、来源或搜索会清除选择，折叠父任务保留子项选择。
- 窄屏使用固定底部队列控制，宽屏放在列表上方。单项主操作随状态变化，清理、重新下载和调度优先级等低频操作放入更多菜单。

## 下载任务与播放入口

哔哩哔哩下载、哔哩哔哩在线解析、yt-dlp、抖音和浏览器导入的任务在成功入库后，标题带下划线。点击标题打开实际导入的媒体卡片播放页；已有的预览播放入口仍保留。哔哩哔哩合集和多分 P 的总标题保持展开作用，具体分 P 的标题可进入对应卡片。

- 每个任务记录最后一次成功导入返回的媒体 ID；重新下载或导入失败时保留上一次成功的关联。
- 打开卡片保留当前播放队列及播放模式。队列中已有该媒体时直接选中，否则追加一次。播放器继续遵循“进入页面自动播放”的设置。
- 追加队列之外的媒体后，保留现有条目作为自定义队列，避免原文件夹或尚未完成的网盘目录加载覆盖它。
- 点击浏览器下载队列的标题时，先暂停网页媒体，再进入卡片，避免两边同时发声。
- 最新关联卡片被删除、移入回收站或本地文件失效时显示提示，不用同名卡片或较早的导入代替。
- 旧哔哩哔哩和 yt-dlp 任务在缺少媒体 ID 时，只按确切来源或路径恢复关联，并按入库时间选取最新卡片。无法确定时提示，不按标题猜测。

逻辑使用三端共用的 Flutter 页面、任务存储和播放队列，不引入平台专用接口。

回归覆盖任务 ID 的保存与恢复、重复导入、批量中途失败、删除与回收站、浏览器暂停期间删除、重复点击、文件失效，以及顺序/随机/单曲循环模式下的队列保留。使用自动化测试验证，无需操控桌面应用。
