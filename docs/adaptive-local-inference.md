# 本地模型自适应调度

默认采用自动加速和有界流水线，旧设置中的 2 迁移为自动；1、3、4 保留为手动上限。旧的自动、优先流水线使用相同的新策略，显式省内存和旧队列的线程偏好保留。CPU 数量、内存余量、播放意图、省电、热状态和 Flutter 帧耗时共同决定资源预算，模型、量化精度、增强选项和分句规则不参与性能调节。

## 运行与保护

实际可用核心数同时受物理核心、进程 affinity、容器配额限制。总计算预算为 `C - max(1, ceil(C/4))`，移动端最多 6，桌面最多 12；播放时最多使用约一半核心。识别使用当前剩余预算，流水线辅助阶段预留 1；没有辅助阶段时不预留。翻译区分提示处理和逐词生成，并保留逐词生成的已有测速选择。手动值为上限，不是保证分配量。所有推理阶段共享预约内的总预算。

工作流拓扑与模型驻留分开：默认保留两块流水线容量，至少两个计算线程且资源信息可靠时允许下一块降噪与当前块识别重叠，辅助模型始终由同一个工作实例顺序使用。不能同时驻留转录、精校和翻译模型不再禁止整条流水线。冷加载识别模型及需要腾出空间的精校/标点加载先排空原生调用，再释放闲置模型；语言与实际时间轴决定是否需要精校，不为未使用的模型收费。

翻译取得独占计算时段。可同时驻留 ASR/GGUF 时，首批及时交接，之后将零散转录窗口聚合到默认 8 条或 45 秒音频再交接，手动小批次和资源压力会缩小目标；不能同时驻留时，在不超过 90 秒音频或 32 条稳定字幕的边界集中翻译，超限的单批立即处理，尾批在根推理预约结束前强制排空。后续静音窗口也推进交接期限，避免已有待译字幕一直等到任务结束。一次交接合并成一次翻译调用，避免循环调用每个小转录窗口而反复处理提示词；保留字幕编号、时间轴、先后顺序及滚动上下文。翻译实例在一次交接内复用，交替驻留时返回识别前释放；原生翻译仍默认每批最多 8 条并保留 800 字符上限。取消和失败保留已完成的译文及原始识别断点。

Hy-MT2 的自然结束响应偶尔会漏掉 JSON 行的外层闭括号。仅在字符串本身完整、标准 JSON 解码成功、编号唯一且内容校验通过时补齐这个格式符号，避免对已生成的完整译文再次推理；生成被截断、字符串未闭合、标签或占位符丢失仍需补译。设置、模型、精度及字幕分句均不因聚合改变。

一般压力减少线程、预读与批次，预算仍有两线程时可保留流水线；严重压力或确实不足时临时降为一块。大模型交替驻留只在对应阶段收窄流水线，阶段完成立即恢复其它允许的重叠；实际内存准入压力则需要连续健康 30 秒才恢复，采样中断不算健康时间。不再被启动时的一次内存判断锁定整个任务。已在运行的原生调用结束后才释放资源、重建线程配置，绝不从另一线程直接释放正在使用的实例。

模型中心为本地转录、本地翻译提供独立设置页，各自显示本机推荐与当前分配；线程、测速与调优清理收在高级设置。推荐使用相同资源探针的一次性快照，不在设置页启动轮询或加载模型。逻辑核心数收在设备详情。恢复推荐只改当前功能的性能参数，返回位置与高级设置的展开状态持久保存。运行状态分别显示流水线、集中翻译、临时顺序与具体原因，自动降档不会冒充用户选择的省内存模式。

两次连续的 2 秒窗口慢帧比例超过 10%、中等热压力或省电模式会减半预算、将翻译限制为每批最多 4 条；超过 25%、严重热压力或内存警告会改为单计算线程、顺序阶段、单条翻译，并在调用边界短暂让步。普通降速不暂停任务。连续健康 30 秒才逐档恢复；信号失效时不升档。内存警告、系统后台期限与原来的任务中断通道分别处理。

加载前重读可用内存，保留系统余量；将权重、CTC、翻译上下文与缓冲的保守放大估算作为新增分配量。并发加载使用分配票据，不能同时花掉同一份可用内存。已驻留模型不重复扣账；余量不足时先回收闲置模型。记录播放器进程和已登记推理子进程的占用。无法满足准入时保存有效断点，明确提示释放资源后继续。

## 平台监测

| 平台 | 实现 |
| --- | --- |
| Android | 独立 `model_resources` 通道；ActivityManager 内存、低内存回调、省电状态、API 29 热状态、API 30 热余量。热余量最多每 10 秒一次。ASR 服务返回独立进程 PID。 |
| iOS | 应用可分配内存、进程 footprint、热状态、低电量模式与内存警告；后台到期继续使用原来的任务中断回调。 |
| macOS | 内存压力事件、主机内存统计、进程及子进程 RSS、物理核心与热状态；不调用 iOS 专用内存接口。 |
| Windows | 系统内存、低内存通知、affinity、物理核心、电源与子进程 RSS；所有查询句柄随监测结束释放。 |
| Linux | MemAvailable、RSS、affinity、cgroup v2 当前组及祖先配额/内存压力；旧系统回退 v1 或主机统计，不需要 root。 |

仅在本地推理预约或测速期间监测。常规采样 2 秒；原生警告立即影响预算。Flutter 根据实际屏幕刷新率计算慢帧；不主动产生帧测量 FPS。播放意图来自播放器的传输状态，不将网络缓冲直接视为算力不足。缺失内存信息、过期信号使用至多两线程的顺序策略，禁用额外自动测速。界面实际配置最多每秒更新一次。

## 渐进调优与硬件加速

先开始正式工作，再从累计有效推理时间中积累测速额度。自动测速软预算为有效推理时间的 5%，每模型每日最多 30 秒；加载和恢复成本计入。每次只探索相邻线程配置（1、2、4、6、8、12），至少两次有效同输入对照、预计净收益达到 10% 才采用；接近时选择更少线程。识别最多暂存 3 秒本地样本，翻译使用当前已完成批次的相同提示，测速输出不会提交字幕或断点。翻译的提示和生成线程分别探索。

自动记录先落盘保留测速额度，防止进程退出后无限重新测速。记录包含配置、耗时、两次对照与观察到的内存/慢帧统计，不含音频、提示或字幕。缓存按设备/系统、模型身份、固定运行库、可得的运行组件身份与播放场景区分，默认 14 天。设置可清除本机调优记录。

新 GPU 组合的编译峰值和耗时未知，默认不在第一次转录/翻译前进行大规模 GPU 对比；可在模型中心主动测速，之后自动结合冷启动耗时与任务量复用已验证的记录。CPU 有预算的邻近探索会渐进进行。Windows/Linux GPU 推理在子进程中执行；Android ASR 使用独立服务。Android 翻译 Vulkan 仍为手动试验选项。没有“GPU 线程数”设置。

GPU 失败仅重试未完成部分；取消和暂时性内存不足不作为硬件损坏缓存。原生推理合作取消，不承诺立即抢占。不会修改整个播放器的进程优先级，不绑核，也没有升级基础推理运行库。

## 验证与发布门槛

确定性测试覆盖五个平台的 1/2/4/8/16/32 核预算、手动上限、配额、失效信号、慢帧、热状态、滞回、并发总预算、取消与分配票据；配置测试覆盖迁移、冻结队列、旧线程断点与云服务序列化。流水线、翻译编号/标签/占位符、GPU 回退和流式交接沿用并扩展原有回归。

可选的 `asr_workflow_native_test.dart` 对四个真实 ASR 模型比较顺序释放、复用、双阶段、降噪领先和自适应模式的完整文本/时间轴/元数据哈希。`local_translation_runtime_test.dart` 对两种 GGUF 模型验证双向翻译、标签、占位符及取消。运行时需要本地测试权重，不会自动下载大模型。

CI 固定 Flutter 3.44.2 / Dart 3.12.2；Windows、Linux 和 Android 新增构建检查，iOS、macOS 保留构建检查并固定 Flutter 与宿主系统版本。CI 成功与本地构建不代表真机性能验收。

本机验证记录（2026-10-20，Windows 宿主）：

- 316 项回归通过；随后对可用性检查入口等收尾改动补测 78 项，通过。另有仅显式启用才运行的原生用例。
- 四种真实 ASR 权重、五种执行方式的完整结果哈希一致；原生 CPU 线程对照、重载及生产转录断点恢复通过。
- Hy-MT2 与 Qwen3 的真实 CPU 推理通过双向翻译、标签/占位符和取消测试；另验证了自动 CPU 调优不会覆盖正式译文，额外加载及耗时可单独统计。
- Windows 与 Android Release 构建已验证。Android 末轮因 Maven 连接失败，使用本地已有的相同依赖离线完成，不替换推理运行库。
- Linux/iOS/macOS 的本次构建尚未在对应宿主执行；CI 配置已补齐，但没有把未运行的 CI 记为通过。原生测试的计时也不作为设备吞吐承诺。

**发布前仍需设备矩阵验收**：五端低、中、高档设备在 Release 下运行至少 30 分钟音频、连续翻译、播放与滚动并存场景；记录首次结果、吞吐、额外测速、输入 P95、慢帧、热状态及应用/子进程峰值。与相同设备和媒体基线比较，AI 新增慢帧不超过 3 个百分点、输入 P95 不超过 100 ms、无持续音频中断、稳定吞吐不低于旧保守配置的 95%。未达到门槛的组合不得作为已验证的自动加速配置。Windows 主机不能代替 Android/iOS/macOS/Linux 真机验收。
