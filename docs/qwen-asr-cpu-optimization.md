# Qwen CPU 流水线与英文字幕优化（2026-10-29）

本轮继续使用 Qwen3-ASR 0.6B / 1.7B 的原 FP16 权重、解码参数和原生识别组件。优化接在现有转录、转录并翻译及增强流程中，没有更换识别模型。

## 已实现

- Qwen 共享对齐领取独立的重计算许可，最多请求 6 个线程，并受用户线程上限、播放、温度和内存预算进一步限制。执行时与 ASR / 本地翻译互斥，避免把大模型对齐长期挤在轻量辅助的单线程里；降噪、标点和英文 CTC 继续使用轻量通道。进度显示实际增强线程数。
- 新任务捕获 `asrTextProcessingVersion: 2`。Qwen 英文精校复用已有 `asr-alignment-en-int8`（95,212,816 字节），一次对齐最长 16 秒的完整语音句，从声学结果取得词边界，再调用原有自然分句。
- 自动语言的新任务冻结英文 CTC 和原多语言组件；手动指定英文时仅准备英文对齐组件。已有任务仍按冻结的版本和依赖解析；v1 Qwen 任务继续使用原共享对齐器。
- 对齐文字只用于求时间，保留 Qwen 识别原文。声学文字差异、边界冲突或对齐不可靠时保留原时间，不按字数分配时间。不启用时间精校时仍尊重用户设置。
- 对齐器复用匹配线程配置的已加载上下文。容量为 2 的队列、资源压力下交替驻留、取消、稳定批次和翻译交接沿用原实现。
- 处理版本仅影响增强指纹；原始 ASR 指纹保持不变。原有模型、默认选择、已完成译文和兼容性基线保留。

## 实际视频检查

设备为 Windows / Ultra X7 358H / 约 32 GB / Arc B390，本节使用 CPU。输入为用户指定视频的前 390 秒，16 kHz 单声道；未清空系统文件缓存，未另外施加播放压力。

`test/qwen_asr_cpu_pipeline_native_test.dart` 使用生产 runner 和应用真实 Windows 资源监控：

| 检查 | 实测 |
| --- | --- |
| 0.6B 完整降噪 → ASR → 时间精校 → 自然分句 | 390 秒音频 / 129.904 秒，约实时 3.00 倍 |
| 主 ASR 模型加载次数 | 1 次 |
| 新转录的字幕 | 121 条，无超过 160 字符的长段 |

这不是旧版与新版全程耗时的直接对照，不能据此宣称整体提升了固定倍数。转录并翻译还需叠加所选翻译模型的耗时。

## 用户所附 SRT 的整理

对原来的 100 条字幕使用对应原视频音频做 CTC 对齐，再运行原自然分句。没有重新生成识别文字：

| 指标 | 整理前 | 整理后 |
| --- | ---: | ---: |
| 字幕条数 | 100 | 109 |
| 超过 160 字符 | 6 | 0 |
| 最长字幕字符数 | 258 | 95 |

100 条中 86 条取得可采用的声学时间，其余保留原时间；所有字幕去除排版空白后的文字完全一致。此检查耗时 26.574 秒。原 SRT 未覆盖，输出为 `.artifacts/qwen-speed-20261029/captions/english-refined.srt`。

原分句功能一直有调用；原来长段主要因为 Qwen 无原生词时间，且部分共享对齐未通过校验，分句器会保留整段。新路线提供可靠声学切点后，原分句器即可工作。

## 共享对齐的 CPU 预算对照

使用同一固定 Qwen 共享对齐文件、同一原生组件、同一视频的三个语音段：

| 原字幕条目 | 1 线程 | 6 线程 |
| --- | ---: | ---: |
| 1 | 9.36 s | 1.94 s |
| 51 | 16.00 s | 3.18 s |
| 59 | 16.67 s | 3.35 s |

这些是对齐阶段耗时，非整个任务提速。条目 1、59 在两种线程配置下仍未通过原始时间次序检查，继续回退；增加线程不会把失败结果标成成功。日韩等语言继续使用共享对齐，具体收益受设备和资源许可影响。

## 验证与复现

原始报告位于 `.artifacts/qwen-speed-20261029/`：`subtitle-baseline.json`、`baseline-asr/`、`baseline-alignment/`、`captions/cpu-pipeline.json`、`captions/english-refined.json`。首轮使用静态资源快照的测速触发保守限速，已作废；表中全程结果来自应用真实资源监控。

```text
python tool/verify_model_integration.py --native --output .artifacts/qwen-speed-20261029/verification
flutter build windows --release --no-pub
```

专用视频检查需显式传入 `QWEN_CPU_AUDIO`、`QWEN_CPU_SUBTITLES`、`QWEN_CPU_OUTPUT` 和可选 `QWEN_CPU_SECONDS`，不会在应用启动时测速或下载。`tool/profile_qwen_cpu.py` 也仅为维护者手动比较。

最终结果：79 个分析目标无问题，834 项回归通过（3 项既有跳过），6 项原生转录 / 翻译 / 取消恢复检查及 2 项用户视频检查通过。Windows Release 构建成功（102.6 秒）；发布目录原生收据、随包目录清单与整理版字幕校验通过，原生识别组件及兼容性基线与本轮修改前一致。验证摘要为 `validation-summary.json`，最终回归在 `verification-final/`，原生检查在 `verification/`。

整理版同时保存为 `build/windows/x64/runner/Release/Downloads/ai.downloaded.1793283388903.refined.srt`。新建任务使用 v2；已有冻结任务继续按原版本恢复，不改写已经完成的字幕和译文。

本轮实机验证限 Windows；其余系统复用原英文 CTC 与平台无关的调度、分句代码，尚未实机复测。此次原生识别组件没有变化，不需要用户安装开发工具。
