## 复测中额外修复的问题

- 字幕侧栏暂停时不会收到播放事件，首次展示或更换字幕后可能没有当前行高亮：在依赖和数据变更时同步索引。
- 触摸选区停在视口边缘时，列表继续滚动而选区没有继续扩展：使用 Flutter selection delegate 在滚动布局完成后更新拖动边缘，验证实际选中文本。
- 长双语字幕预设在滚动容器中没有有效高度约束：按可用视口限制高度，保留普通字幕布局。
- ZIP 解压返回时异步关闭仍未完成，Windows 随即清理会碰到文件占用：同步提取路径使用 `clearSync()`。
- Python 分片下载异常时输出流可能残留：在分片任务结束路径关闭输出流，验证下载失败后的文件清理；同步 iOS 运行时副本。
- 网盘 API 在收到响应头之前取消时，Dart `abort()` 可抛 `HttpException`：统一转换为现有取消失败类型，新增延迟响应头的回归测试。普通断连也转换为可读错误。
- Windows 插件依赖目标名过长，首次构建成功后，增量构建仍可触发 MSB3501：缩短内部目标名，并删除新 CMake 不接受的 TARGET / DEPENDS 组合；保留上游版权和本地变更说明。
- 应用源码导出排除 `windows/ffmpeg_kit_prebuilt/`，将这些预编译输入记录为哈希清单，避免把 DLL 当成应用源代码一起导出。实际本机 FFmpegKit DLL 报告 FFmpeg `n7.1.1`，与独立 CLI 8.0.1 分开记录，仍需匹配其构建来源。
- 干净测试目录补齐跨平台工程源文件；智能翻译基准改用自动创建的独立产物目录，不再依赖本机旧文件夹；Windows 临时目录清理只有限重试已复现的共享 / 非空错误，不把重试加入应用逻辑。
- 独立构建目录曾复制到调试生成的 Android 插件注册文件，正式构建引用不存在的 integration_test：复制工具排除该文件，由 Flutter 在正常正式构建准备阶段重新生成。
- 更新过时 UI 测试对菜单、翻译智能默认、通知和安全区的预期；没有删测试，也没有把真实 Provider 断言用 try/catch 吞掉。

## 公开发布前仍需完成的事情

1. **对应源码交付**：收齐 FFmpeg / FFprobe、libmpv、FFmpegKit 和 yt-dlp 独立包内依赖的匹配源码、补丁、配置和构建脚本。`docs/releasing.md` 已记录精确版本及缺口；应用源码 ZIP 不等于全部第三方对应源码。
2. **缺失材料的可执行处理路线**：优先核实原发布者提供的匹配材料；无法建立对应关系时，使用固定源码与构建脚本重建，或替换成公开完整材料的构建，再跑真实解码 / 转录 / 下载回归。不要只换一个较新 DLL 就宣称问题解决。
3. **外部服务条件**：发布前仍需核实所用服务的使用条件；当前记录不作已完成授权核实的声明。
4. **历史公开范围**：旧 Git 历史仍可能包含退休字体和本机对话导出，不能把当前索引清理说成清空历史。若新建公开仓库，可从本轮干净应用源码 ZIP 建立新历史并保留第三方署名与许可，不复制旧 `.git/`。已有公开副本仍需按原授权和实际范围另行处理。
5. **真机与平台**：在 Android API 36 覆盖旧版升级、通知控制、后台下载 / 转录、文件访问和横竖屏；在承诺支持的 Apple / Linux 环境验证构建与播放。构建成功不能替代这些行为验收。

对应源码问题的依据见 [GNU GPL FAQ](https://www.gnu.org/licenses/gpl-faq.html#SourceAndBinaryOnDifferentSites)。Windows libmpv 旧构建材料的缺口也见 [media-kit 上游讨论](https://github.com/media-kit/media-kit/issues/1460)。这些链接用于解释现状，不代表上游为本应用提供了授权审核。

后续优化按“来源可追溯 → 平台验收 → 模块维护”进行。新增依赖先记录版本、哈希、许可和打包位置；对播放会话、下载和存储模块逐步建立行为接口后再拆分。Android 候选约 415 MiB，其中多套 CJK 字体占明显体积；后续可比较变量字体或按需字体包，并以字幕字形、字重和离线体验回归作为前提，本轮不直接删掉用户已可选的字体。局域网加密和大型架构调整不混入本轮发布收尾。
