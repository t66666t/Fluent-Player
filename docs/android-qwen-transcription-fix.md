# Android Qwen 转录与字幕增强修复（2026-10-31）

## 问题与修复

- **临时音频被拒绝**：Android Flutter 的 `Directory.systemTemp` 实际指向 `code_cache`，旧桥接只允许 `files`、`cache` 和外部文件目录。同一份音频放在 `code_cache` 稳定复现“Qwen 音频请求失败”，放在 `cache` 可以真实识别。现在允许应用自己的代码缓存及外部缓存目录，仍通过规范化路径限制和文件描述符传递音频；不可读取、权限和进程退出分别提示。
- **连续阶段误退出**：关闭旧原生所有者后的三秒计时器可能属于已经销毁的 Service，仍会杀死同进程新建的 Service。现在仅对尚未完成取消的执行器保留看门狗，并以进程内代次隔离旧 Service / 所有者。正常释放不再触发延迟杀进程；卡住的最后一个所有者仍可终止。
- **GPU 驱动故障**：本机 Vulkan 可加载，实际解码在厂商 `vulkan.adreno.so` 的 `vkGetDeviceFaultInfoEXT` 崩溃；自动流水线也出现长时间停留在精校阶段的情况。未将阶段进度停留自行当成已证明的驱动死锁。Qwen 在新所有者中重试 CPU，另为无响应的 GPU 请求加入 120 秒保护：终止私有工作进程，Binder 确认进程退出后才唤醒重试；CPU 请求仍保留原有 720 秒上限，加载仍为 300 秒。同进程其他 CPU 识别、分词和语言识别所有者也能重新建立，不复用失效上下文；显式取消不重试。确认崩溃或超时后，同一应用会话的其他 Qwen 组件跳过故障 GPU；内存回收和普通取消不会触发此标记。失败还会写入 14 天的设备记录，重新测速成功或清除记录后可以再用 GPU，不是永久黑名单，也没有替换系统驱动。
- **内存过度预估及路由过早**：原来在语言判定前，直接按所有已安装对齐器中最大的一个做硬性准入，并把 Qwen FP16 权重计为三份。现在先单独判定语言、释放 LID，再按实际模型准入。已判定为未知的片段不再预留任意语言的大模型。CPU 映射权重估算为一份权重加 1 GiB 计算余量；GPU 保守预留两份权重加余量，另保留 160 MiB 文本处理预算。模型中心手动精校检查和 Qwen 测速使用同一估算；GPU 测速中断保留已完成 CPU 结果，不写入无效加速标定。

设备总内存不等于系统当前可分配内存。仍读取系统可用内存，并保留移动端 256 MiB 安全余量；没有绕过保护或把虚拟扩展内存算成可用物理内存。预算是准入估算，不是承诺所有设备具有完全相同的峰值。

## 流水线及精校选择

音频准备 / 降噪 / VAD → 原模型识别 → 语言判定 → 本批分词与精校 → 原有字幕整理 → 稳定批次 → 原有翻译。

| 任务 | 精校路由 |
| --- | --- |
| 原模型的中文 / 英文 | 原中文 / 英文 CTC；可靠原生词时间继续复用 |
| 支持日韩语的原模型 | 需要精校时使用共享 Qwen；分词可独立使用 |
| Qwen 新任务 v2 英文 | 冻结且已准备的英文 CTC 优先 |
| Qwen 其他受支持精校语言 | 共享 Qwen 对齐器 |
| 未知语言或无匹配对齐器 | 原有时间，不按字数伪造词时间 |

容量为 2 的有界队列及原有资源门控继续使用。需要大模型时先释放可回收的识别 / 旧对齐器；GPU 预算不够先尝试 CPU 精校，仍不够则保留识别文字、原有时间和复核说明。标点及分词的可选阶段也不能因内存压力丢失已识别文字。取消仍中止任务，普通实现错误仍正常上报。

旧任务身份、处理版本、原始识别断点、已完成译文、默认模型和下载文件没有迁移。`test/fixtures/local_model_compatibility.json` 保持原样；没有启动下载、测速或运行库升级。

## 实测记录

手机：24122RKC7C，Android 17 / SDK 37，系统报告总内存 14.76 GiB。测试使用用户当前连接的小米手机；此前平板不在本轮通过范围。

音频：用户提供的《蜡笔小新 日语合集》`BV1ajb3zGEi3` 第一分 P，取其中连续 150 秒。维护者检查入口使用隔离的任务目录和已安装权重，不读写用户队列或下载新模型。

| 检查 | 结果 |
| --- | --- |
| 同音频的 `code_cache` / `cache` CPU 识别 | 修复后均成功，输出一致 |
| 12 秒实际日语音频 CPU 识别 | 4.175 秒，非空日语文字 |
| Vulkan 原生进程崩溃后 CPU 重试 | 自动恢复；应用保持运行 |
| 150 秒日语 Qwen + 默认增强，CPU 对照 | 125.371 秒，41 条字幕，10 次音频准备；跨批处理和恢复通过 |
| 150 秒日语 Qwen + 默认增强，自动加速 | 315.136 秒，包含 Vulkan 尝试及 CPU 回退；最终 41 条字幕均为 CPU，跨批与恢复通过 |
| 有效日语精校及异常时间保护 | 存在实际采用的 Qwen 对齐结果；倒序等不合格结果保留原时间及复核信息，输出时间检查无越界 / 倒序 |
| SenseVoice 自动中文，预算上限 4.87 GiB | 实际中文 CTC 对齐、字幕整理、恢复通过；没有加载日语大对齐器 |
| SenseVoice 日语，预算上限 1.2 GiB | 识别与分词完成；精校内存不足时保留文字和原时间，并给出说明 |
| 25 秒解码中取消，再建立 CPU 所有者 | 取消输出被丢弃，新所有者真实解码成功 |
| 音频语言识别临时路径 | 两种缓存目录均返回日语，置信度 0.9983 |
| GPU 故障后的共享组件选择 | 后续能力查询明确跳过 GPU，CPU 重新识别成功 |
| 最终正常 APK 的 GPU 无响应保护 | 测试工具只暂停私有 GPU 工作进程；生产桥接在 120.267 秒结束请求，能力查询说明本次改用 CPU，新 CPU 所有者 8.616 秒完成 25 秒真实识别 |
| 显式测速的 GPU 内存准入失败 | 保留已完成的 CPU 结果，不写无效 GPU 标定 |

4.87 / 1.2 GiB 是检查工具施加的预算上限，不是声称手机在整个过程一直恰有这些空闲内存。单模型 25 秒实测原生进程峰值：Qwen ASR CPU 2,678,572 KiB，对齐器 CPU 2,700,060 KiB；多阶段运行观察到同一原生进程峰值 4,150,360 KiB。多阶段峰值包含重叠 / 复用，不能当成单个对齐器所需内存。

本机 CPU 对照明显快于包含故障尝试的自动模式；不能把自动模式的 315 秒归因于同一个已确认的超时事件。120 秒保护通过独立的受控故障测试验证，不把人为暂停声称为自然发生的驱动死锁。最终安装状态见本次制品收据。CPU / Vulkan 失败恢复的结果不能表述为 Vulkan 成功推理，也不代表其他 Android 厂商驱动、CUDA 或 Apple / Linux 已通过本轮实机验证。
