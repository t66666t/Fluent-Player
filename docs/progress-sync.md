# 媒体库设备同步

在自己的设备之间同步已有媒体库的内容和观看进度。默认使用同一局域网，不需要注册账号或购买服务器；已有 WebDAV / NAS 可作为可选的记录中转。

## 开始使用

1. 两端打开「媒体库设置 → 设备同步」，添加设备。主动绑定或发起同步时会自动开启服务，不必再单独找一次开关。
2. 点附近的设备，核对两端六位确认码，两边都选择「相同，允许连接」。只会向明确关联的设备分享文件夹。
3. 在设备下面点「同步文件夹」，或在媒体库文件夹里点「同步到设备」，选择已配对的设备。对方看到「想与你同步」后只做一次选择：

   - **关联本地文件夹**：选自己媒体库里已有的文件夹。两边名称可以不同，各自的位置和名称都保留。
   - **接收新文件夹**：默认放在媒体库根目录，也可以展开「保存到」选别的父文件夹。
   - **忽略**：结束这次请求，不改双方已有的媒体库。

4. 接受之后就开始双向补齐原文件、子文件夹和观看进度，不需要再确认「开启自动同步」或「只同步进度」。已有的相同内容会复用，不会再传一遍；只有一边有的内容会补到另一边。空文件夹也可以先关联，以后放进去的条目会自动同步。
5. 正常观看和管理媒体库。默认「智能双向」会交换两端新增、修改和观看进度。离线时仍保留本机记录，重新连上后继续交换。文件还没收齐时显示「已关联，正在补齐」或「需要处理」，不会提前显示「已同步」。

发送请求先通知另一端，再读取文件列表；不会等全库识别或打包后才显示接收请求。已知内容指纹会缓存，新接收资源在写入时顺便生成指纹，不增加单独的整包校验步骤。两端存储路径可以不同。

## 日常入口与同步方式

已关联文件夹的同步图标会立即同步到所有在线的关联设备；旁边的菜单打开同步设置，可以查看各设备状态。没有关联过的文件夹使用同一个「同步到设备」入口。全局「设备同步」页按设备列出已关联的文件夹。暂停只停止继续交换，不删除任何一端已经收到的原文件；停止同步后，迟到的旧消息不会重新建立关系。

| 同步方式 | 内容变化 | 观看进度 |
| --- | --- | --- |
| 智能双向（默认） | 两端新增和修改互通，自动补齐缺失内容 | 双向 |
| 仅同步进度 | 各自保留文件和媒体库结构，不自动传媒体 | 双向 |
| 单向跟随 | 以选定来源设备的内容为准，其他设备接收变化 | 双向 |

「高级设置」默认折叠，可调整同步删除、字幕与附带文件、自动接收上限、接收后预留空间、单任务速度上限以及忽略规则。默认不同步删除，同步字幕与附带文件，自动接收不限量，接收后预留 512 MiB，速度不限。

自动接收上限针对**单次自动接收文件总量**，超过后需手动继续；空间预检获取失败不会凭空判断容量，真实写入失败会提示。限速针对单个传输任务。忽略规则以关联根为起点，`*` 匹配当前层、`**` 跨层、`?` 匹配一个字符，多个规则用逗号或换行分隔。

## 同步范围与条目身份

- 同步基于**现有媒体库**。在库内改名、移动子文件夹或媒体条目，会同步到关联设备；根文件夹在各设备媒体库中的外部位置保留。
- 新文件必须先导入媒体库，并放入已关联文件夹。此功能不会持续监控、扫描或镜像任意系统文件夹，也不会把库内改名/移动直接变成系统文件的改名/搬移。
- 文件夹和媒体使用稳定的条目标识，名称和内容指纹不代替身份。同名文件、同样内容的两个独立条目可以同时存在，默认各记各的观看进度。
- 初次关联会核对已有内容；后续传输可复用已校验一致的本机媒体，避免重复传字节，同时保留独立的逻辑条目。需要相同内容共用进度时，可在高级设置明确开启。
- 置顶、隐藏等本机管理偏好不参与同步。观看位置、看完状态、继续学习状态和最近观看时间参与同步；累积观看时长保留较大值，避免重复计数。

## 删除、冲突与缺失修复

同步移除使用媒体库回收站，**不会因此物理删除源文件**。

- 默认「仅从本机移除」：其他设备保留，本机不会立即自动补回。高级设置里的「恢复本机移除的项目」可恢复相关回收条目并补齐缺失内容。
- 开启「同步删除」后，允许发布内容的一端所做的删除会传播为各设备的回收站操作。智能双向两端均可发布；单向跟随只有来源设备可发布。
- 子项目可显式选择「从所有设备移除」，无需先打开「同步删除」。仅同步进度、单向跟随的非来源端只提供本机移除。
- **关联根文件夹**始终只从本机回收并暂停该组内容传输，其他设备保留，不进行远端递归删除。要恢复时，先在本机回收站恢复根文件夹，再点「立即同步」。
- 磁盘离线、文件暂不可读或过滤规则命中，不会被当成远端删除。本机文件找不到时会尝试有限范围的重新定位或从在线关联设备补齐；「文件需要确认 → 重新定位」可手选本机文件，完整指纹匹配后接回原条目，保留观看进度。选错文件会拒绝接入。

内容和进度都按因果版本合并，不以设备时钟或较大播放位置直接判胜负：

- 两端离线分别修改同一条目，出现冲突时在「文件需要确认」选择保留哪个设备的内容、名称或位置。媒体内容可「保留双方」，保留成独立条目；文件夹改名/移动需选择一个名称或位置。
- 一端删除文件夹、另一端新增内容时，不递归抹掉新内容；界面提示「保留文件夹」后继续同步。
- 同一视频两端都有新观看记录时，在「需要选择的进度」选要保留的记录，允许回退、重看或重新标记。
- 两端同时修改同步设置而产生分歧时，重新进入该文件夹「同步设置」确认并保存。

已加载的播放器不会因远端进度突然跳转；从媒体库重新打开时才采用已同步的续播位置。打开前的同步预取最多等待 900 毫秒，离线不影响播放。暂停或切换视频会保存进度，启用时约每 15 秒交换一次记录，媒体库变化也会触发检查。

## 传输与重新连接

设备离线时可以创建发送任务，重新连上后再发起接收确认。文件传输和后续缺失补齐均走局域网；智能双向建立后，两端均可成为新增内容的发送方。

「设备同步」页和「导入导出」页共用传输卡片。新版直接读取原文件发送，不在发送端制作 fluentpack，不进行独立的整包校验。接收端先把原文件放进自己的永久目录，确认能打开、长度正确，再发布可播放卡片。只收到文件夹或播放信息不算成功。清理临时目录、取消未完成的任务，都不会删除已经提交的视频，也不会删除发送端的源文件。磁盘暂时读不到文件时保留原卡片和进度，不会当成用户删除。

传输百分比是本轮需要写入的原文件和附带文件里，已经确认落盘的字节比例。复用的文件单独计数，不计入网速。续传时已经在磁盘上的字节计入完成量，不计入本次速度。速度用十进制（1 MB = 1,000,000 字节）和大约 2 秒的采样。字节传完但还在保存时，不表示任务已经成功。缺少原文件的条目保持「需要处理」，不会把删减后的清单显示成整个文件夹已同步。

手动导入导出仍使用 fluentpack。哔哩哔哩在线卡片继续按引用同步；设备账号凭据不会随内容复制，网盘媒体按下述离线规则迁移。

哔哩哔哩通过「缓存」功能保存的在线副本不随设备同步迁移，在线卡片保留来源；下载页下载并导入的成品仍按本地媒体传送。网盘媒体则必须先完成缓存或已有明确的完整本地文件，才能迁移；发送前可选择实际可用的缓存画质。接收端将其保存为永久离线媒体并登记缓存，保留来源、实际画质、修订和观看记录，无需登录原网盘即可使用。缺少缓存、只有独立轨道或旧修订时不会冒充迁移成功。

同时最多传输四个文件；单个大文件连续流式传输。安全直传使用协议 3：源端在发送过程中计算摘要，断点先核对已收前缀，同长度损坏文件也会重新获取；重试或恢复尚未完成的任务时，会核对已发布文件与接收日志的长度和摘要。普通播放与启动不会因此扫描整个媒体库。旧的明文直传任务需要更新两端后重新发送；旧版本仅支持原有加密 FluentPack 通道时可沿用该通道。手动导入与导出仍保留 fluentpack 格式。

传输支持断点重验和重连重试；局域网速度取决于网络、磁盘及设备性能。源资源和临时文件在任务使用期间受存储清理保护。准备、传输和导入时保持亮屏，等待与暂停时解除。移动系统可能暂停后台应用，保持两端应用打开可减少中断；已完成的本机内容和记录会保留。

## 使用已有 WebDAV / NAS（可选）

展开「使用已有存储」，填写服务地址、账号和密码，两端连接同一位置。NAS 需要开启可用的 WebDAV 服务。先通过局域网关联文件夹，或从右上角「⋯」导出/导入同步码，再选择对应本机文件夹。同步码包含文件夹密钥，只交给自己的设备；之后若需要媒体传输，仍需在局域网内配对并关联设备。

WebDAV 只交换**加密的观看进度和目录变更记录**，存放在 `FluentPlayerProgress/v1/events/`，不会上传或中转视频、音频及附件。两端不必同时在线即可交换记录；缺少的媒体需等有资源的设备在局域网可达后补齐。同步方式和设置的后续组内协商通过已关联设备连接交换。

单条损坏记录会跳过并提示，其他有效记录继续同步；损坏文件不被自动删除，修复后会重新读取。旧播客快照及已被新记录覆盖的事件，在替代记录成功上传后分批清理；失败后保留待清理队列。较大的本机同步存档会先压缩再加密，写入前检查可读容量，超限时保留上一份有效存档；旧版较大的存档可在受限范围内读取并压缩升级。

不需要自建本软件的服务器。已有 WebDAV 服务是否收费、能否从外网访问，取决于用户自己的服务。外网地址要求 HTTPS，内网 IP 可使用 HTTP；证书错误不会自动跳过。

## 平台与保护边界

局域网连接要求设备互相可达。访客 Wi-Fi、设备隔离或防火墙可能阻止连接；自动发现失败时可用「手动连接」输入对方显示的本机地址。Android 前台使用组播锁；iOS/macOS 首次需要允许本地网络访问。iOS 自动发现还受签名权限和系统组播限制，可尝试手动地址。移动端后台持续同步不作保证。

LAN 配对和控制记录使用 X25519、双端确认和 AES-GCM。新版媒体通过局域网流式传输，请求、目录、媒体分帧和完成结果均使用独立会话密钥加密认证；密钥只经已配对的控制通道交换，网络抓包不能直接读取媒体。取消配对或关闭同步会撤销在途会话，迟到响应不能恢复设备关联或写入同步数据。WebDAV 的目录与进度记录继续按组加密。

每个关联文件夹有独立密钥。WebDAV 记录按组加密，本地同步状态也加密保存，包裹密钥由系统凭据存储保管。无法读取或遇到新版数据时停止写回，保留原记录。

## 实现入口

- `lib/features/progress_sync/`：进度与目录模型、因果合并、加密存储、LAN、WebDAV、文件传输及同步设置。
- `folder_sync_coordinator.dart`：现有媒体库与逻辑条目映射、改名移动、回收保护、缺失检测及补齐。
- `folder_sync_settings_sheet.dart` / `folder_sync_conflict_sheet.dart`：文件夹设置、移除与冲突选择。
- `lib/widgets/media_library_folder_sync_button.dart`：已关联文件夹的轻量同步入口。
- `LibraryService.applySyncedPlaybackProgress`：批量写回现有媒体库活动记录，避免本地播放反馈循环。
- `MediaPlaybackService.beforeLibraryPlayback`：在选取续播位置前进行有时间限制的同步预取。
- `test/progress_sync_*`、`test/folder_sync_*`、`test/folder_transfer_*`：同步、传输、合并与界面回归。

设计参考 LocalSend 的附近设备配对、Syncthing 的因果冲突保留和 Joplin 的本地记录加 WebDAV 传输。没有引入这些项目源码，也不要求用户部署这些系统。
